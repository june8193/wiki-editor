# Spec: 사이드바 UI 개편 (액티비티 바 · 워크스페이스 뷰 · 사이드바 접기/너비 조절 · 우측 문서 목차 · 설정 모달)

## Problem Statement (문제 정의)

현재 **왼쪽 사이드바**에는 **폴더 트리**, **Git 패널**, **문서 목차**가 하나의 세로 영역에 전부 쌓여 있어 정보가 과밀하고 가시성이 떨어집니다.

- 세 패널이 고정 너비(260px)의 좁은 영역을 나눠 쓰기 때문에 각 패널의 가용 높이가 작고, 사용자가 지금 필요한 패널에 집중할 수 없습니다.
- 사이드바를 접거나 너비를 조절할 수 없어, 긴 파일명·경로·커밋 메시지가 잘리거나 반대로 편집 공간을 넓히고 싶을 때 대응할 방법이 없습니다.
- **워크스페이스 전환기**(즐겨찾기·최근 워크스페이스 팝오버)와 즐겨찾기 토글(`★`/`☆`)이 폴더 트리 헤더에 끼어 있어, 워크스페이스 관리 기능이 탐색 UI와 섞여 있습니다.
- **문서 목차**는 활성 문서에 종속된 정보인데도 워크스페이스 탐색 영역에 있어 맥락이 맞지 않습니다.
- **전역 설정 패널**은 우측 고정 패널로 열려, 문서 목차를 우측으로 옮기면 우측 영역을 두고 충돌합니다.

## Solution (해결 방안)

VS Code와 유사한 **액티비티 바 + 단일 뷰 사이드바** 구조로 개편하고, 문서 종속 정보는 **우측 사이드바**로 분리합니다.

1. **액티비티 바**: 앱 본문 좌측 끝에 항상 보이는 세로 아이콘 열을 두고, **탐색기(폴더 트리) / Git / 워크스페이스** 세 뷰 중 하나를 선택합니다. 왼쪽 사이드바는 한 번에 하나의 뷰만 표시합니다.
2. **접기/펼치기**: 활성 아이콘을 다시 누르면 왼쪽 사이드바가 접히고(액티비티 바는 유지), 다른 아이콘을 누르면 해당 뷰로 전환되며 접혀 있었다면 펼쳐집니다. 단축키는 제공하지 않습니다.
3. **너비 조절**: 왼쪽 사이드바 오른쪽 경계를 드래그해 너비를 조절하고, 더블클릭으로 기본 너비로 복원합니다.
4. **워크스페이스 뷰**: 현재 워크스페이스 카드(이름·경로·즐겨찾기 토글·`폴더 열기...`)와 즐겨찾기 목록, 최근 워크스페이스 목록을 별도의 사이드바 뷰로 제공합니다. 탐색기 헤더에는 워크스페이스 이름만 표시합니다.
5. **우측 사이드바(문서 목차)**: 문서 목차를 우측 사이드바로 옮기고, 접기/펼치기와 너비 조절을 지원합니다.
6. **설정 모달**: 전역 설정 패널을 화면 가운데 모달로 전환하여 우측 영역은 문서 목차 전용으로 사용합니다.
7. **아이콘**: 아이콘 라이브러리 `lucide-react`를 도입하고, Git 아이콘에 변경 파일 수 배지를 표시합니다.

## User Stories (사용자 스토리)

1. As a 위키 작성자, I want 액티비티 바에서 탐색기·Git·워크스페이스 아이콘 중 하나를 눌러 왼쪽 사이드바에 해당 뷰만 표시하고, so that 필요한 정보에 집중하고 패널마다 세로 공간을 충분히 쓸 수 있습니다.
2. As a 위키 작성자, I want 현재 활성 뷰의 아이콘을 다시 눌러 왼쪽 사이드바를 접고, so that 편집 공간을 최대한 넓게 쓸 수 있습니다.
3. As a 위키 작성자, I want 왼쪽 사이드바가 접힌 상태에서 아무 아이콘이나 누르면 해당 뷰로 펼쳐지게 하고, so that 한 번의 클릭으로 원하는 뷰로 돌아갈 수 있습니다.
4. As a 위키 작성자, I want 액티비티 바가 사이드바 접힘 여부와 관계없이 항상 보이고, 현재 활성 뷰가 시각적으로 강조되기를 원하며, so that 지금 어떤 뷰가 열려 있는지 알 수 있습니다.
5. As a 위키 작성자, I want Git 아이콘에 변경 파일 수(스테이징·미스테이징·추적되지 않음 합계) 배지가 표시되고, so that Git 뷰를 열지 않아도 커밋할 변경이 있는지 알 수 있습니다.
6. As a 위키 작성자, I want 왼쪽 사이드바 오른쪽 경계를 드래그해 너비를 조절하고, so that 긴 파일명이나 커밋 메시지를 잘리지 않게 볼 수 있습니다.
7. As a 위키 작성자, I want 너비가 180px와 min(600px, 창 너비의 50%) 사이로 제한되고, so that 사이드바가 사라지거나 편집 공간을 잠식하지 않습니다.
8. As a 위키 작성자, I want 경계를 더블클릭하면 기본 너비 260px로 복원되고, so that 조절한 너비를 빠르게 초기화할 수 있습니다.
9. As a 위키 작성자, I want 워크스페이스 뷰에서 현재 워크스페이스의 이름·경로를 확인하고 즐겨찾기 추가/해제 및 `폴더 열기...`를 실행하며, so that 워크스페이스 관리를 한곳에서 할 수 있습니다.
10. As a 위키 작성자, I want 워크스페이스 뷰에서 즐겨찾기 목록과 최근 워크스페이스 목록을 보고 클릭해 전환하며 개별 즐겨찾기를 해제하고, so that 자주 쓰는 위키로 빠르게 이동할 수 있습니다.
11. As a 위키 작성자, I want 워크스페이스 뷰에서 다른 워크스페이스로 전환하면 자동으로 탐색기 뷰로 이동하고, so that 전환 직후 바로 파일을 탐색할 수 있습니다.
12. As a 위키 작성자, I want 미저장 변경이 있는 상태에서 워크스페이스 뷰로 전환을 시도하면 기존과 동일하게 확인 다이얼로그가 표시되기를 원하고, so that 작업 내용을 잃지 않습니다.
13. As a 위키 작성자, I want 앱 시작 시 열린 워크스페이스가 없으면 워크스페이스 뷰가, 있으면 탐색기 뷰가 활성화되기를 원하고, so that 첫 화면에서 바로 다음 행동을 할 수 있습니다.
14. As a 위키 작성자, I want 탐색기 헤더에는 현재 워크스페이스 이름만 텍스트로 표시되고, so that 탐색기가 파일 탐색에만 집중된 간결한 UI가 됩니다.
15. As a 위키 작성자, I want 문서 목차가 편집 공간 오른쪽의 우측 사이드바에 표시되고, so that 활성 문서 정보와 워크스페이스 탐색 정보가 분리됩니다.
16. As a 위키 작성자, I want 우측 사이드바에서 기존과 동일하게 헤딩 클릭 스크롤, 목차(TOC) 삽입, 헤딩 넘버링 적용·제거, 헤딩 번호 표시 토글을 사용하고, so that 기능 손실 없이 위치만 바뀝니다.
17. As a 위키 작성자, I want 활성 문서가 없거나 마크다운이 아닐 때 우측 사이드바가 사라지지 않고 빈 상태 메시지를 표시하기를 원하고, so that 탭을 오갈 때 레이아웃이 흔들리지 않습니다.
18. As a 위키 작성자, I want 우측 사이드바 헤더의 접기 버튼으로 목차를 접고, 접힌 뒤에는 우측 끝의 얇은 세로 탭(목차 아이콘)을 눌러 다시 펼치고, so that 필요할 때만 목차를 볼 수 있습니다.
19. As a 위키 작성자, I want 우측 사이드바 왼쪽 경계를 드래그해 180~500px 범위에서 너비를 조절하고 더블클릭으로 기본 240px로 복원하며, so that 헤딩이 긴 문서도 편하게 볼 수 있습니다.
20. As a 위키 작성자, I want `Settings > 설정 패널` 메뉴를 실행하면 설정이 화면 가운데 모달로 열리고, so that 우측 목차와 충돌하지 않고 설정에 집중할 수 있습니다.
21. As a 위키 작성자, I want 설정 모달을 `닫기` 버튼, `Esc` 키, 바깥 영역(배경) 클릭으로 닫고, so that 익숙한 방식으로 모달을 빠져나갈 수 있습니다.
22. As a 위키 작성자, I want 사이드바 상태(활성 뷰·접힘·너비)가 앱을 다시 시작하면 기본값으로 돌아가고, so that 설정 파일이 UI 상태로 오염되지 않습니다.

## Implementation Decisions (구현 결정사항)

- **아이콘 의존성**: `lucide-react`를 런타임 의존성으로 추가합니다. 아이콘 버튼에는 반드시 `aria-label`과 툴팁(`title`)을 제공하며, 아이콘 자체는 `aria-hidden` 처리합니다.
- **왼쪽 사이드바 뷰 상태 모델** (세션 메모리 전용, `config.json`에 저장하지 않음):

  ```ts
  type LeftSidebarView = 'explorer' | 'git' | 'workspace'
  interface LeftSidebarState {
    activeView: LeftSidebarView
    isCollapsed: boolean
    width: number
  }
  ```

- **액티비티 바 전이 규칙**:
  - `select(view)`: `isCollapsed === false && activeView === view`이면 `isCollapsed = true`로 전이합니다(뷰 유지).
  - 그 외에는 `activeView = view`, `isCollapsed = false`로 전이합니다.
  - 워크스페이스 뷰에서 워크스페이스 전환이 **성공**하면 `activeView = 'explorer'`(펼침)로 전이합니다. 전환이 취소(미저장 확인 다이얼로그에서 취소)되거나 실패하면 뷰를 유지합니다.
  - 초기 뷰: 초기 워크스페이스 복원이 끝난 시점에 워크스페이스가 없으면 `'workspace'`, 있으면 `'explorer'`로 결정합니다. 그 뒤로는 사용자의 선택을 덮어쓰지 않습니다.
- **너비 제한 규칙**: 순수 함수로 분리합니다.
  - 왼쪽: `clamp(width, 180, min(600, windowWidth * 0.5))`, 기본값 260. 최소 너비 아래로 드래그해도 자동으로 접히지 않습니다.
  - 오른쪽: `clamp(width, 180, 500)`, 기본값 240.
  - 창 크기가 줄어 최대값이 현재 너비보다 작아지면 다음 렌더/리사이즈 시 최대값으로 보정합니다.
- **사이드바 리사이저**: 좌·우 사이드바가 공유하는 하나의 재사용 가능한 리사이즈 핸들(포인터 드래그 + 더블클릭 복원)을 만듭니다. 기존 **분할 구분자**(Splitter)의 드래그 처리 패턴을 참고하되 별개의 컴포넌트로 둡니다. 접근성 확보를 위해 `role="separator"`, `aria-orientation="vertical"`, `aria-valuenow/min/max`, 좌·우 방향키로 너비를 조절하는 동작을 제공합니다.
- **왼쪽 사이드바 구성**: 액티비티 바(항상 표시) + 접히지 않았을 때만 렌더링되는 사이드바 본문(활성 뷰 1개 + 리사이저).
  - 뷰를 바꿔도 폴더 트리의 펼침 상태 등 워크스페이스 트리 상태(훅 상태)는 유지되어야 합니다. 트리 상태는 이미 상위 훅이 소유하므로 뷰 컴포넌트를 언마운트해도 됩니다. 단, 인라인 생성·이름 변경 같은 일시적 편집 상태는 뷰를 전환하면 초기화되어도 됩니다.
- **Git 배지**: `staged + unstaged + untracked` 파일 수 합계가 0보다 클 때만 표시합니다. 저장소가 아니거나 워크스페이스가 없으면 표시하지 않습니다. 99를 넘으면 `99+`로 표시합니다.
- **워크스페이스 뷰**: 기존 **워크스페이스 전환기** 팝오버의 섹션 렌더링(즐겨찾기/최근, 활성 항목 강조, 개별 해제)을 재사용하거나 흡수하여 상시 표시 목록으로 바꿉니다. `폴더 열기...` 버튼은 메뉴 `open-folder` 명령과 같은 핸들러를 호출합니다. 워크스페이스가 없으면 현재 워크스페이스 카드 대신 안내 문구와 `폴더 열기...` 버튼을 표시합니다.
- **탐색기 헤더**: 워크스페이스 전환기 팝오버와 즐겨찾기 토글을 제거하고 워크스페이스 이름 텍스트(경로는 툴팁)와 기존 파일·폴더 생성/새로고침 액션만 남깁니다.
- **우측 사이드바**: 편집 공간 오른쪽에 위치하며 문서 목차 패널만 담습니다. 상태(`isCollapsed`, `width`)는 세션 메모리에만 둡니다. 기존 문서 목차 패널 내부의 접기 상태는 제거하고, 헤더의 접기 버튼이 우측 사이드바를 접도록 바꿉니다. 접힌 상태에서는 얇은 세로 탭(목차 아이콘, `aria-label="문서 목차 펼치기"`)만 렌더링합니다.
- **설정 모달**: 전역 설정 패널을 오버레이 + 가운데 대화상자(`role="dialog"`, `aria-modal="true"`)로 렌더링합니다. 기존 접근 가능한 이름 `전역 설정 패널`을 유지합니다. `Esc`, 배경 클릭, `닫기` 버튼으로 닫습니다. 열려 있는 동안 편집기 단축키를 막아야 하는지는 기존 **확인 다이얼로그** 처리 방식(`isShortcutDisabled`)을 따릅니다. 메뉴 `toggle-settings`의 토글 의미는 유지합니다.
- **도메인 용어**: `CONTEXT.md`를 갱신합니다. 신규 용어로 **액티비티 바**, **탐색기 뷰**, **Git 뷰**, **워크스페이스 뷰**, **우측 사이드바**, **사이드바 리사이저**를 추가하고, 기존 용어 중 **왼쪽 사이드바**, **워크스페이스 전환기**(워크스페이스 뷰로 대체), **폴더 트리**, **Git 패널**, **문서 목차**, **전역 설정 패널**의 위치 설명을 고칩니다. 각 티켓은 자신이 바꾼 영역의 용어를 함께 갱신합니다.

## Testing Decisions (테스트 결정사항)

- 검증 기준: DOM 구조나 내부 상태가 아니라 접근 가능한 역할·이름(`getByRole`/`getByLabelText`)으로 사용자가 관찰하는 동작을 검증합니다. 모든 테스트는 인메모리 하네스로 격리하며 실제 파일 시스템이나 `config.json`에 접근하지 않습니다.
- 테스트 심 (사전 합의된 심):
  - **`<App />` 통합 테스트 (인메모리 `createInMemoryWikiApi` 하네스)**: Catches 액티비티 바 뷰 전환·접기/펼치기 전이 오류, 초기 뷰 결정 및 워크스페이스 전환 후 탐색기 자동 이동 누락, 워크스페이스 뷰의 즐겨찾기/최근 전환·해제·`폴더 열기...` 회귀, Git 배지 수 오류, 목차가 우측 사이드바로 이동한 뒤 헤딩 스크롤·TOC 삽입·넘버링 회귀, 우측 사이드바 접기/펼치기, 설정 모달 열기/닫기(`Esc`·배경·버튼), 키보드로 리사이저를 조절할 때의 `aria-valuenow` 변화 / Misses 실제 포인터 드래그의 픽셀 단위 레이아웃, CSS 시각적 결과(아이콘 모양, 강조 색, 오버레이 렌더링).
  - **사이드바 너비 제한 순수 함수 (Vitest 단위 테스트)**: Catches 최소/최대/창 너비 50% 경계값 계산 오류, 기본값 복원 값 오류 / Misses 이벤트 바인딩과 렌더링 반영.
- *(위 심 목록은 `/ticket-runner`의 사전 합의된 심(Pre-agreed Seams)으로 사용됩니다.)*
- 참고할 기존 테스트 패턴:

  - 기존 사이드바 워크스페이스 전환기 테스트(미열림/열림 상태 전환, 즐겨찾기 관리)

  - `PaneTabStore`의 분할 비율 제한 단위 테스트 패턴

## Out of Scope (범위 제외 사항)

- 사이드바 상태(활성 뷰·접힘·너비)를 `config.json`이나 다른 저장소에 영속화하는 작업
- 사이드바 토글 키보드 단축키와 `View` 메뉴 항목(좌·우 모두)
- 최소 너비 아래로 드래그할 때 자동으로 접히는 동작
- 액티비티 바 아이콘 순서 변경, 드래그로 뷰를 재배치하는 작업, 우측 사이드바에 다른 뷰를 추가하는 작업
- 검색 뷰 등 새로운 사이드바 기능
- 설정 패널 내용(항목·레이아웃) 자체의 변경

## Further Notes (기타 참고사항)

- **오버플로우/레이어**: 사이드바 본문이 `overflow: hidden`으로 바뀌면 폴더 트리 컨텍스트 메뉴나 Git 브랜치 드롭다운이 잘리지 않는지 확인해야 합니다. 설정 모달 오버레이는 기존 **확인 다이얼로그**보다 아래 레이어에 두어, 모달 안에서 확인 다이얼로그를 띄울 때 가려지지 않게 합니다.
- **드래그 중 상호작용**: 리사이즈 드래그 중에는 텍스트 선택과 편집기 포인터 이벤트를 막고, 커서를 `col-resize`로 고정합니다.
- **테스트 환경**: jsdom에서는 `window.innerWidth` 기본값(1024)을 기준으로 왼쪽 최대 너비가 512px로 계산된다는 점을 테스트 기대값에 반영합니다.
