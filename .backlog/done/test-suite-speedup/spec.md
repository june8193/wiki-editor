# Spec: 테스트 스위트 병렬화 및 실행 환경 최적화를 통한 회귀 검증 속도 개선

## Problem Statement (문제 정의)

현재 레포지토리의 전체 자동화 테스트 스위트(`npm test`, 79개 스위트 · 741개 테스트)는 16코어 개발 환경에서도 약 **195초(3분 16초)**가 소요되어 TDD 개발 루프, 자율 티켓 실행 검증, 릴리즈 전 회귀 확인 시 피드백 주기가 과도하게 느립니다.

1. **단일 Git 통합 스위트 직렬 병목**: 실제 `git` 바이너리와 임시 저장소를 사용하는 메인 프로세스 Git 서비스 통합 테스트 15개 케이스가 공유 `beforeEach` 상태에 묶여 단일 워커에서 완전 직렬로 실행되며 혼자 **191.35초**를 소비해 전체 테스트 실행 시간을 결정짓고 있습니다(단일 최장 원격 동기화 케이스만 약 40.8초 소요, 매 케이스마다 불필요한 `git config` 서브프로세스 반복 스폰).
2. **초대형 `<App />` 통합 스위트 직렬 누적**: 17개 이상의 피처에 걸친 UI 통합 시나리오가 단일 기본 `<App />` 스위트(25개 도메인 그룹, 123개 테스트, **131.67초**)와 다중 창 `<App />` 스위트(44개 테스트, **72.86초**) 두 곳에 직렬로 누적되어 멀티코어 워커 병렬화를 활용하지 못하고 있습니다.
3. **반복적인 `jsdom` 환경 생성 오버헤드**: 렌더러 테스트 프로젝트가 매 파일마다 새로운 `jsdom` 환경을 초기화하느라 워커 누적 **328.5초(추적 시간의 38%)**를 환경 부팅에만 소비하고 있으며, 브라우저 DOM에 전혀 의존하지 않는 순수 상태 스토어·유틸리티 단위 테스트들까지 무거운 `jsdom` 환경 위에서 실행되고 있습니다.

## Solution (해결 방안)

프로덕션 런타임 동작과 기존 741개 테스트의 검증 범위·단언(assertion)을 100% 보존하면서, 실행 환경 라우팅·워커 재사용·거대 직렬 스위트 도메인 분할을 통해 멀티코어 병렬 효율을 극대화합니다.

1. **실행 환경 적정 라우팅 및 `vmThreads` 워커 재사용**: DOM·브라우저 전역 객체에 의존하지 않는 렌더러 순수 상태 스토어 및 유틸리티 단위 테스트를 가벼운 `node` 환경 프로젝트에서 실행하고, 실제 DOM이 필요한 `renderer` 프로젝트는 워커당 `jsdom` 환경을 1회만 생성하면서 파일 간 모듈 격리를 유지하는 `vmThreads` 풀로 구동합니다.
2. **Git 서비스 통합 테스트 샌드박스 모듈화 및 도메인별 병렬 스위트 분할**: 격리된 임시 디렉터리와 기본 작성자 정보(`user.name`, `user.email`)가 사전 기록된 `.gitconfig`를 제공하는 공용 Git 테스트 샌드박스 헬퍼를 구축하여 불필요한 `git config` 프로세스 스폰을 없애고, 상태/스테이징/브랜치·원격 동기화·로그/커밋 상세·Diff·변경 사항 롤백 도메인별 스위트로 분할(장시간 원격 메가 테스트의 정상 흐름과 오류·충돌 검증 분리 포함)해 멀티코어에서 병렬 실행합니다.
3. **기본 `<App />` 및 다중 창 `<App />` 통합 스위트의 도메인별 분할 및 공용 헬퍼 추출**: 반복 선언되던 Mermaid 스텁·스크롤 스텁·**액티비티 바**/**에디터 모드** 조작·탭 드래그 보조 함수를 공용 테스트 헬퍼로 통합하고, 거대 단일 스위트들을 앱 셸·워크스페이스/**폴더 트리**·**편집 공간**/**탭 바**·**문서 편집기**/**Mermaid 다이어그램 블록**/**문서 목차**/링크·**Git 패널**/**Diff 탭** 및 공유 **문서 버퍼**·창 간 탭 이동/종료 보호·다중 **메인 창** 세션 도메인 스위트로 분할하여 워커 병렬성을 확보하고 향후 피처 개발의 선례(Prior Art)를 정립합니다.

## User Stories (사용자 스토리)

1. As a 위키 에디터 개발자, I want 프로덕션 코드를 수정한 뒤 전체 테스트 스위트(`npm test`)를 실행했을 때 기존과 동일한 회귀 검증 강도를 유지하면서도 멀티코어를 활용해 대폭 단축된 시간(목표 60초 이하) 안에 결과를 확인하기를 원하며, so that TDD 및 코드 리뷰·릴리즈 검증 루프를 빠르게 반복할 수 있습니다.
2. As a 위키 에디터 개발자, I want 브라우저 DOM이 필요 없는 렌더러 순수 유틸리티 및 상태 스토어 단위 테스트가 `jsdom` 초기화 없이 즉시 실행되고 DOM 컴포넌트·통합 테스트는 워커당 재사용되는 `jsdom` 풀에서 격리 실행되기를 원하며, so that 불필요한 테스트 환경 부팅 비용으로 CPU와 시간을 낭비하지 않습니다.
3. As a 위키 에디터 개발자, I want 실제 `git` 바이너리를 검증하는 Git 서비스 통합 테스트들이 각자 완전히 격리된 임시 저장소 샌드박스에서 도메인별로 병렬 실행되고 단일 40초대 병목 케이스가 독립 시나리오로 나뉘기를 원하며, so that Windows 프로세스 스폰 비용이 단일 코어에 직렬로 쌓여 전체 테스트 시간을 붙잡아 두지 않습니다.
4. As a 위키 에디터 개발자, I want 단일 파일에 누적된 기본 `<App />` 통합 테스트와 다중 창(**메인 창**·**보조 창**) `<App />` 통합 테스트가 도메인 책임별 스위트와 공용 테스트 헬퍼로 정돈되기를 원하며, so that 특정 도메인 수정 시 관련 통합 스위트만 빠르게 부분 실행할 수 있고 향후 새 기능 추가 시에도 자연스럽게 도메인별 파일 구조를 따를 수 있습니다.

## Implementation Decisions (구현 결정사항)

- **무변이 및 무손실 검증 보존 불변식**:
  - 프로덕션 애플리케이션 코드(메인 프로세스, 프리로드 브리지, 렌더러 컴포넌트·훅·스토어·스타일)의 런타임 동작과 외부 인터페이스는 변경하지 않습니다.
  - 기존 테스트 스위트가 검증하던 모든 시나리오, 경계 조건, 보안 검증(워크스페이스 외부 경로 및 심볼릭 링크 차단 등), 오류 처리 단언을 누락 없이 보존합니다(장시간 복합 테스트를 독립 케이스로 분리함에 따라 전체 테스트 케이스 수는 기존 기준선인 `741`개 이상이어야 함).
  - 단계적 분할(Expand-Contract) 과정에서 원본 스위트와 분리된 신규 스위트에 동일 테스트가 중복으로 남아 이중 실행되지 않도록 이관 완료된 블록은 즉시 원본에서 제거하고, 모든 이관이 끝나면 빈 원본 거대 파일을 삭제합니다.
- **Vitest 프로젝트 라우팅 및 풀 구성 (사전 호환성 검증 확정)**:
  - 렌더러 하위 테스트 중 `DOMPurify`, `CodeMirror`, `TipTap`/`ProseMirror`, React 컴포넌트/훅 렌더링, 브라우저 레이아웃·캔버스·이벤트 객체에 직간접적으로 의존하지 않는 순수 데이터 계산 유틸리티 및 순수 상태 스토어(`*.test.ts`)만 `node` 환경 프로젝트의 수집 대상에 포함하고 `renderer` 프로젝트 수집 대상에서는 제외합니다.
  - 브라우저 전역 객체나 DOM 살균·편집기 뷰에 직간접적으로 의존하는 렌더러 `.test.ts` 및 모든 `.test.tsx` 스위트는 `renderer` 프로젝트(`jsdom`)에 유지합니다.
  - `renderer` 프로젝트는 워커 스레드당 `jsdom` 환경을 재사용하면서 VM 컨텍스트로 파일 간 모듈 상태를 격리하는 `vmThreads` 풀을 사용합니다.
- **Git 서비스 통합 테스트 샌드박스 및 도메인 분할 규칙**:
  - 공용 Git 테스트 샌드박스 팩토리는 호출마다 독립된 임시 루트 디렉터리(`mkdtemp`), 작업 저장소 폴더, 비저장소 일반 폴더, 격리된 `.gitconfig`(`defaultBranch = main` 및 기본 `user.name` / `user.email` 사전 설정 포함), `GIT_CONFIG_NOSYSTEM=1` 및 `GIT_CONFIG_GLOBAL`이 주입된 서비스 인스턴스와 보조 `runGit` 실행기, 그리고 Windows 파일 잠금 지연을 견디는 재시도 정리 함수(`maxRetries`, `retryDelay`)를 제공합니다.
  - 테스트에서 기본 작성자 신원만으로 충분한 경우 별도의 `git config user.name` / `git config user.email` 서브프로세스를 추가 스폰하지 않으며, 서로 다른 작성자(예: Alice / Bob) 구분이 필요한 시나리오만 명시적으로 설정합니다.
  - 기존 단일 Git 서비스 테스트 스위트는 다음 5개 도메인 스위트로 분리하여 병렬 워커에 분산합니다:
    1. 저장소 초기화(`init`), 상태 파싱(`status`), 스테이징/언스테이징(`stage`/`unstage`), 로컬 브랜치 조회·전환(`branches`/`checkout`) 및 단위 파서/오류 포매터 헬퍼
    2. 베어 원격 저장소 연동(`push`/`pull`/`sync`/`fetch`) — 기존 40초대 단일 복합 케이스를 (a) 원격 게시·추적·이름 변경·동시 비충돌 동기화 시나리오와 (b) 비패스트포워드 거부·병합 충돌 상태·원격 미설정 및 도달 불가 오류 격리 시나리오로 분리
    3. 커밋 그래프 로그(`log` 범위 필터·참조 해석·100건 페이지네이션) 및 커밋 상세(`commitDetail`)와 원시 오류 로깅 검증
    4. 스테이징/비스테이징/미추적/바이너리/대용량 절단/경로 보안 작업 트리 Diff 및 커밋 간 Diff(`diff`)
    5. 추적 파일·병합 충돌(`U`)·미추적 파일(`trashItem` 주입 및 폴백) 개별/전체 변경 사항 롤백(`discard`/`discardAll`)
- **`<App />` 및 다중 창 `<App />` 통합 테스트 도메인 분할 규칙**:
  - 여러 `<App />` 통합 스위트에서 반복 사용되는 Mermaid 렌더 스텁 상태 관리기, `scrollIntoView` 프로토타입 스텁, **액티비티 바** 탐색·**워크스페이스 뷰** 전환·**편집기 영역** 내 **에디터 모드** 전환 보조 함수, 창 간 탭 드래그 이벤트/`DataTransfer`/버퍼 지연 보조 함수를 렌더러 테스트 공용 헬퍼 모듈로 추출합니다.
  - Vitest의 정적 호이스팅 규칙을 따르기 위해 `vi.mock('mermaid', ...)` 호출 자체는 이를 필요로 하는 각 `<App />` 통합 테스트 파일 최상단에 얇게 선언하되, 내부 스텁 동작과 초기화 함수는 공용 헬퍼를 재사용하여 코드 중복을 방지합니다(전역 `setup` 파일에는 넣지 않아 Mermaid 렌더러 자체 단위 테스트의 순수성을 유지).
  - 기존 기본 `<App />` 통합 스위트(25개 `describe` 그룹)는 도메인 응집도에 따라 다음 5개 스위트로 분할합니다(기존 검색 전용 `<App />` 스위트는 그대로 유지):
    1. **앱 셸 · 설정 · 레이아웃**: 앱 셸 초기화, 테마 영속성, **전역 설정 패널** 모달 및 엄격한 `config.json` 스키마 검증, **액티비티 바** 전환, **왼쪽 사이드바**·**우측 사이드바** 접기/펼치기 및 **사이드바 리사이저**, 뷰포트 스크롤/오버플로우 격리, 렌더러 오류 로깅 및 UI 브레드크럼
    2. **워크스페이스 · 폴더 트리 · 상태 복원**: **워크스페이스 뷰** 및 즐겨찾기, **폴더 트리** 탐색·생성·이름 변경·삭제·상대/절대 경로 복사·다중 선택 및 드래그 앤 드롭 이동, 문서 저장/자동 저장, 워크스페이스별 레이아웃·탭·펼침 폴더 상태 영속화 및 동일 워크스페이스 재선택 보호
    3. **편집 공간 · 탭 바 · 화면 분할 모드**: 멀티 탭 열기/전환/닫기 보호, **주 편집기 영역**·**보조 편집기 영역** 간 **화면 분할 모드**(`single`/`horizontal`/`vertical`) 및 **분할 구분선** 조절, 탭 드래그 이동·복제, 25개 이상 탭 마운트 상한, 읽기 전용 이미지 미리보기 탭
    4. **문서 편집기 · Mermaid · 문서 목차 · 링크**: 4종 **에디터 모드**(`Raw`·`위지윅`·`Preview`·`Split`) 무손실 왕복 및 **표 편집 툴바**, `Split` 양방향 스크롤 동기화 및 로컬 이미지 삽입/렌더링, **Mermaid 다이어그램 블록** 렌더링·복사/내보내기·탭 세션 높이 유지, **문서 목차** 스크롤 스파이, **링크 자동완성 메뉴**(`Ctrl+K` 포함) 및 마크다운 링크 네비게이션
    5. **Git 패널 · Diff 뷰어 통합**: **Git 패널** 초기화·스테이징·커밋·원격 동기화·스마트 커밋 CTA·**Changes 섹션**/**Graph 섹션** 아코디언 및 **섹션 리사이저**, 읽기 전용 작업 트리 **Diff 탭** 및 커밋 변경 파일 **Diff 탭** 통합
  - 기존 다중 창 `<App />` 통합 스위트는 다음 3개 스위트로 분할합니다:
    1. **공유 문서 버퍼 실시간 동기화**: 창 간 본문·미저장 배지·자동 저장 중복 제거·`config.json` 공유·이름 변경/삭제/외부 변경 정합성 및 마지막 참조 닫기 경합 보호
    2. **보조 창 탭 분리·병합·닫기 보호 및 Git 롤백 연동**: **보조 창** 셸 구성, 컨텍스트 메뉴 및 창 밖 드래그 아웃 탭 분리, 창 간 탭 병합·분할 드롭, **메인 창**·**보조 창** 닫기 시 미저장 **확인 다이얼로그** 및 `workspace-state.json` 배제 불변식, 다중 창 환경에서의 개별/전체 Git 변경 사항 롤백 연동
    3. **다중 메인 창 워크스페이스 세션 격리**: `'새 창에서 열기'` 및 이미 열린 워크스페이스 창 포커스 전환, 세션별 **문서 버퍼**·**보조 창**·**폴더 트리**·**Git 패널**·**검색 패널**·**문서 내 찾기 바** 격리 및 전역 설정 브로드캐스트 동기화

## Testing Decisions (테스트 결정사항)

- **검증 기준**: 리팩토링 전후로 프로덕션 코드 무변경 상태에서 전체 테스트 스위트(`npm test`), 타입체크(`npm run typecheck`), 프로덕션 번들 빌드(`npm run build`)가 모두 오류 없이 통과하고, 분할 전후 테스트 시나리오 누락·중복이 없으며 전체 Wall-clock 테스트 시간이 유의미하게 단축되는지 검증합니다.
- **사전 합의된 테스트 심 (Pre-agreed Seams)**:
  1. **Vitest 멀티 프로젝트 실행기 심 (`npm test` / `vitest run` CLI 경계)**
     - **Catches**: 프로젝트 글롭 라우팅 오류로 인한 테스트 파일 누락·중복 수집, `node` 환경으로 이동한 렌더러 단위 테스트의 숨은 브라우저 전역 참조 오류, `vmThreads` 풀에서의 모듈 목 호이스팅·CSS 임포트·비동기 타이머/DOM 정리 격리 회귀, 단일 장시간 직렬 병목 잔존 여부.
     - **Misses**: 실제 패키징된 Electron 바이너리 창 생성 및 OS 네이티브 프로세스 기동.
  2. **격리 임시 저장소 기반 Git 서비스 공개 인터페이스 심 (`GitService` + 공용 임시 Git 샌드박스 / Vitest)**
     - **Catches**: 병렬 워커 동시 실행 시 임시 디렉터리·환경 변수(`.gitconfig`) 간섭, Windows 프로세스 종료 직후 임시 폴더 정리 경쟁 실패, 원격/로컬/Diff/롤백 시나리오 분할 과정에서의 검증 조건 누락.
     - **Misses**: Electron IPC 채널 직렬화 및 **Git 패널** UI 상태 전이.
  3. **`<App />` 단일 창 및 다중 창 공개 UI 통합 심 (React Testing Library + 인메모리 단일/다중 창 `WikiApi` 하네스 / Vitest)**
     - **Catches**: 공용 헬퍼 추출 및 도메인별 스위트 분할 과정에서의 Mermaid/스크롤/드래그 스텁 초기화 누락, 테스트 간 전역 `document`/`window` 상태 오염, 기존 UI 시나리오 단언 유실.
     - **Misses**: 실제 Chromium 레이아웃 엔진의 픽셀 단위 렌더링 및 OS 네이티브 드래그 커서 좌표계.
- *(위 심 목록은 `/ticket-runner`의 사전 합의된 심(Pre-agreed Seams)으로 사용됩니다.)*
- **참고할 기존 테스트 패턴 (Prior Art)**:
  - 검색 기능을 별도 도메인 스위트로 분리해 유지 중인 기존 `<App />` 검색 통합 테스트 패턴
  - 인메모리 단일 창 및 다중 창 `WikiApi` 하네스 패턴
  - `GIT_CONFIG_NOSYSTEM=1` 및 임시 `.gitconfig`로 호스트 Git 설정을 격리하는 Git 서비스 통합 테스트 패턴

- 저장소 에이전트 규칙 문서(`GEMINI.md`)나 글로벌 스킬 프롬프트에 테스트 작성 가드레일 문구를 추가하는 작업

## Further Notes (기타 참고사항)

- **Windows 파일 핸들 해제 안정성**: 병렬로 다수의 `git` 프로세스가 동시에 종료될 때 Windows Defender나 인덱서가 `.git` 내부 파일을 잠깐 붙잡을 수 있으므로, 샌드박스 정리 시 `maxRetries`와 `retryDelay` 옵션을 반드시 유지합니다.
- **성능 개선 확인 지표**: 기준선 측정치(79개 스위트 · 741개 테스트 · 약 195.7초) 대비 모든 티켓 완료 후 전체 스위트 Wall-clock 실행 시간이 16코어 개발 환경 기준 60초 안팎(기존 대비 3배 이상 단축)으로 수렴하는지 최종 확인합니다.
