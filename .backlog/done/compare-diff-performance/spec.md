# Spec: Compare 및 공통 Diff 뷰어 로딩·렌더링 성능 개선 (Compare & Diff Viewer Performance)

## Problem Statement (문제 정의)

**Compare 뷰**의 **Compare 패널**에서 브랜치·워크트리 비교 결과를 불러오거나 변경 파일을 선택해 **Diff 탭**(**Diff 뷰어**)을 열 때 체감 지연과 화면 멈칫거림(프레임 드랍)이 발생합니다.

1. **과도한 직렬 `git` 자식 프로세스 실행**:
   - **Compare 패널**에서 변경 파일 하나를 클릭할 때마다 저장소 루트 조회(`rev-parse --show-toplevel`), `HEAD` 검증(`rev-parse HEAD`), 공통 조상 계산(`merge-base`), 실제 `diff`까지 총 4개의 `git` 프로세스가 직렬로 실행됩니다. 이미 비교 요약 단계에서 `mergeBaseHash`를 구했음에도 파일마다 다시 계산하며, Windows 환경의 프로세스 생성 비용이 누적되어 클릭마다 수백 ms의 초기 응답 지연이 발생합니다.
   - `Base`/`Compare` Ref 또는 `3-dot`/`2-dot` 모드를 전환할 때 실행되는 비교 요약 조회 역시 다단계 직렬 검증과 중복된 전체 트리 `git diff -M`(`--name-status` 및 `--numstat` 2회 실행)을 포함해 총 9개의 `git` 프로세스를 실행합니다.
2. **렌더러 메인 스레드 동기 구문 분석·대규모 DOM 마운트 및 리렌더 전파**:
   - **Diff 뷰어**가 파일 경로 변경 시마다 비동기 파서 로더를 거치며 **전체 테이블 이중 렌더링 + 전 라인 이중 Lezer 파싱**을 유발합니다(1차 정적 폴백 파싱 직후 비동기 상태 갱신으로 2차 전체 재파싱).
   - 셀 렌더링 본문에서 메모이제이션 없이 줄마다 개별 `parser.parse`를 동기 호출하여, 기본 보기인 **좌우 비교(Side-by-Side)**에서 내용이 동일한 `context` 줄조차 좌·우 두 번씩 중복 파싱합니다.
   - 행 가상화(Virtualization) 없이 최대 1MB 패치의 수백~수천 행 `<table>`(`white-space: pre-wrap; word-break: break-word`)을 일괄 마운트해 브라우저 레이아웃 계산이 메인 스레드를 블로킹합니다.
   - 상위 **메인 창** 셸 상태 변화(**Compare 패널** 파일 필터 입력, 폴더 트리 접기/펼치기, 서브 탭 전환, **사이드바 리사이저** 드래그 등)가 메모이제이션되지 않은 **Diff 뷰어**로 전파되어 열려 있는 Diff 전체를 반복 재파싱합니다.
3. **단일 파일 포커스 탭 교체 시 캐시 즉시 증발**:
   - **Compare 패널**에서 다른 파일을 클릭하거나 이전/다음(`↑`/`↓`) 버튼으로 이동하면 단일 **Diff 탭**의 대상이 교체되는 즉시 직전 파일의 Diff 데이터가 스토어에서 삭제됩니다. 불변(immutable)에 가까운 `branch-compare`·`commit`·`stash` Diff조차 방금 본 파일로 돌아갈 때마다 IPC 왕복과 `git` 재실행, `"Diff 불러오는 중..."` 빈 화면 전환을 처음부터 반복합니다.

## Solution (해결 방안)

Git 백엔드 프로세스 실행 경로, 공통 **Diff 뷰어** 렌더링 파이프라인, 그리고 렌더러 세션의 불변 Diff 캐시 계층을 함께 최적화하여 파일 전환과 스크롤을 즉각적으로 반응하게 개선합니다.

1. **Git 백엔드 프로세스 스폰 최소화 및 `mergeBaseHash` 재사용**:
   - 정규화된 워크스페이스 경로별 Git 저장소 루트(`repoRoot`)를 경량 `.git` 존재 확인 기반으로 캐싱·검증해 반복적인 `rev-parse --show-toplevel` 실행과 중복 `realpath` 호출을 제거합니다.
   - `branch-compare` Diff 요청에 선택적 `mergeBaseHash`를 전달·검증하여, 비교 요약에서 이미 확인된 공통 조상을 재사용하고 정상 경로에서 단일 `git diff` 1회 실행만으로 패치를 반환합니다(실패 시에만 미커밋 저장소 여부를 판별해 기존 오류 메시지를 보존).
   - 비교 요약(`compareSummary`) 조회 시 사전 리비전 확인을 병렬화하고, 변경 파일 상태·이름 변경(`-M`)과 줄 수 통계(`numstat`)를 단일 `git diff` 실행으로 통합합니다.
2. **공통 Diff 뷰어 단일 패스 구문 강조·메모이제이션 및 리렌더 격리**:
   - 번들된 기본 언어 및 이미 로드된 언어 파서는 첫 렌더에서 동기적으로 즉시 조회하여 불필요한 비동기 상태 갱신과 이중 전체 렌더링을 제거하고, 아직 로드되지 않은 동적 언어 파서를 비동기로 불러오는 동안에는 중복 폴백 파싱을 생략합니다.
   - 패치당 단어 단위(Intra-line) 하이라이트를 1회만 계산해 **좌우 비교**·**인라인** 모드 간 재사용하고, 줄 내용 기반 구문 강조 스팬 메모이제이션으로 **좌우 비교**의 동일 `context` 줄 중복 파싱과 리렌더 재파싱을 제거합니다.
   - **Diff 뷰어**를 `React.memo` 및 안정적인 콜백·네비게이션 참조로 격리해 **Compare 패널** 필터링·트리 조작·사이드바 너비 조절 중 불필요한 재렌더링을 차단합니다.
3. **대용량 Diff 뷰포트 가상 스크롤(Windowing)**:
   - 일정 행 수를 초과하는 대용량 Diff에서는 현재 스크롤 영역 주변 행(오버스캔 포함)만 DOM과 구문 강조 계산 대상으로 렌더링하고 상·하단 스페이서 행으로 전체 스크롤 높이와 줄바꿈 행 높이를 유지하며, 다른 파일로 **Diff 탭** 대상이 바뀔 때 스크롤 위치를 최상단으로 초기화합니다(소규모 Diff는 오버헤드 없이 전체 행을 직접 렌더링).
4. **불변 Diff 세션 LRU 캐시 및 스냅샷 알림 병합**:
   - **메인 창**과 **보조 창** 모두에서 `branch-compare`·`commit`·`stash` 완료 결과를 개수 및 총 바이트 상한이 있는 세션 메모리 LRU 캐시에 유지하여, **Compare 패널** 목록 클릭이나 `↑`/`↓` 순회로 이전에 확인한 파일을 다시 열 때 IPC 호출과 로딩 화면 깜빡임 없이 즉시 표시합니다.
   - 워킹 트리(`staged`, `unstaged`) Diff의 최신성, Stash 삭제 시 무효화, 워크스페이스 전환 시 전체 초기화 불변식을 엄격히 유지합니다.

## User Stories (사용자 스토리)

1. As a 개발자·위키 작성자, I want **Compare 패널**에서 변경 파일을 처음 클릭했을 때 불필요한 사전 `git` 프로세스 대기 없이 즉시 **Diff 탭**이 열리기를 원하며, so that Windows 환경에서도 지연 없이 코드와 문서를 검토할 수 있습니다.
2. As a 개발자, I want `Base`/`Compare` 브랜치나 `3-dot`/`2-dot` 모드를 전환할 때 비교 요약과 변경 파일 트리가 빠르게 갱신되기를 원하며, so that 여러 브랜치와 워크트리 조합을 끊김 없이 비교할 수 있습니다.
3. As a 개발자, I want 수백~수천 줄 규모의 신규 문서나 대규모 리팩터링 파일을 **Diff 뷰어**(**좌우 비교** 및 **인라인**)로 열거나 스크롤할 때 화면 멈춤 없이 부드럽게 동작하기를 원하며, so that 대용량 변경분도 쾌적하게 리뷰할 수 있습니다.
4. As a 개발자, I want **Diff 탭**을 열어 둔 채 **Compare 패널**에서 파일 필터를 입력하거나 폴더 트리를 접고 펼치거나 **사이드바 리사이저**를 드래그할 때 입력 지연이 없기를 원하며, so that 파일 탐색과 화면 배치를 매끄럽게 조작할 수 있습니다.
5. As a 개발자, I want **Compare 패널**의 파일 목록 클릭이나 **Diff 뷰어** 헤더의 이전/다음(`↑`/`↓`) 버튼으로 이미 열어 본 파일로 다시 이동할 때 `"Diff 불러오는 중..."` 깜빡임이나 재조회 없이 즉시 화면이 전환되기를 원하며, so that 여러 파일을 앞뒤로 오가며 맥락을 대조할 수 있습니다.
6. As a 사용자, I want 다른 파일로 **Diff 탭**을 전환했을 때 스크롤이 문서 최상단에서 시작되고, 워크스페이스를 전환하거나 Stash를 정리했을 때 오래된 캐시가 남지 않기를 원하며, so that 항상 정확하고 예측 가능한 Diff 화면을 볼 수 있습니다.

## Implementation Decisions (구현 결정사항)

### 1. 공유 데이터 계약 확장 (기존 호환성 유지)

기존 `GitDiffRequest`의 `'branch-compare'` 분기에 선택적 `mergeBaseHash` 필드를 추가합니다(대화 맥락 및 기존 공유 Git 계약 기반 확정):

```ts
export type GitDiffRequest =
  | ({ kind: 'staged' } & GitChangedFile)
  | ({ kind: 'unstaged' } & GitChangedFile)
  | ({
      kind: 'commit'
      commitHash: string
      shortHash: string
    } & GitChangedFile)
  | ({
      kind: 'stash'
      stashRef: string
      stashHash: string
    } & GitChangedFile)
  | ({
      kind: 'branch-compare'
      baseRef: string
      compareRef: string
      mode: GitCompareMode
      mergeBaseHash?: string | null
    } & GitChangedFile)
```

- **탭 식별자 불변성**: **Diff 탭**의 결정적 식별 키(`formatGitDiffTabKey` 계열)는 기존과 동일하게 `mode`, `baseRef`, `compareRef`, `status`, `origPath`, `path`만으로 산출하며 `mergeBaseHash` 유무에 따라 탭 키가 달라지지 않도록 유지합니다.
- **하위 호환성 및 보안 검증**:
  - `mergeBaseHash`가 생략(`undefined`)된 직접 호출에서도 기존과 동일한 결과를 반환합니다.
  - `mergeBaseHash`가 문자열로 전달된 경우 기존 커밋 해시 검증 규칙(16진수 해시 형식 검증, 선행 `-`·공백·제어문자·범위 연산자 차단)을 동일하게 적용하며, 활성 워크스페이스 일치 및 저장소 내부 상대 경로 보안 검사를 그대로 유지합니다.
  - **Compare 패널**에서 여는 `branch-compare` Diff 요청과 Ref/모드 변경 시 탭 동기화, 그리고 **보조 창**으로의 **Diff 탭** 분리·이동 페이로드에 현재 요약의 `mergeBaseHash`를 함께 포함합니다.

### 2. Git 서비스 프로세스 실행 및 저장소 루트 캐싱 규칙

- **저장소 루트(`repoRoot`) 캐싱 및 자동 무효화**:
  - 정규화된 워크스페이스 실제 경로(`workspaceRealRoot`)에 대응하는 `repoRoot`를 메모리에 캐싱하되, 조회 시 캐시된 `repoRoot`의 `.git` 엔트리 존재 여부(및 워크스페이스가 하위 폴더인 경우 중간 경로에 새 `.git`이 생성되지 않았는지)를 파일시스템 메타데이터로 경량 확인합니다.
  - `.git` 확인에 실패하거나 `init` 작업이 수행되면 캐시를 무효화하고 `git rev-parse --show-toplevel`로 재해석하며, 커스텀 `GIT_DIR` 환경변수가 주입된 경우에는 캐시를 우회합니다.
  - `diff` 실행 시 이미 확인한 `workspaceRealRoot`를 재사용하여 중복 `realpath` 호출을 제거합니다.
- **`branch-compare` 단일 파일 Diff 실행 경로**:
  - `three-dot` 모드에서 유효한 `mergeBaseHash` 문자열이 전달되면 별도의 `HEAD` 확인이나 `merge-base` 프로세스를 띄우지 않고 `<mergeBaseHash>..<compareRef>` 범위로 단일 `git diff` 프로세스만 실행합니다.
  - `mergeBaseHash === null`(공통 조상 없음 확인 완료) 또는 `two-dot` 모드에서는 `<baseRef>..<compareRef>` 범위로 단일 `git diff` 프로세스만 실행합니다.
  - `mergeBaseHash === undefined`인 직접 호출에서는 필요한 리비전/`merge-base` 확인을 직렬이 아닌 병렬로 수행합니다.
  - 첫 커밋 전(`isUnborn`) 저장소에 대한 친화적 오류 메시지는 모든 정상 요청에서 사전 `HEAD` 프로세스를 띄우는 대신, `git diff` 실패 시에만 `HEAD` 커밋 존재 여부를 확인해 동일하게 반환합니다.
- **비교 요약(`compareSummary`) 통합 실행 경로**:
  - `HEAD`, `baseRef^{commit}`, `compareRef^{commit}` 리비전 확인과 브랜치/태그 참조 조회를 가능한 범위에서 병렬화합니다.
  - `three-dot` 모드에서 구한 `mergeBaseHash`가 존재하면 `diff` 범위에 `<mergeBaseHash>..<compareRef>`를 직접 사용해 Git 내부의 중복 `merge-base` 계산을 피합니다.
  - 변경 파일 상태/이름 변경(`--raw -z -M`)과 줄 수/바이너리 통계(`--numstat -z`)를 단일 `git diff` 호출(`--raw --numstat -z -M`)로 통합 파싱하여 전체 트리에 대한 rename 탐지(`-M`)가 1회만 수행되도록 합니다.

### 3. 공통 Diff 뷰어 구문 강조·메모이제이션·가상 스크롤 규칙

- **동기 우선 파서 해석 및 단일 패스 렌더링**:
  - 정적 번들에 포함된 언어 및 이미 로드 완료되어 캐시에 존재하는 `@codemirror/language-data` 파서는 동기 조회 함수로 첫 렌더에서 즉시 반환합니다.
  - 캐시에 없는 동적 언어 파서를 비동기로 로드하는 동안에는 임시 정적 폴백 파싱을 수행하지 않고 일반 텍스트(단어 단위 변경 하이라이트 포함)로 1차 표시한 뒤, 로드 완료 시 1회만 구문 강조를 반영합니다.
- **단어 단위 하이라이트 공유 및 줄 단위 구문 스팬 메모이제이션**:
  - 연속 삭제/추가 줄 쌍의 토큰 단위 LCS 계산은 파싱된 패치당 1회만 수행해 **좌우 비교**와 **인라인** 행 생성에서 공유하며, 2차원 중첩 배열 대신 1차원 버퍼를 사용해 가비지 컬렉션 부담을 줄입니다.
  - 줄 문자열과 활성 파서를 키로 하는 범위 제한 메모이제이션을 통해 **좌우 비교**의 좌·우 동일 `context` 줄 중복 파싱과 재렌더 시 재파싱을 방지합니다.
- **대용량 행 가상 스크롤(Windowing) 및 스크롤 초기화**:
  - 전체 행 수가 임계치(예: 200행) 이하인 소규모 Diff는 기존과 동일하게 모든 행을 직접 렌더링합니다.
  - 임계치를 초과하는 대용량 Diff에서는 스크롤 컨테이너의 현재 표시 구간과 상·하단 오버스캔 범위 내의 행만 실제 `<tr>` 및 구문 강조 대상으로 렌더링하고, 화면 밖 상·하단 구간은 높이를 보존하는 스페이서 `<tr>`로 대체합니다(자동 줄바꿈으로 실제 렌더링 높이가 기본 추정치와 다른 행은 측정값을 반영해 스크롤 점프를 방지하며, 레이아웃 측정값이 `0`인 헤드리스/초기 마운트 환경에서는 안전한 기본 뷰포트 높이로 첫 구간을 렌더링합니다).
  - **Diff 뷰어**가 표시하는 대상 파일 키가 변경되면 스크롤 컨테이너의 `scrollTop`을 `0`으로 초기화합니다(동일 파일 내 **좌우 비교** ↔ **인라인** 전환이나 워킹 트리 내용 갱신은 불필요하게 강제 초기화하지 않고 자연스럽게 동작).
- **리렌더 격리**:
  - **Diff 뷰어**에 `React.memo`를 적용하고 상위 **편집기 영역** 및 **메인 창**에서 전달하는 콜백과 이전/다음 파일 네비게이션 정보를 안정화해, **Compare 패널**의 파일 필터 입력·폴더 트리 토글·서브 탭 전환·**사이드바 리사이저** 드래그 시 **Diff 뷰어** 본문이 다시 렌더링되지 않도록 합니다.

### 4. 불변 Diff 세션 LRU 캐시 및 무효화 불변식

- **대상 분류**:
  - 불변(Immutable) Diff: `branch-compare`, `commit`, `stash` — 성공적으로 로드된(`status: 'loaded'`) 결과를 탭 교체 이후에도 세션 LRU 캐시에 보존합니다(오류 상태 `error`는 재시도 가능하도록 고정 캐싱하지 않음).
  - 가변(Mutable) Diff: `staged`, `unstaged` — 워킹 트리·인덱스 상태 변화에 따라 즉시 갱신되어야 하므로 열려 있는 탭 기준으로만 관리하고 탭이 닫히면 기존처럼 정리합니다.
- **용량 상한 (Bounded LRU)**:
  - 최근 조회 순서를 기준으로 최대 항목 수(예: 40개) 및 총 `rawPatch` 바이트 예산(예: 12MB, 단 단일 1MB 패치 최소 1개 이상 보장) 내에서 가장 오래 전에 참조된 비열림 불변 항목부터 퇴거(evict)합니다(현재 활성 **Diff 탭**에 열려 있는 항목은 퇴거 대상에서 제외).
- **무효화 및 동기화 규칙**:
  - 워크스페이스 전환 또는 세션 종료(`dispose`) 시 캐시 전체를 즉시 비웁니다.
  - Stash 목록 갱신 시 목록에서 사라진 `stashHash`에 해당하는 캐시 항목을 함께 제거합니다.
  - **메인 창**의 Git 세션 스토어와 **보조 창**의 Diff 상태 훅 모두 동일한 불변 LRU 보존 정책을 지원하여 **보조 창**에서도 재방문 시 불필요한 재요청이 발생하지 않도록 합니다.
  - 단일 **Diff 탭**을 열거나 교체할 때 스토어 스냅샷 커밋을 불필요하게 연속 2회 발생시키지 않고 병합하며, 캐시 히트 시에는 `'loading'` 중간 상태를 거치지 않고 즉시 로드된 Diff를 렌더링합니다.

## Testing Decisions (테스트 결정사항)

- **검증 기준**: 내부 캐시 자료구조나 비공개 헬퍼 함수가 아니라, 공개 Git 서비스/IPC 계약·실행된 Git 프로세스 호출 횟수/인자 경계·**Diff 뷰어** DOM 동작·사용자 관점 앱 통합 인터랙션을 기준으로 검증합니다.
- **사전 합의된 테스트 심(Pre-agreed Seams)**:
  1. **`GitService` + `registerGitIpc` 통합 테스트 심** (실제 임시 Git 샌드박스 + 프로세스 스폰 스파이/인터셉터):
     - *Catches*: `compareSummary` 단일 `git diff` 통합 파싱(일반 변경·rename·바이너리·`3-dot`/`2-dot`·동일 Ref), `mergeBaseHash` 전달 시 단일 프로세스 실행 및 미전달 하위 호환, 잘못된 `mergeBaseHash`/Ref/경로 인젝션 차단, 첫 커밋 전(`isUnborn`)·비Git 폴더 예외 보존, `repoRoot` 캐싱 및 `init` 후 갱신.
     - *Misses*: 렌더러 컴포넌트 렌더링, 가상 스크롤 레이아웃 및 세션 스토어 상태 전이.
  2. **`GitDiffViewer` 컴포넌트 테스트 심** (JSDOM `ResizeObserver` 및 스크롤 컨테이너 레이아웃 스텁 포함):
     - *Catches*: 번들/캐시된 언어 파서의 단일 패스 구문 강조 렌더링, **좌우 비교** `context` 줄 중복 파싱 방지, 대용량 패치(수백~수천 행) 마운트 시 렌더링되는 `<tr>` 수 제한 및 스크롤 이동에 따른 행 윈도우 갱신, 파일 전환 시 `scrollTop` 최상단 초기화, 상위 리렌더 시 메모이제이션 격리.
     - *Misses*: 실제 Chromium 테이블 픽셀 페인트 시간 및 Main 프로세스 IPC 왕복.
  3. **`App` + 인메모리 `WikiApi` 하네스 통합 테스트 심** (**메인 창** 및 다중 창 **보조 창** 하네스 포함):
     - *Catches*: **Compare 패널**에서 `mergeBaseHash`가 `git.diff` 요청과 **보조 창** 탭 이동까지 전달되는 흐름, 파일 목록 클릭 및 `↑`/`↓` 순회로 이미 본 `branch-compare`·`commit`·`stash` 파일을 다시 열 때 `git.diff` 재호출 0회 및 로딩 화면 미노출, LRU 용량 초과 퇴거, Stash 삭제·워크스페이스 전환 시 캐시 무효화, `staged`/`unstaged` 가변 Diff 실시간 갱신 유지.
     - *Misses*: 실제 `git` 바이너리 프로세스 스폰 비용.
- **참고할 기존 테스트 패턴(Prior art)**:
  - 백엔드 Git 통합 테스트: 임시 Git 샌드박스 및 `git worktree` 기반 브랜치 비교·Diff 통합 테스트 패턴.
  - 컴포넌트 레이아웃 테스트: `GitDiffViewer` 단위 테스트 및 JSDOM `ResizeObserver`/스크롤 컨테이너 스텁 헬퍼 패턴.
  - 렌더러 앱 통합 테스트: `App` + 인메모리 `WikiApi` 하네스 기반 Compare 뷰 및 다중 창 보조 창 테스트 패턴.

## Out of Scope (범위 제외 사항)

- Web Worker 기반 백그라운드 구문 분석 오프로딩 (동기 파서 캐시 + 줄 메모이제이션 + 뷰포트 가상화로 렌더링 대상 행 수가 수십 줄로 제한되므로 범위 제외)
- **Diff 뷰어** 내 텍스트 검색(`Ctrl+F`) 또는 접힌 컨텍스트 줄 펼치기(Expand context) 신설
- 여러 변경 파일의 Diff를 한 화면에 연속 스크롤로 나열하는 통합 PR 피드 보기 모드
- 디스크 영속 Diff 캐시 (`workspace-state.json` 등에 Diff 본문 저장하지 않음)
