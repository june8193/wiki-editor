# Spec: 마크다운 이미지 삽입 · 전 모드 렌더링 · 읽기 전용 이미지 탭

## Problem Statement (문제 정의)

현재 위키 에디터에서 마크다운 문서에 이미지를 삽입하거나 확인하려 할 때 세 가지 문제가 발생합니다.

1. **위지윅 모드 이미지 스키마 부재**: **위지윅** 모드의 에디터 스키마에 이미지 노드가 등록되어 있지 않아 마크다운 이미지가 화면에 렌더링되지 않으며, **위지윅** 모드로 전환해 편집할 경우 기존 이미지 구문이 손실될 수 있습니다.
2. **워크스페이스 로컬 이미지 경로 미해석 및 차단**: Preview 및 **위지윅** 렌더링 파이프라인이 활성 문서 기준 상대 경로를 해석하지 않고 외부 `http`·`https` 스킴만 허용하고 있어, `./assets/diagram.png`나 `../shared/logo.svg` 같은 로컬 이미지가 개발·프로덕션 환경 모두에서 표시되지 않습니다.
3. **클립보드 붙여넣기·드래그 앤 드롭 미지원 및 이미지 파일 텍스트 오염**: 캡처한 이미지를 `Ctrl+V`로 붙여넣거나 OS 탐색기 및 **탐색기 뷰**의 **폴더 트리**에서 이미지 파일을 드래그 앤 드롭하여 삽입하는 경로와 바이너리 저장 계층이 없습니다. 또한 **폴더 트리**에 있는 이미지 파일을 클릭하면 UTF-8 텍스트로 읽혀 깨진 문자로 열리고 자동 저장 시 원본 바이너리 파일이 손상될 위험이 있습니다.

## Solution (해결 방안)

1. **안전한 로컬 에셋 프로토콜 및 전 에디터 모드 이미지 렌더링**:
   - Electron 메인 프로세스에 열린 워크스페이스 루트 내부 실경로만 서빙하는 전용 에셋 프로토콜(`wiki-asset:`)을 등록하고, 현재 문서 경로 기준 상대 경로 해석기와 **위지윅** 이미지 노드를 연결합니다.
   - 이를 통해 `![alt](./assets/...)` 로컬 이미지와 `![alt](https://...)` 외부 이미지를 **Raw**·**위지윅**·**Preview**·**Split** 네 가지 **에디터 모드** 전체에서 반응형(`max-width: 100%`)으로 표시하고 표준 마크다운 구문을 무손실 왕복 보존합니다.
2. **클립보드 붙여넣기 및 파일·폴더 트리 드래그 앤 드롭 이미지 수집(Ingestion)**:
   - 깊은 단일 워크스페이스 이미지 수집 인터페이스를 통해 클립보드 비트맵과 워크스페이스 외부 드롭 이미지는 현재 마크다운 문서 하위 `assets/` 폴더에 자동 명명·충돌 회피(`-1`, `-2`) 규칙으로 즉시 저장한 뒤 `./assets/<파일명>`을 삽입합니다.
   - 이미 열린 워크스페이스 내부에 존재하는 이미지(OS 탐색기 드롭 또는 **폴더 트리** 드롭)는 중복 복사하지 않고 현재 문서 기준 상대 경로로 바로 연결합니다.
3. **폴더 트리 연동 읽기 전용 이미지 미리보기 탭**:
   - **폴더 트리**에서 지원 이미지 파일을 열 때 UTF-8 텍스트 읽기·쓰기 및 자동 저장에서 분리된 읽기 전용 이미지 미리보기 뷰를 **문서 편집기** 탭으로 제공하여 앱 안에서 안전하게 이미지를 확인하고 **화면 분할 모드**·이름 변경·삭제와 일관되게 연동합니다.

## User Stories (사용자 스토리)

1. As a 위키 작성자, I want 마크다운 문서에 작성한 로컬 상대 경로 이미지(`![설명](./assets/pic.png)`, `![설명](../shared/arch.svg)`)와 외부 웹 이미지(`https://...`)가 **위지윅**, **Preview**, **Split** 모든 **에디터 모드**에서 본문 폭(`max-width: 100%`)에 맞춰 선명하게 렌더링되기를 원하며, so that 별도 외부 뷰어 없이 문서 내 시각 자료를 즉시 확인할 수 있습니다.
2. As a 위키 작성자, I want **Raw**와 **위지윅** 사이를 반복 전환하거나 **위지윅** 안에서 이미지를 복사·붙여넣고 문서를 편집하더라도 마크다운 원문의 표준 `![alt](상대경로)` 구문이 내부 프로토콜 URL로 변질되지 않고 그대로 유지되기를 원하며, so that 다른 마크다운 도구 및 Git 저장소와의 호환성을 지킬 수 있습니다.
3. As a 위키 작성자, I want 화면 캡처나 복사한 이미지를 **Raw** 또는 **위지윅** 모드에서 `Ctrl+V`로 붙여넣으면 별도 이름 입력 창 없이 `<문서명>-YYYYMMDD-HHmmss.<확장자>` 파일이 현재 문서 폴더 하위 `assets/`에 자동 저장되고 마크다운 이미지가 즉시 삽입되기를 원하며, so that 문서 작성 흐름을 끊지 않고 스크린샷을 빠르게 첨부할 수 있습니다.
4. As a 위키 작성자, I want 일반 텍스트, 코드, 표 셀 등 텍스트 데이터가 포함된 클립보드를 붙여넣을 때는 이미지 수집이 가로채지 않고 기존 텍스트·서식 붙여넣기가 그대로 동작하기를 원하며, so that 일상적인 편집 작업이 방해받지 않습니다.
5. As a 위키 작성자, I want OS 파일 탐색기에서 워크스페이스 외부의 이미지 파일(단일 또는 다중)을 **Raw**나 **위지윅** 본문으로 드래그 앤 드롭하면 원본 파일명을 유지(충돌 시 `-1`, `-2` 자동 부여)한 채 현재 문서 하위 `assets/`로 복사되고 문서에 삽입되기를 원하며, so that 외부 이미지 자료를 손쉽게 위키 안으로 가져올 수 있습니다.
6. As a 위키 작성자, I want 이미 현재 워크스페이스 내부에 있는 이미지 파일을 OS 탐색기나 왼쪽 사이드바 **폴더 트리**에서 에디터로 드래그 앤 드롭하면 불필요한 복사본을 만들지 않고 현재 문서 기준 상대 경로(`../common/logo.png` 등)로 바로 연결되기를 원하며, so that 공용 이미지를 중복 없이 재사용할 수 있습니다.
7. As a 위키 작성자, I want 비이미지 파일을 드롭하거나 에디터 바깥 창 영역에 파일을 잘못 놓더라도 앱 창이 해당 파일 경로로 네비게이션되어 작업 화면이 사라지지 않기를 원하며, so that 작성 중인 미저장 문서를 안전하게 보호할 수 있습니다.
8. As a 위키 작성자, I want **폴더 트리**에서 `.png`, `.jpg` 등 이미지 파일을 클릭했을 때 깨진 텍스트 대신 읽기 전용 이미지 미리보기 탭으로 열리고 파일 이름 변경·삭제·**화면 분할 모드**와 자연스럽게 동기화되기를 원하며, so that 첨부된 이미지를 안전하게 검수하고 문서와 나란히 비교할 수 있습니다.

## Implementation Decisions (구현 결정사항)

### 1. 지원 이미지 형식 및 경로·인코딩 규칙
- **지원 이미지 확장자 및 MIME**: `.png`(`image/png`), `.jpg`·`.jpeg`(`image/jpeg`), `.gif`(`image/gif`), `.webp`(`image/webp`), `.svg`(`image/svg+xml`), `.bmp`(`image/bmp`), `.avif`(`image/avif`)를 대소문자 구분 없이 지원합니다.
- **마크다운 경로 표기 불변식**:
  - 현재 문서 하위 `assets/`에 저장된 이미지는 항상 `./assets/<파일명>` 형태의 POSIX 슬래시 상대 경로로 기록합니다.
  - 워크스페이스 내 다른 폴더의 이미지를 참조할 때는 활성 문서 디렉터리 기준 POSIX 상대 경로(`./...` 또는 `../...`)로 기록합니다.
  - 파일명이나 상위 폴더명에 공백 또는 괄호(`(`, `)`) 등 CommonMark 링크 구분 문자가 포함된 경우, 파서 호환을 위해 경로 세그먼트를 안전하게 퍼센트 인코딩하여 **Raw**·**위지윅**·**Preview** 전 모드에서 동일하게 파싱되도록 보장합니다.
  - 삽입 시 기본 대체 텍스트(`alt`)는 확장자를 제외한 파일명 스템(예: `![diagram](./assets/diagram.png)`)을 사용하여 접근성 역할(`role="img"`)을 보장합니다.

### 2. 전용 로컬 에셋 프로토콜(`wiki-asset:`) 및 보안 경계
- **프로토콜 등록 및 URL 매핑**:
  - Electron 앱 초기화 시 표준·보안 스킴으로 전용 로컬 에셋 프로토콜(`wiki-asset:`)을 등록합니다. Windows 드라이브 문자(`C:`)나 대소문자 정규화로 인한 호스트 파싱 왜곡을 피하기 위해 고정 호스트와 인코딩된 경로 파라미터 구조를 사용합니다.
  - 사용자 작성 마크다운 원문이나 외부 입력의 URI 허용 목록에는 `wiki-asset:`을 직접 열지 않고, 새니타이즈 단계 이후 렌더러의 이미지 표시 계층에서만 활성 워크스페이스 문서 경로와 상대 이미지 경로를 결합해 `wiki-asset:` URL을 생성합니다.
- **메인 프로세스 보안 불변식**:
  - 프로토콜 핸들러는 기존 워크스페이스 파일 시스템 모듈과 동일한 경로 검증 규칙을 강제합니다: 열린 워크스페이스가 없으면 거부하고, 요청 경로의 실경로(`realpath`)가 현재 열린 워크스페이스 루트 내부에 속하는지 확인하며, 상위 경로 탈출(`..`)·외부 심볼릭 링크·무시 대상 시스템 경로(`.git`, `node_modules` 등) 및 비이미지 확장자 접근을 차단합니다.
  - 응답 시 확장자에 맞는 정확한 `Content-Type` 헤더와 함께 스크립트 실행을 원천 차단하는 `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'` 헤더를 부여합니다(특히 SVG 에셋 방어).

### 3. Preview 및 위지윅 이미지 렌더링·왕복 계약
- **Preview 및 Split 모드**:
  - 마크다운 Preview 렌더러는 선택적 활성 문서 경로 컨텍스트를 받아, HTML 새니타이즈(`rehype-sanitize`) 이후 이미지 요소의 로컬 상대 `src`를 `wiki-asset:` 표시 URL로 변환합니다(`http://`, `https://` 외부 URL은 그대로 유지하며 `javascript:`, `data:text/html` 등 위험 스킴은 기존과 동일하게 제거).
- **위지윅 모드 원본 경로 보존 불변식**:
  - TipTap 이미지 확장을 기반으로 이미지 노드를 구성하되, ProseMirror 문서 상태의 이미지 노드 `src` 속성은 항상 **마크다운 원문 경로**(예: `./assets/pic.png`)를 그대로 보관합니다.
  - DOM `<img>` 요소를 렌더링할 때만 현재 문서 경로 기준 `wiki-asset:` 표시 URL을 주입하고 원본 경로를 데이터 속성(`data-markdown-src`)에 함께 기록하며, HTML 파싱 시 `data-markdown-src`가 있으면 이를 우선 복원합니다. 이를 통해 `getMarkdown()` 직렬화, 모드 전환 왕복, **위지윅** 내부 이미지 잘라내기·복사·붙여넣기 전 과정에서 `wiki-asset:` 내부 URL이 마크다운 원문에 유출되지 않도록 보장합니다.
- **표시 스타일**:
  - 드래그 리사이즈 핸들이나 HTML `<img width="...">` 강제 변환 없이 표준 마크다운 구문을 유지하며, **위지윅**·**Preview**·**Split** 본문 내 이미지는 컨테이너 가로 폭을 넘지 않도록 `max-width: 100%; height: auto` 스타일을 적용합니다.

### 4. 워크스페이스 이미지 수집(Ingestion) 깊은 모듈 계약
- 렌더러가 폴더 생성·중복 검사·파일 쓰기를 여러 IPC 호출로 조합하지 않도록, 워크스페이스 파일 시스템 계층과 IPC 브리지에 단일 이미지 수집 인터페이스를 둡니다:

```ts
// 합의된 도메인 계약 형태 (설계 확정)
export type WorkspaceImageIngestSource =
  | {
      kind: 'clipboard'
      bytes: Uint8Array
      mimeType: string
      now?: number // 테스트 결정성 주입용 선택 타임스탬프
    }
  | {
      kind: 'filePath'
      filePath: string
    }
  | {
      kind: 'fileBytes'
      fileName: string
      bytes: Uint8Array
    }

export interface WorkspaceImageIngestInput {
  documentPath: string
  source: WorkspaceImageIngestSource
}

export interface WorkspaceImageIngestResult {
  markdownPath: string // 예: "./assets/guide-20261115-183000.png" 또는 "../shared/logo.png"
  altText: string
  savedPath: string
}
```

- **저장 위치 및 명명·충돌 회피 규칙**:
  - `documentPath`는 반드시 현재 열린 워크스페이스 내부의 유효한 파일 경로여야 합니다(`config.json` 등 비워크스페이스 버퍼에서는 이미지 수집 비활성화).
  - **워크스페이스 내부 이미지 참조 (`kind: 'filePath'`이고 대상 실경로가 현재 열린 워크스페이스 루트 내부이며 무시 폴더가 아닌 지원 이미지인 경우)**: 파일을 복사하지 않고 `documentPath`가 속한 폴더에서 해당 이미지로의 상대 경로를 계산해 반환합니다.
  - **외부 파일 복사 (`kind: 'filePath'` 외부 경로 또는 `kind: 'fileBytes'`)**: `<문서폴더>/assets/` 디렉터리를 자동 생성(없을 때만)하고 원본 파일명을 유지하되, 동명 파일이 이미 존재하면 `<이름>-1.<확장자>`, `<이름>-2.<확장자>` 순으로 배타적 파일 생성(`wx`)을 시도해 덮어쓰기와 경쟁 조건을 방지합니다.
  - **클립보드 비트맵 저장 (`kind: 'clipboard'`)**: 문서 파일명 스템(비어 있거나 사용할 수 없는 문자는 안전한 기본값으로 정규화)과 로컬 시각 타임스탬프를 조합해 `<문서명>-YYYYMMDD-HHmmss.<확장자>`로 `<문서폴더>/assets/`에 배타적 생성(`wx`, 동초 다중 붙여넣기 시 `-1`, `-2` 부여)합니다.

### 5. 에디터 붙여넣기·드래그 앤 드롭 및 창 보호 규칙
- **클립보드 붙여넣기 판별**:
  - `Raw` 및 `위지윅` 에디터의 마크다운 문서에서 `paste` 이벤트 발생 시, 클립보드에 복사된 이미지 파일이 있거나 `text/plain` 텍스트가 비어 있는 상태에서 지원 이미지 비트맵 항목이 존재할 때만 이미지 수집으로 처리합니다(`text/plain`이 존재하는 일반 텍스트·코드·스프레드시트 표 복사는 기존 텍스트 붙여넣기 유지).
- **드래그 앤 드롭 처리**:
  - **폴더 트리**의 이미지 파일 행은 드래그 가능(`draggable`)하도록 구성하며, 탭 분할 드롭 페이로드와 충돌하지 않는 전용 내부 드래그 데이터 타입으로 워크스페이스 파일 경로를 전달합니다(**편집 공간**의 탭 분할 드롭존은 탭 드래그 중에만 활성화되므로 간섭하지 않음).
  - OS 파일 탐색기 드롭 시에는 preload 브리지(`webUtils.getPathForFile` 등)로 원본 파일 경로를 조회해 `filePath` 소스로 전달하고, 경로를 얻을 수 없는 환경에서는 파일 바이트(`fileBytes`) 폴백을 사용합니다.
  - 다중 이미지 드롭 시 전달된 파일 순서를 유지해 줄바꿈(문단) 단위로 모두 삽입하며, 드롭 좌표에 해당하는 에디터 위치(좌표 해석 불가 시 현재 선택 커서 위치)에 삽입합니다.
  - 앱 창 전역 및 메인 `webContents` 수준에서 파일 드롭으로 인한 기본 브라우저 파일 네비게이션을 차단합니다.

### 6. 읽기 전용 이미지 미리보기 탭 및 도메인 용어집 동기화
- **이미지 전용 문서 버퍼**:
  - **문서 버퍼**가 텍스트 문서뿐 아니라 워크스페이스 이미지 항목을 표현할 수 있도록 구분하며, 지원 이미지 확장자 파일을 열 때는 UTF-8 `readFile`을 호출하지 않고 읽기 전용 이미지 버퍼로 개설합니다.
  - 이미지 버퍼는 항상 `isDirty: false`를 유지하며 자동 저장 타이머·수동 저장(`Ctrl+S`)·일괄 저장 확인 및 외부 변경 시 UTF-8 텍스트 비교(`reconcileWorkspaceBuffersWithDisk`)에서 안전하게 제외하되, 외부 파일 삭제 시 탭 닫기·파일 이름 변경 시 경로/제목 리매핑·외부 이미지 갱신 시 캐시 무효화(리로드)를 지원합니다.
  - **문서 편집기**에서 이미지 버퍼가 활성화되면 텍스트용 **에디터 모드** 전환기와 저장 버튼을 비활성화(또는 읽기 전용 표시)하고 중앙 정렬된 반응형 이미지 미리보기 뷰를 렌더링합니다.
- **도메인 용어집(`CONTEXT.md`) 동기화**:
  - **문서 버퍼** 및 **문서 편집기** 관련 설명에 마크다운 이미지 렌더링과 읽기 전용 이미지 미리보기 동작을 반영합니다.

## Testing Decisions (테스트 결정사항)

- **검증 기준**: 내부 구현 세부사항이 아닌 역할·접근 가능한 이름·속성(`getByRole('img')`, `getByLabelText`, 마크다운 직렬화 결과 등) 중심의 사용자 관찰 가능 동작을 **Red → Green → Refactor** TDD 절차로 검증하며, 모든 테스트는 임시 디렉터리 또는 인메모리 어댑터로 완전히 격리합니다.
- **사전 합의 테스트 심 (Pre-agreed Seams)**:
  1. **`<App />` 공개 UI 통합 심 (React Testing Library + 인메모리 `WikiApi` 어댑터)**:
     - **Catches**: `Raw`·`위지윅` 클립보드 이미지 붙여넣기(`Ctrl+V`) 및 일반 텍스트 붙여넣기 구분 오류, 외부 파일 및 **폴더 트리** 드래그 앤 드롭 삽입 누락, 4개 **에디터 모드** 전환 시 이미지 렌더링 누락·내부 프로토콜 URL 원문 유출 회귀, **폴더 트리** 이미지 클릭 시 깨진 텍스트 편집기 노출·자동 저장 오염 및 이름 변경·삭제 동기화 누락
     - **Misses**: 실제 OS 디스크 바이너리 저장·배타적 파일 생성(`wx`), 심볼릭 링크·경로 탈출 차단, Electron 메인 프로세스 프로토콜 바이트 응답
  2. **워크스페이스 파일 시스템 및 로컬 에셋 프로토콜 심 (임시 디렉터리 기반 Vitest 통합 테스트)**:
     - **Catches**: 문서 하위 `assets/` 자동 생성 및 파일명 규칙(`<문서명>-YYYYMMDD-HHmmss.<확장자>`, 원본 파일명 유지, `-1`·`-2` 충돌 회피) 오류, 워크스페이스 내부 이미지 중복 복사 회귀, 상위 경로·심볼릭 링크·시스템 폴더(`.git`, `node_modules`) 탈출 보안 취약점, `wiki-asset:` 프로토콜의 MIME·CSP 헤더 및 오류 상태 코드 불일치
     - **Misses**: 렌더러 DOM의 클립보드·드래그 이벤트 전달 및 화면 레이아웃 스타일링
  3. **마크다운 Preview · 위지윅 직렬화 및 보안 심 (`renderMarkdownToReact` + TipTap 에디터 인스턴스 / Vitest)**:
     - **Catches**: 공백·괄호가 포함된 상대 경로의 CommonMark 파싱·인코딩 깨짐, **위지윅** 마크다운 왕복(`getMarkdown()`) 및 내부 복사·붙여넣기 시 원본 상대 경로 변질, 악성 URI(`javascript:`, `data:text/html`) 및 `<img onerror>` XSS 새니타이즈 우회
     - **Misses**: Electron IPC 브리지 및 실제 파일 시스템 입출력
- *(위 심 목록은 사용자 승인을 거쳐 `/ticket-runner`의 사전 합의된 심(Pre-agreed Seams)으로 사용됩니다.)*
- **참고할 기존 테스트 패턴 (Prior Art)**:
  - `<App />` 통합 테스트의 인메모리 `createInMemoryWikiApi` 하네스 및 모드 전환·분할 영역·**폴더 트리** 조작 패턴
  - `WorkspaceFsService` 테스트의 `mkdtemp` 임시 디렉터리 및 경로 탈출·심볼릭 링크·시스템 폴더 차단 검증 패턴
  - `markdownPreview` 및 `wysiwygMarkdown` 테스트의 GFM 직렬화 왕복 및 XSS 새니타이즈 검증 패턴

## Out of Scope (범위 제외 사항)

- **서식 툴바**의 이미지 삽입 버튼, 네이티브 파일 선택 다이얼로그 삽입, **슬래시 명령어 메뉴** 기본 이미지 명령어 추가
- 붙여넣기·드롭 시 파일명을 수동 입력받는 프롬프트 모달
- **전역 설정 패널**(`config.json`)을 통한 이미지 저장 폴더 경로 커스터마이징
- **위지윅** 모드 내 마우스 드래그 이미지 크기 조절(리사이즈 핸들) 및 HTML `<img width="...">` 직렬화 변환
- 마크다운 본문에서 이미지 참조를 지웠을 때 `assets/` 폴더 내 미참조 파일을 자동 삭제하는 가비지 컬렉션

## Further Notes (기타 참고사항)

- **성능 및 메모리**: 로컬 이미지는 Base64 데이터 URI로 마크다운이나 메모리에 인라인하지 않고 파일 시스템 경로와 `wiki-asset:` 스트리밍/바이트 응답으로 처리하여, 고해상도 스크린샷이 여러 장 포함된 문서에서도 마크다운 버퍼 크기와 에디터 반응 속도를 가볍게 유지합니다.
