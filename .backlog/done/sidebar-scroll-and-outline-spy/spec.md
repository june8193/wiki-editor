# Spec: 사이드바 스크롤 격리 · Git 패널 고정 헤더 · 문서 목차 위치 추적

## Problem Statement (문제 정의)

긴 마크다운 문서를 열거나 탐색할 때 레이아웃 스크롤과 사이드바 탐색 경험에 세 가지 문제가 있습니다.

1. **문서 스크롤 시 전체 화면 이탈**: **문서 편집기**를 감싸는 세로 플렉스 체인에 최소 높이 해제와 오버플로우 격리가 누락되어, 긴 문서를 열면 문서 본문 영역이 아닌 앱 전체 높이가 문서 길이만큼 늘어납니다. 그 결과 문서를 아래로 스크롤하면 **액티비티 바**, **왼쪽 사이드바**, **우측 사이드바**, **탭 바**, **에디터 헤더**, **서식 툴바**가 모두 화면 위로 밀려 올라가 사라지고 좌우에는 빈 배경만 남습니다.
2. **Git 패널의 레거시 내부 접기 혼선**: 단일 뷰 사이드바 개편 이후 **왼쪽 사이드바**는 한 번에 하나의 뷰만 표시하고 **액티비티 바**로 전체 접기/펼치기를 수행하지만, **Git 패널** 헤더에는 과거 다중 패널 적층 시절의 내부 접기 토글(`▾`/`▸`)이 그대로 남아 있습니다. 이를 누르면 사이드바가 접히는 대신 빈 사이드바 기둥만 남은 채 본문만 숨겨져 혼란을 줍니다.
3. **문서 목차의 현재 위치 파악 불가**: 긴 문서를 스크롤하며 읽거나 편집할 때 **우측 사이드바**의 **문서 목차**에 현재 보고 있는 섹션이 표시되지 않으며, 목차가 길어도 자동으로 따라오지 않아 문서 내 현재 위치를 파악하기 어렵습니다.

## Solution (해결 방안)

1. **앱 셸 높이 고정 및 영역별 독립 스크롤 격리**: 앱 최상위 루트와 앱 셸을 창 높이에 고정하고 플렉스 컨테이너 체인의 최소 높이·오버플로우를 격리하여, **액티비티 바**·**왼쪽 사이드바**·**우측 사이드바**·**탭 바**·**에디터 헤더**·**서식 툴바**·**표 편집 툴바**(Raw 상단 고정형)는 제자리에 고정된 채 각 사이드바 목록과 문서 본문만 독립적으로 스크롤되게 합니다.
2. **Git 패널 고정 헤더 통일**: **Git 패널** 내부의 접기 상태와 토글 버튼을 제거하고, **탐색기 뷰**·**워크스페이스 뷰**·**문서 목차**와 일관되게 제목·현재 브랜치 배지·Ahead/Behind 배지·새로고침 버튼을 상시 표시하는 고정 헤더로 정리합니다.
3. **우측 사이드바 문서 목차 위치 추적 (Scroll Spy)**: 활성 **편집기 영역**의 마크다운 문서를 **Raw**·**위지윅**·**Preview** 어느 **에디터 모드**로 스크롤하더라도 본문 상단 기준 위치에 해당하는 헤딩을 **문서 목차**에서 실시간으로 강조하고, 활성 항목이 목차 가시 영역 밖으로 벗어났을 때만 최소 이동(`nearest`)으로 자동 스크롤합니다.

## User Stories (사용자 스토리)

1. As a 위키 작성자, I want 긴 문서를 아래로 스크롤해도 **액티비티 바**, **왼쪽 사이드바**, **우측 사이드바**, **탭 바**, **에디터 헤더**, **서식 툴바**가 화면 제자리에 고정되어 유지되고 문서 본문만 스크롤되기를 원하며, so that 문서 어느 위치에서도 파일 탐색·Git 작업·목차 이동·서식 편집을 즉시 수행할 수 있습니다.
2. As a 위키 작성자, I want **왼쪽 사이드바**의 각 뷰(**폴더 트리**, **Git 패널**, **워크스페이스 뷰**)와 **우측 사이드바**의 **문서 목차**가 각자 헤더는 고정된 채 내부 본문만 독립적으로 스크롤되기를 원하며, so that 파일이나 헤딩이 많아도 문서 본문 스크롤과 서로 간섭하지 않습니다.
3. As a 위키 작성자, I want **화면 분할 모드**(`좌우 분할`, `상하 분할`)에서도 **주 편집기 영역**과 **보조 편집기 영역** 각각이 상단 **탭 바**·**에디터 헤더**·**서식 툴바**를 고정한 채 자기 영역의 문서 본문만 독립 스크롤하기를 원하며, so that 두 문서를 나란히 비교·편집할 때도 레이아웃이 무너지지 않습니다.
4. As a 위키 작성자, I want **Git 뷰**의 **Git 패널** 헤더가 불필요한 내부 접기 토글 없이 브랜치·동기화 상태와 새로고침 액션만 깔끔하게 표시하고 본문을 항상 노출하기를 원하며, so that 사이드바 접기 동작과 혼동하지 않고 일관된 헤더 경험을 얻습니다.
5. As a 위키 작성자, I want **Preview**, **위지윅**, **Raw** 세 **에디터 모드** 모두에서 문서 본문을 스크롤할 때 현재 화면 상단에 위치한 섹션의 헤딩이 **문서 목차**에서 강조 표시되기를 원하며, so that 어떤 모드로 작업하든 현재 읽거나 편집 중인 문서 위치를 즉시 확인할 수 있습니다.
6. As a 위키 작성자, I want 문서 스크롤에 따라 바뀐 활성 헤딩이 **문서 목차**의 보이는 영역 밖에 있을 때만 목록이 최소한으로 자동 스크롤되기를 원하며, so that 목차가 불필요하게 출렁이지 않으면서도 활성 헤딩을 항상 시야 안에 둘 수 있습니다.
7. As a 위키 작성자, I want **문서 목차**에서 특정 헤딩(특히 문서 하단의 짧은 섹션)을 클릭해 이동했을 때 클릭한 헤딩이 즉시 활성 상태로 강조 유지되기를 원하며, so that 스크롤 한계 때문에 윗 섹션이 잘못 강조되는 어색함 없이 선택한 위치를 명확히 볼 수 있습니다.
8. As a 위키 작성자, I want 탭을 전환하거나 **에디터 모드**를 바꾸거나 분할된 다른 **편집기 영역**으로 포커스를 옮기면 **문서 목차**의 활성 헤딩이 새 활성 문서의 스크롤 위치에 맞춰 즉시 갱신되기를 원하며, so that 항상 현재 집중하고 있는 문서의 정확한 위치가 표시됩니다.

## Implementation Decisions (구현 결정사항)

- **앱 셸 및 편집 공간 높이·오버플로우 격리**:
  - 루트 문서(`html`, `body`, `#root`)와 최상위 앱 셸, 본문 행 레이아웃에 오버플로우 차단을 적용하여 앱 창 자체에 전체 페이지 스크롤바가 생기지 않도록 보장합니다.
  - **편집기 영역**과 **문서 편집기**를 잇는 세로 플렉스 체인 전체에 최소 높이 제약 해제(`min-height: 0`)와 오버플로우 격리를 적용하고, 각 영역의 상단 고정 바(**탭 바**, **에디터 헤더**, **서식 툴바**, Raw 상단 **표 편집 툴바**)와 사이드바 헤더에 축소 방지(`flex-shrink: 0`)를 명시합니다.
  - **왼쪽 사이드바** 내부 뷰 컨테이너들도 최소 높이 제약 해제 및 오버플로우 정리를 통해 창 높이를 넘지 않도록 맞추되, 뷰포트 고정 좌표(`position: fixed`)를 사용하는 **폴더 트리** 컨텍스트 메뉴와 네이티브 브랜치 선택 드롭다운이 잘리지 않도록 유지합니다.
- **Git 패널 고정 헤더 구조**:
  - **Git 패널** 컴포넌트 내부의 접힘 상태(`isCollapsed`) 및 헤더 전체를 감싸던 토글 버튼을 제거합니다.
  - 헤더 좌측은 정적 제목 그룹(`Git` 텍스트, 저장소일 때 현재 브랜치 배지 및 Ahead/Behind 배지), 우측은 기존 새로고침 버튼으로 구성하며 본문 영역은 항상 렌더링합니다.
- **문서 목차 활성 헤딩 판정 계약**:
  - 활성 헤딩 상태는 0 기반 인덱스(`number | null`)로 표현하며, 활성 **편집기 영역**의 활성 탭이 마크다운 문서이고 파싱된 헤딩이 존재할 때만 유효한 인덱스를 가집니다(그 외에는 `null`).
  - **상단 기준선 판정 규칙(순수 함수로 분리)**:
    - **Preview** 및 **위지윅** 모드: 문서 본문 스크롤 컨테이너 가시 영역 상단 기준선(컨테이너 상단에서 소폭의 여유 오프셋, 예: 24px) 이하에 상단이 도달한 헤딩 중 **가장 마지막 헤딩**의 인덱스를 반환합니다. 첫 번째 헤딩 상단이 아직 기준선보다 아래에 있는 서문 구간이면 `null`을 반환합니다.
    - **Raw** 모드: 원문 에디터 스크롤 뷰포트의 동일한 상단 기준선 높이에 걸친 문서 줄 번호(1-based)를 조회하여, 시작 줄 번호(`line`)가 해당 줄 번호 이하인 헤딩 중 **가장 마지막 헤딩**의 인덱스를 반환합니다(첫 헤딩 줄 이전이면 `null`).
    - **수동 스크롤 최하단 도달 보정**: 문서가 실제로 스크롤된 상태(`scrollTop > 0`)에서 스크롤 컨테이너 바닥 끝(남은 여유 2px 이하)에 도달한 경우 마지막 헤딩 인덱스를 반환합니다. 단, 스크롤바가 없는 짧은 문서(`scrollTop === 0`)에서는 일반 상단 기준선 규칙을 그대로 적용해 첫 화면에서 마지막 헤딩으로 잘못 점프하지 않게 합니다.
- **문서 목차 클릭 이동 시 활성 헤딩 고정 및 해제 전이**:
  - 사용자가 **문서 목차**에서 헤딩 항목을 클릭하면 클릭한 헤딩 인덱스를 즉시 활성 헤딩으로 지정합니다.
  - 클릭으로 유발된 프로그래밍 방식 스크롤 이동 동안에는 스크롤 이벤트가 들어와도 클릭한 헤딩 인덱스가 윗 헤딩으로 덮어써지지 않도록 보호하며, 이후 사용자의 실제 추가 스크롤 입력이 발생하거나 활성 탭·**편집기 영역**·**에디터 모드**가 전환되면 일반 스크롤 판정으로 복귀합니다.
- **문서 목차 강조 표현 및 자동 스크롤**:
  - 활성 인덱스에 해당하는 **문서 목차** 항목 버튼에 `aria-current="location"` 속성과 활성 시각 스타일을 부여하고, 비활성 항목에는 `aria-current`를 부여하지 않습니다.
  - 활성 인덱스가 `null`이 아닌 값으로 변경될 때 해당 버튼 요소에 대해 `scrollIntoView({ block: 'nearest' })`를 호출하여 **문서 목차** 스크롤 영역 밖에 있을 때만 화면 안으로 최소 이동시킵니다(메서드 미지원 테스트 환경에서는 안전하게 건너뜁니다).
- **도메인 용어집 동기화**:
  - `CONTEXT.md`의 **문서 목차** 정의에 문서 스크롤 위치에 따른 현재 헤딩 강조 및 목차 자동 스크롤 동작을 반영합니다.

## Testing Decisions (테스트 결정사항)

- 검증 기준: 내부 구현 세부사항이 아닌 역할·접근 가능한 이름·속성(`getByRole`, `getByLabelText`, `aria-current="location"`) 등 사용자 관점의 외부 관찰 동작을 검증합니다. 모든 테스트는 인메모리 하네스로 격리하여 실제 파일 시스템이나 설정 파일을 건드리지 않습니다.
- 사전 합의 테스트 심(Pre-agreed Seams):
  - **활성 헤딩 판정 순수 함수 심 (Vitest 단위 테스트)**: Catches 첫 헤딩 이전 서문 구간(`null`), 상단 기준선 경계값 통과, 짧은 비스크롤 문서(`scrollTop === 0`)와 스크롤 최하단 도달(`scrollTop > 0`) 구분, 픽셀 오프셋·줄 번호 기반 헤딩 인덱스 계산 오류 / Misses 실제 에디터 DOM 좌표 측정 및 스크롤 이벤트 연결.
  - **`<GitSidebarPanel />` 및 `<DocumentOutlinePanel />` 컴포넌트 심 (React Testing Library)**: Catches **Git 패널** 레거시 내부 접기 토글 잔존 여부 및 고정 헤더(브랜치·Ahead/Behind·새로고침) 회귀, **문서 목차** 활성 항목의 `aria-current="location"` 전환 및 `scrollIntoView({ block: 'nearest' })` 자동 스크롤 호출 누락 / Misses 상위 앱 상태 전이와 실제 브라우저 CSS 스크롤바 렌더링.
  - **`<App />` 통합 심 (인메모리 `createInMemoryWikiApi` 하네스 + React Testing Library)**: Catches **Preview**·**위지윅**·**Raw** 세 **에디터 모드**에서 스크롤 및 **문서 목차** 항목 클릭 시 활성 헤딩 동기화 오류, 하단 짧은 섹션 클릭 직후 윗 헤딩으로 덮어써지는 회귀, **화면 분할 모드**에서 활성 **편집기 영역**·탭·**에디터 모드** 전환 시 목차 갱신 누락 / Misses 실제 Chromium 창의 픽셀 단위 플렉스·오버플로우 렌더링.
- *(위 심 목록은 사용자 승인을 거쳐 `/ticket-runner`의 사전 합의된 심(Pre-agreed Seams)으로 사용됩니다.)*
- 참고할 기존 테스트 패턴(Prior Art):
  - `MarkdownTocEngine` 순수 함수 단위 테스트 패턴
  - `GitSidebarPanel` 및 `DocumentOutlinePanel` 컴포넌트 테스트(내부 접기 제거 검증 포함)
  - `<App />` 통합 테스트의 인메모리 `WikiApi` 하네스 및 **에디터 모드** 전환·**화면 분할 모드**·**문서 목차** 클릭 스크롤 검증 패턴

## Out of Scope (범위 제외 사항)

- **왼쪽 사이드바**의 접기/펼치기 버튼 추가나 사이드바 토글 단축키 도입(기존 **액티비티 바** 활성 아이콘 재클릭 방식 유지)
- 문서 스크롤 변화 없이 에디터 커서 이동만으로 **문서 목차** 활성 헤딩을 변경하는 동작
- **화면 분할 모드**에서 비활성 **편집기 영역**을 스크롤할 때 **문서 목차**를 함께 바꾸는 동작(**문서 목차**는 항상 활성 **편집기 영역**만 반영)
- **문서 목차** 자동 스크롤 애니메이션 커스터마이징이나 사용자 설정 토글 추가

## Further Notes (기타 참고사항)

- **성능 고려**: 스크롤 이벤트는 고빈도로 발생하므로, 계산된 활성 헤딩 인덱스가 직전 값과 동일할 때는 상위 React 상태 갱신을 생략하여 불필요한 리렌더링을 방지합니다.
- **jsdom 테스트 환경 특성**: jsdom은 실제 레이아웃 엔진이 없어 `getBoundingClientRect`·`offsetTop` 등이 기본적으로 0을 반환하므로, 순수 판정 로직을 분리해 정밀 검증하고 통합 테스트에서는 스크롤 이벤트·레이아웃 스텁 또는 줄 번호/오프셋 경로를 통해 외부 관찰 상태(`aria-current="location"`) 전이를 검증합니다.
