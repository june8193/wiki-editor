# 02 — 워크스페이스 뷰 '새 창에서 열기' 버튼 및 새 메인 창 워크스페이스 초기화

**Spec:** [spec.md](../spec.md)

**What to build:** **워크스페이스 뷰**의 **즐겨찾기 워크스페이스** 및 **최근 워크스페이스** 목록 각 항목 행 우측에 `'새 창에서 열기'` 아이콘 버튼(`↗`)을 추가하고(현재 창의 활성 워크스페이스 행은 `disabled`), 클릭 시 원본 창 상태를 그대로 유지한 채 새 **메인 창**을 열어 지정된 워크스페이스의 이전 트리·탭 레이아웃(`workspace-state.json`)을 복원하고 **탐색기 뷰**로 진입하게 합니다.

**Blocked by:** 01-multi-main-window-session-coordinator-and-ipc

**Status:** resolved

- [x] **워크스페이스 뷰** 상단 현재 워크스페이스 카드는 기존 `'폴더 열기...'` 단일 버튼을 유지하고, **즐겨찾기 워크스페이스** 및 **최근 워크스페이스** 목록의 각 항목 행 우측에 `'새 창에서 열기'` 아이콘 버튼(`aria-label="{이름} 새 창에서 열기"`, `title="{이름} 새 창에서 열기"`)이 상시 렌더링됩니다(즐겨찾기 항목은 `'새 창에서 열기'` 버튼 우측에 `'즐겨찾기 해제'` `×` 버튼 배치).
- [x] 현재 창에 이미 열려 있는 활성 워크스페이스와 동일한 경로(`isSameWorkspacePath`)의 목록 행에서는 `'새 창에서 열기'` 버튼이 숨겨지지 않고 `disabled` 상태로 표시되어 다른 행들과 아이콘 열 정렬을 유지합니다.
- [x] 다른 워크스페이스 항목의 `'새 창에서 열기'` 버튼을 클릭하면 원본 창의 열린 워크스페이스, 편집 중인 미저장 **문서 버퍼**, 현재 **왼쪽 사이드바** 뷰(`워크스페이스 뷰`)가 초기화나 미저장 **확인 다이얼로그** 없이 그대로 유지됩니다.
- [x] 새로 열린 **메인 창**은 초기화 컨텍스트로 전달된 `initialWorkspacePath`를 우선 오픈하여(`recentWorkspaces[0]` 자동 복원 대신), 해당 워크스페이스의 저장된 **폴더 트리** 펼침(`expandedDirs`)과 **편집 공간** 탭·분할 레이아웃(`workspace-state.json`)을 복원하고 **왼쪽 사이드바**를 **탐색기 뷰**로 표시하며 `recentWorkspaces`를 갱신합니다.
- [x] 두 **메인 창**에서 각각 서로 다른 워크스페이스의 문서를 동시에 편집·저장하고 **보조 창**으로 탭을 분리할 때 각 워크스페이스 세션의 **문서 버퍼**·**폴더 트리**·**Git 패널** 상태가 서로 간섭 없이 독립 동작합니다.
- [x] 디스크에 존재하지 않거나 유효하지 않은 폴더 경로에 대해 `'새 창에서 열기'` 버튼을 클릭하면 새 창이 생성되지 않고 요청한 현재 창의 **오류 배너**에 즉시 오류 메시지가 표시됩니다.
- [x] 멀티윈도우 `<App />` 통합 테스트 심이 위 동작들을 검증하며, `npm run typecheck`, `npm test`, `npm run build`가 통과합니다.
