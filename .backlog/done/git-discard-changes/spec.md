# Spec: Git 패널 Changes 섹션 변경 사항 롤백 (Discard Changes)

## Problem Statement (문제 정의)

현재 **왼쪽 사이드바**의 **Git 뷰**에 위치한 **Git 패널**의 **Changes 섹션**은 워킹 트리의 변경 파일을 스테이지(`+` / `전체 +`)하거나 스테이지 해제(`-` / `전체 -`)하는 기능만 제공하며, 불필요한 로컬 수정본이나 새로 생성된 미추적 파일을 이전 상태로 되돌리는 롤백(변경 사항 취소) 기능을 제공하지 않습니다.

- 문서를 시험 삼아 수정하거나 실수로 삭제·편집했을 때 앱 안에서 즉시 복원할 수 없어 외부 Git 클라이언트나 터미널(`git restore`, `git checkout --`)을 별도로 열어야 합니다.
- 워킹 트리에 여러 수정 파일과 미추적(`?`) 파일이 섞여 있을 때 한 번의 확인으로 안전하게 정리(추적 파일 복원 + 미추적 파일 휴지통 이동)할 수단이 없습니다.
- 외부 터미널에서 강제로 워킹 트리를 되돌릴 경우 열린 **문서 버퍼**(특히 미저장 상태)나 **Diff 탭**과의 동기화를 사용자가 직접 챙겨야 합니다.

## Solution (해결 방안)

VS Code의 Source Control 변경 사항 취소 경험과 앱의 기존 UI 일관성을 결합하여 **Changes 섹션**의 `변경 사항` 목록에 개별 및 전체 롤백 기능을 추가합니다.

1. **`변경 사항` 섹션 전용 상시 롤백 버튼 (`↶` / `전체 ↶`)**:
   - **Changes 섹션**의 `변경 사항`(Unstaged + Untracked) 헤더에는 기존 `전체 +` 왼쪽에 `전체 ↶` 버튼을, 각 파일 행에는 기존 `+` 왼쪽에 `↶` 버튼을 나란히 상시 표시합니다.
   - `스테이지됨` 섹션에는 롤백 버튼을 두지 않으며, 스테이지된 변경을 버리려는 경우 먼저 Unstage(`-`)한 뒤 `변경 사항`에서 롤백합니다.
2. **파일 상태별 안전한 Git 복원 및 OS 휴지통 연동**:
   - **추적된 수정·삭제 파일 (`M`, `D`)**: Index 기준으로 워킹 트리를 복원하여 동일 파일에 이미 스테이지된 변경분이 있더라도 그대로 보존합니다(첫 커밋 전 `isUnborn` 저장소 포함).
   - **병합 충돌 파일 (`U`)**: 현재 브랜치(`HEAD` / `--ours`) 기준으로 Index와 워킹 트리를 강제 복원(현재 브랜치에 존재하지 않던 파일이면 제거)하여 충돌 상태를 즉시 해소합니다.
   - **미추적 파일 (`?`)**: 영구 삭제 대신 OS 휴지통(`trashItem`)으로 이동해 실수 시 복구 여지를 남깁니다.
3. **빠른 개별 실행 + 안전한 `'전체 롤백'` 위험 강조 확인 다이얼로그**:
   - 개별 파일의 `↶` 버튼은 별도 롤백 모달 없이 즉시 실행하여 빠른 편집 흐름을 유지합니다.
   - 헤더의 `전체 ↶` 버튼은 별도 분기 버튼 없이 항상 전체 항목(추적 복원 + 미추적 휴지통 이동)을 일괄 처리하되, 실행 전 위험 색상(`--danger-color` 빨간 버튼)이 적용된 **확인 다이얼로그**에서 추적 파일 개수(복구 불가 경고)와 미추적 파일 개수(휴지통 이동 안내)를 구분해 안내합니다.
4. **열린 문서 버퍼 · 보조 창 · Diff 탭 완전 동기화**:
   - 롤백 대상 파일에 미저장(`●`) **문서 버퍼**가 열려 있을 때만 기존 브랜치 전환/Pull과 동일하게 `'저장 후 진행'` / `'저장 없이 진행'` **확인 다이얼로그**를 거치며, 롤백 대상이 아닌 다른 문서의 미저장 편집본은 묻지도 건드리지도 않습니다.
   - 롤백이 완료되면 대상 **문서 버퍼**는(`'저장 없이 진행'` 선택 시에도 자동 저장 재덮어쓰기나 충돌 경고 없이) 복원된 디스크 내용으로 즉시 갱신되고, 디스크에서 삭제된 파일의 탭은 **메인 창**과 **보조 창**에서 자동으로 닫힙니다.
   - 롤백된 파일에 대해 열려 있던 `unstaged` **Diff 탭**은 자동으로 닫힙니다(`staged` 및 `commit` **Diff 탭**은 유지).

## User Stories (사용자 스토리)

1. As a 위키 작성자, I want **Changes 섹션**의 `변경 사항` 목록 각 파일 행에서 `+` 버튼 왼쪽의 `↶` 버튼을 눌러 수정되거나 삭제된 추적 파일(`M`, `D`)을 별도 확인 모달 없이 즉시 복원하기를 원하며, so that 불필요한 편집을 끊김 없이 빠르게 되돌릴 수 있습니다.
2. As a 위키 작성자, I want 하나의 파일에 스테이지된 변경과 추가 워킹 트리 수정이 함께 있을 때 `변경 사항`에서 롤백하면 스테이지된 내용은 보존되고 워킹 트리만 스테이지 상태로 복원되기를 원하며(`스테이지됨` 섹션에는 롤백 버튼 미노출), so that 커밋하려고 골라 둔 변경분을 실수로 잃지 않습니다.
3. As a 위키 작성자, I want `변경 사항` 목록의 미추적(`?`) 파일에서 `↶` 버튼을 누르면 해당 파일이 영구 삭제 대신 OS 휴지통으로 이동하기를 원하며, so that 새로 만든 초안 파일을 잘못 치웠더라도 OS 휴지통에서 되찾을 수 있습니다.
4. As a 위키 작성자, I want 병합 충돌(`U`) 상태인 파일에서 롤백을 실행하면 현재 브랜치(`--ours` / `HEAD`) 내용으로 강제 복원되어 충돌 상태가 해소되기를 원하며, so that 원격 병합 중 내 브랜치 버전을 유지하고 싶을 때 터미널 없이 즉시 정리할 수 있습니다.
5. As a 위키 작성자, I want `변경 사항` 헤더의 `전체 ↶` 버튼을 누르면 추적 파일 개수(복구 불가 안내)와 미추적 파일 개수(휴지통 이동 안내)가 구분 표시되고 위험 색상(`--danger-color`) 확인 버튼이 있는 단일 **확인 다이얼로그**가 뜨기를 원하며, 확인 시 모든 변경 사항이 일괄 롤백되고 취소 시 그대로 유지되기를 원하며, so that 대규모 작업 취소 전 영향 범위를 명확히 인지하고 실수를 방지할 수 있습니다.
6. As a 위키 작성자, I want 롤백하려는 파일이 에디터에 열려 있고 미저장(`●`) 변경 사항이 있을 때 기존 브랜치 전환/Pull처럼 `'저장 후 진행'` / `'저장 없이 진행'` 확인을 거치되, 롤백 대상이 아닌 다른 열린 문서의 미저장 변경은 방해받지 않기를 원하며, so that 작업 중인 다른 문서의 흐름을 끊지 않으면서 미저장 편집 유실을 통제할 수 있습니다.
7. As a 위키 작성자, I want 파일이 롤백되면 **메인 창**과 모든 **보조 창**에 열려 있는 해당 파일의 **문서 버퍼**가 복원된 디스크 내용으로 즉시 갱신(삭제된 파일이면 탭 자동 닫기)되고 **폴더 트리**와 **액티비티 바** 배지도 함께 갱신되기를 원하며, so that 롤백 직후 화면과 실제 디스크 상태가 항상 일치합니다.
8. As a 위키 작성자, I want 롤백한 파일의 `unstaged` **Diff 탭**이 **편집기 영역**에 열려 있으면 롤백 완료와 함께 자동으로 닫히고 `staged`나 과거 커밋(`commit`) **Diff 탭**은 그대로 유지되기를 원하며, so that 이미 사라진 워킹 트리 변경의 빈 **Diff 뷰어** 탭을 수동으로 닫지 않아도 됩니다.

## Implementation Decisions (구현 결정사항)

### 1. Git 롤백 IPC 및 서비스 계약
- **공유 Git API 확장 형태** (설계 확정 스키마):

  ```ts
  export interface WikiGitApi {
    // 기존 메서드 유지 ...
    discard: (workspacePath: string, paths: string[]) => Promise<GitStatus>
    discardAll: (workspacePath: string) => Promise<GitStatus>
  }
  ```

- **경로 보안 및 활성 워크스페이스 검증**:
  - IPC 계층은 요청된 `workspacePath`가 현재 열린 활성 워크스페이스 루트와 일치하는지 검증합니다.
  - Git 서비스는 전달된 모든 저장소 상대 경로에 대해 빈 문자열·NUL 바이트 차단, 저장소 루트 외부 탈출 차단, 현존 상위 디렉터리 실경로 기반 심볼릭 링크 탈출 차단, `.git` 메타데이터 세그먼트 차단을 강제합니다(워킹 트리에서 삭제된 `D` 파일도 상위 실경로 검증으로 안전하게 허용).
- **상태별 롤백 실행 규칙** (실행 시점의 최신 `GitStatus` 재조회 기준):
  - **추적 수정·삭제 (`M`, `D`)**: Index 기준으로 워킹 트리를 복원(`git checkout -f -- <paths>` 동등 동작)합니다. 동일 경로에 스테이지된 변경(`MM`, `AM`, `RM` 등)이 있어도 Index는 건드리지 않으며, 첫 커밋 전(`isUnborn`) 저장소에서 스테이지된 파일의 추가 수정·삭제도 Index 기준으로 정상 복원합니다.
  - **병합 충돌 (`U`)**: 현재 브랜치(`HEAD` / `--ours`) 기준으로 Index의 충돌 스테이지와 워킹 트리를 함께 정리합니다. `HEAD`에 존재하는 경로(`UU`, `AA`, `AU`, `UD` 등)는 `HEAD` 버전으로 Index·워킹 트리를 강제 복원하고, `HEAD`에 존재하지 않던 경로(`UA`, `DU`, `DD` 등)는 Index와 워킹 트리에서 제거하여 롤백 직후 `U` 상태가 남지 않게 합니다.
  - **미추적 (`?`)**: 주입된 `trashItem` 어댑터(프로덕션에서는 Electron `shell.trashItem`, 미주입 테스트 환경에서는 파일시스템 삭제 폴백)를 호출해 OS 휴지통으로 이동합니다. 심볼릭 링크 자체를 대상으로 처리해 링크 대상 원본을 따라가지 않으며, 이미 외부에서 삭제된 경로(`ENOENT`)는 멱등하게 무시합니다.
  - **이미 깨끗한 경로**: 최신 상태 조회 결과 `unstaged`·`untracked` 어느 쪽에도 없는 경로는 예외 없이 건너뛰고 최신 `GitStatus`를 반환합니다.
  - **`discardAll`**: 최신 상태의 모든 `unstaged`(`M`, `D`, `U`) 및 `untracked`(`?`) 항목을 수집해 동일한 분류 규칙으로 일괄 처리한 뒤 최신 `GitStatus`를 반환합니다.

### 2. Changes 섹션 UI 및 확인 다이얼로그 계약
- **버튼 배치 및 활성화 불변식**:
  - **Changes 섹션**의 `변경 사항` 헤더 우측 액션 영역에 `전체 ↶` 버튼(`aria-label` 및 `title`: `"전체 변경 사항 롤백"`, `변경 사항` 파일 수가 `0`이거나 `pendingAction !== null`일 때 비활성화)과 `전체 +` 버튼을 좌→우 순서로 상시 렌더링합니다.
  - `변경 사항` 각 파일 행 우측에 `↶` 버튼(`aria-label`: `"${file.path} 변경 사항 롤백"`, `title`: `"변경 사항 롤백"`, `pendingAction !== null`일 때 비활성화)과 `+` 버튼을 좌→우 순서로 상시 렌더링합니다.
  - 파일 행의 `↶` 또는 `+` 버튼 클릭은 파일명 버튼 클릭(**Diff 탭** 열기)과 완전히 분리됩니다.
  - `스테이지됨` 섹션 헤더 및 파일 행에는 롤백 버튼을 렌더링하지 않습니다.
- **확인 다이얼로그 위험 강조(`danger`) 톤 확장** (설계 확정 스키마):

  ```ts
  export type ConfirmDialogTone = 'primary' | 'danger'

  export interface ConfirmDialogState {
    title: string
    message: string
    confirmLabel: string
    confirmTone?: ConfirmDialogTone // 기본값 'primary'
    secondaryLabel?: string
    onConfirm: () => Promise<void> | void
    onSecondary?: () => Promise<void> | void
    onCancel?: () => void
  }
  ```

  - `confirmTone === 'danger'`일 때 확인 버튼에 테마의 `--danger-color` 배경·테두리와 대비 전경색을 적용한 위험 강조 스타일을 렌더링하며, 미지정(`'primary'`)일 때는 기존 기본 스타일을 그대로 유지합니다.
- **개별 롤백 vs `'전체 롤백'` 확인 흐름**:
  - **개별 파일 롤백 (`↶`)**: 별도의 롤백 **확인 다이얼로그**를 띄우지 않고 즉시 실행 흐름으로 진입합니다.
  - **`'전체 롤백'` (`전체 ↶`)**: 분기 버튼(`secondaryLabel`) 없이 취소 버튼과 단일 위험 강조(`confirmTone: 'danger'`) 확인 버튼(`전체 롤백`)만 가진 **확인 다이얼로그**를 항상 먼저 표시합니다. 안내 메시지는 현재 `변경 사항`의 추적 파일 수(`unstaged.length`, 충돌 `U` 포함)와 미추적 파일 수(`untracked.length`) 구성에 맞춰 구분 작성합니다:
    - 추적 파일만 있을 때: 추적 파일 개수와 복구 불가 안내 표시
    - 미추적 파일만 있을 때: 미추적 파일 개수와 휴지통 이동 안내 표시
    - 추적 파일과 미추적 파일이 함께 있을 때: 총 파일 수와 함께 추적 파일 복원 개수(복구 불가 안내) 및 미추적 파일 휴지통 이동 개수를 모두 명시

### 3. 열린 문서 버퍼 미저장 보호 · 강제 디스크 동기화 · Diff 탭 정리 규칙
- **대상 경로 한정 미저장(`●`) 확인**:
  - 개별 롤백(`paths`) 및 `'전체 롤백'`(전체 확인 승인 후 실제 실행 직전) 모두 **롤백 대상 경로 집합에 해당하는 열린 워크스페이스 문서 버퍼 중 미저장 상태(`isDirty` 또는 로컬 대기 편집 존재)가 하나 이상 있을 때만** 기존 브랜치 전환/Pull과 동일한 `'저장 후 진행'` / `'저장 없이 진행'` **확인 다이얼로그**를 표시합니다.
  - 롤백 대상에 포함되지 않은 다른 열린 워크스페이스 문서나 `config.json` 버퍼가 미저장 상태이더라도 프롬프트를 띄우거나 저장·폐기하지 않습니다.
  - 사용자가 `'저장 후 진행'`을 선택하면 해당 롤백 대상 미저장 버퍼들만 먼저 저장한 뒤(저장 실패 시 롤백 중단) Git 롤백을 실행합니다. `'취소'`를 선택하면 롤백을 중단합니다.
- **롤백 완료 후 대상 문서 버퍼 강제 동기화 불변식**:
  - `'저장 없이 진행'`을 선택해 대상 **문서 버퍼**가 메모리에 `isDirty: true`인 상태로 Git 롤백이 실행된 경우를 포함하여, 롤백된 대상 경로의 열린 **문서 버퍼**는 예약된 자동 저장 타이머와 대기 중인 편집 플러시를 즉시 해제하고 디스크 상태에 맞춰 강제 정합화합니다:
    - 롤백 후 디스크에 파일이 존재하면: `content`와 `savedContent`를 복원된 디스크 내용으로 교체하고 `isDirty: false`로 초기화(이미지 버퍼는 에셋 리비전 갱신)하여 **메인 창**과 모든 **보조 창**에 브로드캐스트하며, `"외부 변경과 미저장 편집 내용이 충돌할 수 있습니다"` 경고를 발생시키지 않습니다.
    - 롤백 후 디스크에서 파일이 제거되었으면(미추적 `?` 휴지통 이동 또는 `HEAD`에 없던 `U` 파일 제거): 미저장 여부와 무관하게 추가 닫기 확인이나 삭제 경고 없이 해당 **문서 버퍼**를 제거하고 **메인 창**과 모든 **보조 창**의 연결된 문서 탭을 닫습니다(열린 탭이 `0`개가 된 **보조 창**은 기존 창 수명주기 규칙에 따라 자동 종료).
  - 함께 **폴더 트리**와(커밋 그래프에 영향을 줄 수 있는 변경 시 또는 최신 상태 반영 시) Git 상태를 갱신합니다.
- **열린 `unstaged` Diff 탭 자동 닫기**:
  - 개별 파일 롤백이 성공하면 **주 편집기 영역**과 **보조 편집기 영역**에서 `request.kind === 'unstaged'`이고 대상 경로와 일치하는 **Diff 탭**을 자동으로 닫습니다.
  - `'전체 롤백'`이 성공하면 두 **편집기 영역**에 열려 있는 모든 `request.kind === 'unstaged'` **Diff 탭**을 자동으로 닫습니다.
  - `request.kind === 'staged'` 및 `request.kind === 'commit'` **Diff 탭**은 닫지 않고 유지하며, 분할 영역의 마지막 탭이 닫혀 한쪽 영역이 비면 기존 **편집기 영역** 규칙에 따라 자동으로 단일 화면 모드로 복귀합니다.
- **동시성 및 작업 잠금**:
  - 기존 Git 뮤테이션 직렬화 규칙과 동일하게 롤백 실행 중(`pendingAction !== null`)에는 중복 Git 액션 실행과 파일 감시 기반 중간 상태 덮어쓰기를 차단합니다.
- **도메인 용어집 동기화**:
  - 도메인 용어집(`CONTEXT.md`)의 **Changes 섹션**과 **확인 다이얼로그** 정의에 변경 사항 롤백 및 전체 롤백 확인 내용을 반영합니다.

## Testing Decisions (테스트 결정사항)

- **검증 기준**: 내부 구현 세부나 CSS 클래스가 아니라 접근 가능한 역할·이름(`getByRole`, `getByLabelText`)과 공개 서비스 인터페이스를 통해 사용자가 관찰하는 엔드투엔드 동작을 검증합니다. 모든 테스트는 인메모리 하네스, 임시 디렉터리, 주입형 `trashItem` 어댑터로 격리하여 실제 OS 휴지통이나 작업 저장소에 영향을 주지 않습니다.
- **사전 합의된 테스트 심 (Pre-agreed Seams)**:
  1. **`<App />` 멀티 윈도우 + 인메모리 `window.wikiApi` 통합 심 (`createMultiWindowWikiHarness` + React Testing Library)**
     - **Catches**: **Changes 섹션** `변경 사항`의 상시 `↶` / `전체 ↶` 버튼 배치 및 `스테이지됨` 미노출, 개별 파일 즉시 롤백과 `'전체 롤백'` 위험 색상(`danger`) **확인 다이얼로그**(추적·미추적 개수 구분 메시지 및 취소 방어), 롤백 대상에 미저장(`●`) **문서 버퍼**가 있을 때만 뜨는 `'저장 후 진행'` / `'저장 없이 진행'` 확인(비대상 미저장 문서 무간섭) 및 **메인 창**·**보조 창** 버퍼 강제 갱신·삭제 탭 자동 닫기(자동 저장 재덮어쓰기 및 충돌 경고 부재 포함), 롤백된 경로의 열린 `unstaged` **Diff 탭** 자동 닫기(`staged`·`commit` **Diff 탭** 유지), **폴더 트리**·**액티비티 바** 배지 갱신 회귀.
     - **Misses**: 실제 `git` CLI 서브프로세스 실행 및 Electron `shell.trashItem` 네이티브 OS 휴지통 호출.
  2. **Git 서비스 통합 심 (임시 디렉터리 기반 격리 실제 Git 저장소 + 주입형 `trashItem` 어댑터 / Vitest)**
     - **Catches**: 실제 `git` 바이너리에서의 추적 수정·삭제(`M`, `D`) 파일 Index 기준 워킹 트리 복원(동일 파일의 Staged 변경 보존 및 첫 커밋 전 `isUnborn` 저장소 포함), 병합 충돌(`U`: `UU`, `AA`, `DD`, `DU`, `UD`, `AU`, `UA`) 파일의 현재 브랜치(`HEAD`/`--ours`) 기준 강제 복원 및 충돌 해소, 미추적(`?`) 파일의 주입형 `trashItem` 호출(미주입 시 삭제 폴백), 개별(`discard`)·전체(`discardAll`) 실행 및 저장소 외부 경로·심볼릭 링크 탈출·`.git` 세그먼트 차단 오류.
     - **Misses**: Electron IPC 채널 바인딩과 렌더러 컴포넌트·다이얼로그 상태 전이.
  3. **Git IPC 핸들러 & Preload 브리지 경계 심 (가짜 `IpcMainLike` / `IpcRendererLike` / Vitest)**
     - **Catches**: 신규 롤백 IPC 채널(`git:discard`, `git:discard-all`)의 활성 워크스페이스 일치 검증·라우팅 누락 및 `window.wikiApi.git` 브리지 인자 매핑 불일치.
     - **Misses**: Git CLI 실행 세부 로직과 렌더러 UI 상호작용.
- *(위 심 목록은 `/ticket-runner`의 사전 합의된 심(Pre-agreed Seams)으로 사용됩니다.)*
- **참고할 기존 테스트 패턴 (Prior Art)**:
  - `<App />` 및 멀티 윈도우 통합 테스트의 `createMultiWindowWikiHarness` 패턴
  - 격리된 임시 저장소(`mkdtemp` + 로컬 `.gitconfig`)에서 실제 `git` 바이너리를 검증하는 Git 서비스 통합 테스트 패턴 및 `WorkspaceFsService`의 주입형 `trashItem` 테스트 패턴
  - 가짜 `IpcMainLike` / `IpcRendererLike` 기반 IPC 및 Preload 브리지 단위 테스트 패턴

## Out of Scope (범위 제외 사항)

- `스테이지됨` 섹션에서의 직접 롤백 버튼 제공 (스테이지된 파일은 Unstage(`-`) 후 `변경 사항`에서 롤백)
- **Diff 탭** 내부에서 특정 줄이나 헝크(Hunk) 단위로만 부분 롤백(Discard Hunk / Line)하는 기능
- `'전체 롤백'` 다이얼로그에서 `'추적된 파일만 취소'`와 `'전체 취소'`를 나누는 다중 분기 버튼
- 롤백 실행 후 앱 내부에서 자체 되돌리기(Undo 스택 또는 별도 백업 스냅샷) 제공 (미추적 파일만 OS 휴지통 복구 가능)
- 개별 파일 롤백 시 확인 다이얼로그 표시 여부를 토글하는 **전역 설정 패널** 옵션

## Further Notes (기타 참고사항)

- **하위 폴더 워크스페이스 호환성**: 열린 워크스페이스가 상위 Git 저장소의 하위 디렉터리인 경우에도 `GitStatus`의 저장소 루트 기준 상대 경로 검증과 `trashItem` 호출이 저장소 루트 경계 안에서 일관되게 동작해야 합니다.
- **자동 저장 경합 방지**: 미저장 상태의 열린 문서에 대해 사용자가 `'저장 없이 진행'`으로 롤백을 승인했을 때, 지연된 자동 저장 타이머나 진행 전 로컬 플러시가 복원된 디스크 파일을 다시 옛 편집본으로 덮어쓰지 않도록 버퍼 허브 수준에서 보장해야 합니다.
