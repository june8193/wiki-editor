# Spec: 문서 검색 기능 (워크스페이스 전체 검색 및 문서 내 찾기)

## Problem Statement (문제 정의)

현재 앱은 **폴더 트리**를 수동으로 펼쳐 파일을 찾거나 **문서 목차**·**링크 자동완성 메뉴**로 제한된 이동만 할 수 있을 뿐, 워크스페이스 전체 문서나 열려 있는 문서 본문에서 원하는 키워드를 검색하는 기능이 전혀 없습니다.

- 위키 문서가 늘어나면 특정 주제·용어·코드 조각이 어느 문서의 어느 위치에 적혀 있는지 일일이 파일을 열어 확인해야 합니다.
- 긴 문서를 `Raw` · `위지윅` · `Preview` · `Split` **에디터 모드**로 읽거나 편집할 때 `Ctrl+F`로 본문 내 키워드를 찾고 이동할 수 없습니다.
- 자동 저장이 기본 비활성(`autoSave: false`)인 환경에서 방금 작성 중인 미저장 **문서 버퍼**의 내용을 워크스페이스 차원에서 검색할 방법도 없습니다.

## Solution (해결 방안)

**액티비티 바**에 전용 **검색 뷰**(**검색 패널**)를 추가해 워크스페이스 전체의 파일명·경로 및 본문 내용을 통합 검색하고, **문서 편집기** 전 4개 **에디터 모드**에서 동작하는 플로팅 **문서 내 찾기 바**를 함께 제공합니다.

1. **전용 검색 뷰 및 워크스페이스 전체 텍스트 검색**: **액티비티 바**에 `검색` 아이콘(`탐색기` · `검색` · `Git` · `워크스페이스`)을 추가하고 `Ctrl+Shift+F`로 즉시 진입합니다. 이미지·바이너리·대용량 파일·시스템 폴더를 제외한 워크스페이스 내 모든 텍스트 파일의 파일명·경로와 본문을 검색하며, 현재 **메인 창** 세션(소속 **보조 창** 포함)의 미저장 열린 **문서 버퍼**를 디스크보다 우선 반영합니다.
2. **파일별 통합 결과 및 모드 유지 위치 이동**: 파일명·경로 일치와 본문 일치를 파일별 접기/펼치기 그룹으로 통합 표시하고(파일명 일치 시 헤더 강조 및 상위 우선 정렬), 본문 일치 줄을 클릭하면 활성 **편집기 영역**에서 해당 문서를 열거나 활성화한 뒤 **현재 에디터 모드를 유지**한 채(찾기 바를 자동으로 열지 않고) 해당 위치로 스크롤·임시 강조합니다.
3. **4개 에디터 모드 공통 문서 내 찾기 바**: **에디터 헤더**의 찾기(`🔍`) 버튼과 `Ctrl+F`로 **문서 편집기** 우상단에 플로팅 **문서 내 찾기 바**를 띄웁니다. `Raw` · `위지윅` · `Preview` · `Split` 모든 **에디터 모드**와 **메인 창**·**보조 창**을 지원하며(`Diff 탭`·이미지 탭 제외), **편집기 영역** 단위로 열림 상태와 검색어를 유지해 다른 텍스트 탭이나 모드로 전환해도 즉시 재검색합니다.
4. **일관된 매칭 옵션 및 안전 가드레일**: **검색 뷰**와 **문서 내 찾기 바** 모두 기본 대소문자 무시 부분 일치와 `Aa`(대소문자 구분) · `ab`(단어 단위) · `.*`(정규식) 3종 토글을 동일하게 제공하며, 잘못된 정규식 인라인 안내·빈 매치 무한 루프 방어·결과 상한 절단·후속 검색 시 이전 스캔 취소로 안정적인 반응성을 보장합니다.

## User Stories (사용자 스토리)

1. As a 위키 작성자, I want **액티비티 바**의 `검색` 아이콘을 클릭하거나 `Ctrl+Shift+F`를 눌러 **왼쪽 사이드바**에 **검색 뷰**를 열고 입력창에 즉시 포커스되기를 원하며, so that 현재 편집 중인 문서를 가리지 않고 왼쪽에서 워크스페이스 전체를 검색할 수 있습니다.
2. As a 위키 작성자, I want 워크스페이스 전체 검색이 `.git`·`node_modules` 등 시스템 폴더와 이미지·바이너리·대용량 파일을 제외하고 마크다운뿐 아니라 `.txt`, `.json`, 확장자 없는 문서 등 모든 텍스트 파일의 파일명·경로와 본문을 함께 찾아 주기를 원하며, so that 워크스페이스 안의 텍스트 문서를 빠짐없이 찾을 수 있습니다.
3. As a 위키 작성자, I want 아직 저장하지 않고 **메인 창** 또는 소속 **보조 창**에서 편집 중인 문서의 최신 내용도 워크스페이스 검색에 즉시 반영되기를 원하며, so that 방금 작성한 내용도 검색할 수 있고 결과 줄 번호가 편집기와 어긋나지 않습니다.
4. As a 위키 작성자, I want 검색어를 타이핑하면 한글 IME 조합을 방해하지 않고 잠시 뒤(`200ms` 디바운스) 자동으로 검색되고 `Enter`나 상단 새로고침 버튼으로 즉시 재실행할 수 있기를 원하며, so that 문서 편집 중 목록이 흔들리지 않으면서도 빠르게 결과를 확인할 수 있습니다.
5. As a 위키 작성자, I want 검색 결과가 파일별 통합 그룹(접기/펼치기)으로 정리되어 파일명·경로가 일치한 파일은 헤더가 강조되면서 상단에 우선 표시되고, 그 아래에 본문 일치 줄 번호와 일치 구간이 강조된 스니펫이 표시되기를 원하며, so that 같은 파일이 중복되지 않고 원하는 문서와 문맥을 한눈에 파악할 수 있습니다.
6. As a 위키 작성자, I want **검색 뷰**에서 파일명 일치 항목이나 본문 일치 줄을 클릭하면 활성 **편집기 영역**에서 해당 문서가 열리거나 기존 탭이 활성화되고, 본문 일치 줄 클릭 시 현재 **에디터 모드**를 유지한 채(찾기 바를 자동으로 띄우지 않고) 해당 위치로 스크롤·강조되기를 원하며, so that `Raw`, `위지윅`, `Preview`, `Split` 어느 모드로 작업 중이든 흐름이 끊기지 않고 바로 해당 지점을 확인할 수 있습니다.
7. As a 위키 작성자, I want **검색 뷰**와 **문서 내 찾기 바** 모두에서 `Aa`(대소문자 구분) · `ab`(단어 단위) · `.*`(정규식) 옵션을 전환할 수 있고 잘못된 정규식을 입력해도 앱 오류 없이 인라인 안내만 표시되기를 원하며, so that 단순 키워드 검색부터 정밀 패턴 검색까지 안전하게 수행할 수 있습니다.
8. As a 위키 작성자, I want **에디터 헤더**의 찾기(`🔍`) 버튼을 클릭하거나 `Ctrl+F`(텍스트 선택 상태면 선택 텍스트 자동 채움)를 눌러 현재 문서에서 키워드를 찾고 `n / m` 매치 수 확인과 `Enter`/`Shift+Enter`(`F3`/`Shift+F3`) 순환 이동, `Esc` 닫기를 사용할 수 있기를 원하며, so that 단축키와 마우스 어느 쪽으로든 문서 내 검색을 빠르게 수행할 수 있습니다.
9. As a 위키 작성자, I want 문서 내 찾기가 `Raw` · `위지윅` · `Preview` · `Split` 4개 **에디터 모드** 모두에서 동작하고(`Split`에서는 `Raw` 기준 탐색과 우측 `Preview` 동시 강조·줄 동기화 스크롤), **메인 창**과 **보조 창** 모두에서 일관되게 동작하기를 원하며, so that 읽기·편집·분할·다중 창 환경 어디서나 문서 내 검색을 쓸 수 있습니다.
10. As a 위키 작성자, I want 같은 **편집기 영역**에서 다른 텍스트 탭으로 전환하거나 **에디터 모드**를 바꿔도 **문서 내 찾기 바**와 검색어가 유지되어 즉시 새 탭·새 모드에서 재검색되고, **Diff 탭**이나 이미지 탭에서는 찾기 바가 잠시 숨겨지고 헤더 버튼이 비활성화되기를 원하며, so that 여러 문서를 번갈아 보며 같은 키워드를 확인할 때 매번 검색어를 다시 입력하지 않아도 됩니다.
11. As a 위키 작성자, I want **왼쪽 사이드바**에서 다른 뷰로 전환하거나 접었다가 다시 **검색 뷰**로 돌아와도 직전 검색어·옵션·결과가 유지되고, 다른 워크스페이스로 전환하면 검색 상태가 깨끗하게 초기화되기를 원하며, so that 현재 워크스페이스 탐색 문맥을 잃지 않으면서 다른 프로젝트와 결과가 섞이지 않습니다.

## Implementation Decisions (구현 결정사항)

### 확정된 핵심 계약 형태 (설계 인터뷰 확정 계약)

```ts
export interface SearchMatchOptions {
  caseSensitive: boolean
  wholeWord: boolean
  useRegex: boolean
}

export interface TextMatchSpan {
  start: number // UTF-16 code unit offset (inclusive)
  end: number   // UTF-16 code unit offset (exclusive)
}

export interface WorkspaceSearchRequest {
  query: string
  options: SearchMatchOptions
  maxTotalMatches?: number   // 기본 1000
  maxMatchesPerFile?: number // 기본 100
}

export interface WorkspaceSearchLineMatch {
  lineNumber: number         // 1-based line number
  lineText: string           // 표시용 스니펫 문자열
  lineOffset: number         // 원본 줄 시작 대비 lineText 시작 오프셋 (원본 컬럼 = lineOffset + span.start)
  matches: TextMatchSpan[]   // lineText 기준 일치 구간 목록
}

export interface WorkspaceSearchFileResult {
  path: string
  relativePath: string
  name: string
  nameMatches: TextMatchSpan[] // relativePath 기준 파일명·경로 일치 구간
  lineMatches: WorkspaceSearchLineMatch[]
  totalMatchCount: number      // 해당 파일의 전체 본문 일치 수 (상한 절단 전)
  truncatedInFile: boolean
}

export interface WorkspaceSearchResponse {
  query: string
  files: WorkspaceSearchFileResult[]
  totalFileCount: number
  totalMatchCount: number
  truncated: boolean
  error?: string               // 잘못된 정규식 등 검색식 오류
}

export interface DocumentSearchJumpRequest {
  paneId: PaneId
  tabId: string
  query: string
  options: SearchMatchOptions
  lineNumber: number           // 1-based
  columnStart: number          // 0-based UTF-16 offset within line
  columnEnd: number            // 0-based UTF-16 offset within line
  nonce: number
}
```

### 아키텍처 및 전이 규칙

- **공용 텍스트 매칭 엔진**:
  - 메인 프로세스 워크스페이스 검색과 렌더러 **문서 내 찾기 바**가 동일한 검색 매칭 규칙(`SearchMatchOptions`)을 공유합니다.
  - 기본 모드는 대소문자 무시 부분 일치이며, 1글자 이상의 검색어를 지원합니다.
  - `ab`(단어 단위) 옵션은 영문·숫자뿐 아니라 한글·유니코드 문자(`[\p{L}\p{N}_]`) 경계를 올바르게 판별하여 부분 단어 오매칭을 방지합니다.
  - `.*`(정규식) 옵션에서 문법 오류가 발생하면 예외를 던지지 않고 구조화된 `error` 메시지를 반환하며, 빈 문자열을 일치시키는 정규식(`.*`, `^`, `a*` 등)은 `lastIndex`를 안전하게 전진시켜 무한 루프를 원천 차단합니다.
- **메인 프로세스 워크스페이스 검색 서비스 및 세션 격리**:
  - 각 **메인 창** 세션은 자신의 워크스페이스 파일시스템과 세션 공유 **문서 버퍼** 허브를 조합해 워크스페이스 검색을 수행합니다(다른 **메인 창** 세션과 완전 격리).
  - 파일 탐색은 기존 무시 목록(`.git`, `node_modules`, `.hg`, `.svn`, `.DS_Store`, `Thumbs.db`), 워크스페이스 루트 밖 탈출·순환 심볼릭 링크 차단 규칙을 동일하게 적용합니다.
  - 대상 파일은 모든 텍스트 파일이며, 지원 이미지 확장자·알려진 바이너리 확장자·선두 8KB 내 널 바이트(`\0`) 포함 파일·크기 `2MB` 초과 파일은 본문 검색에서 제외합니다.
  - 현재 세션의 공유 **문서 버퍼** 허브에 열려 있는 워크스페이스 텍스트 문서(메인 창 및 소속 **보조 창**의 미저장 편집분 포함)는 디스크 파일 대신 메모리 최신 본문으로 검색하며, 전역 `config.json` 버퍼는 워크스페이스 검색에서 제외합니다.
  - 파일명·경로 일치(`nameMatches`)가 있는 파일은 결과 상단에 우선 정렬하고(동일 우선순위 내 `relativePath` 오름차순), 파일당 본문 일치 표시 상한(기본 `100`건)과 전체 본문 일치 상한(기본 `1,000`건) 초과 시 `truncated` / `truncatedInFile` 플래그를 설정합니다.
  - 긴 줄은 첫 번째 일치 지점 주변의 읽기 쉬운 스니펫(`lineText`)과 원본 줄 시작 기준 `lineOffset`으로 잘라 반환하여 IPC 페이로드와 렌더링 부하를 제한합니다.
  - 동일 세션에서 새 검색 요청이 도착하면 직전 미완료 스캔의 `AbortSignal`을 취소하여 오래된 결과가 최신 결과를 덮어쓰지 않도록 보장합니다.
- **액티비티 바 · 검색 뷰 · 검색 패널 UI**:
  - **액티비티 바** 순서를 `탐색기` · `검색` · `Git` · `워크스페이스`로 확장합니다.
  - `Ctrl+Shift+F` 실행 시 **왼쪽 사이드바**가 접혀 있거나 다른 뷰를 표시 중이면 **검색 뷰**로 전환·펼침하고 검색 입력창에 포커스하며, 이미 입력된 검색어가 있으면 전체 선택합니다. 모달(**확인 다이얼로그**, **전역 설정 패널**)이 열려 있을 때는 억제하고, **보조 창**에서는 무시합니다.
  - **애플리케이션 메뉴 바**는 기존 `File`, `Settings`, `Help` 3개 구성을 그대로 유지합니다.
  - 입력 변경 시 `200ms` 디바운스 자동 검색을 수행하고, 한글 등 IME 조합(`isComposing`) 중에는 조합 완료 시점까지 검색을 지연하며, `Enter` 키 또는 상단 `새로고침` 버튼 클릭으로 즉시 재검색합니다. 문서 편집 중 목록 흔들림을 막기 위해 편집/파일 변경 시 자동 재검색은 하지 않습니다.
  - 결과 목록은 파일별 통합 접기/펼치기 그룹으로 렌더링하며(파일당 일치 수 배지, 파일명·경로 일치 시 헤더 하이라이트, 하위에 1-기반 줄 번호와 일치 구간이 강조된 스니펫), 본문 일치 없이 파일명만 일치한 파일은 헤더 클릭으로 바로 엽니다.
  - **검색 뷰** 상태(검색어, 옵션, 결과, 접힘 상태)는 다른 사이드바 뷰 전환·접기 시 메모리에 유지하고, 워크스페이스 전환 시 초기화하며, 디스크 `workspace-state.json`에는 저장하지 않습니다.
- **문서 내 찾기 바 및 에디터 헤더 진입**:
  - **에디터 헤더**에 찾기(`🔍`, 툴팁 `"문서 내 찾기 (Ctrl+F)"`) 버튼을 추가합니다(이미지 미리보기 탭에서는 비활성화).
  - **문서 편집기** 및 전역 단축키에서 `Ctrl+F` 실행 시 현재 활성 **편집기 영역**의 활성 탭이 텍스트 문서라면 **문서 내 찾기 바**를 열고 검색 입력창에 포커스합니다. 에디터에 단일 줄 텍스트가 선택되어 있으면 해당 선택 텍스트로 검색어를 자동 채우며, 이미 열려 있고 선택 텍스트가 없으면 입력창 포커스 및 전체 선택만 수행합니다.
  - 찾기 바는 **문서 편집기** 우상단에 플로팅 형태로 배치되며 검색 입력창, `Aa` · `ab` · `.*` 옵션 토글, 매치 카운트(`n / m` 또는 `결과 없음`), 이전(`Shift+Enter` / `Shift+F3` / 버튼)·다음(`Enter` / `F3` / 버튼)·닫기(`Esc` / 버튼), 정규식 오류 인라인 안내를 제공합니다.
  - 찾기 바 상태(`isOpen`, `query`, `options`)는 **편집기 영역(Pane)** 단위로 관리하여 같은 영역 내에서 다른 텍스트 탭으로 전환하거나 **에디터 모드**를 변경해도 열림 상태와 검색어를 유지한 채 즉시 재검색합니다. **Diff 탭**이나 이미지 미리보기 탭이 활성화되면 찾기 바를 일시 숨기고(`Ctrl+F` 억제), 텍스트 탭으로 돌아오면 다시 표시합니다. **메인 창**과 **보조 창** 모두 동일하게 동작합니다.
  - **4개 에디터 모드별 문서 내 찾기 구현 원칙**:
    - `Raw`: CodeMirror 6 상태 필드 및 마크 데코레이션으로 전체 일치 및 현재 활성 일치를 강조하고, 활성 일치 변경 시 뷰포트 중앙으로 스크롤합니다(외부 패키지 추가 없이 공용 매칭 엔진 사용).
    - `Split`: 좌측 `Raw` 편집기를 매치 목록·카운트(`n / m`)·탐색 기준으로 삼고, 우측 `Preview`에도 동일 검색어·옵션의 일치 하이라이트를 동시 적용하며 `Raw` 이동 시 기존 줄 동기화 스크롤과 연동합니다.
    - `위지윅`: TipTap/ProseMirror 문서 텍스트 노드를 순회하는 플러그인 데코레이션으로 본문·헤딩·목록·표·코드 블록 내 전체 일치와 활성 일치를 강조하고, 활성 일치 DOM 위치로 스크롤합니다.
    - `Preview`: 렌더링된 마크다운 DOM 텍스트 노드에 일치 강조 마크를 적용하되 코드 블록 헤더(`코드 복사` 버튼·언어 배지)와 **Mermaid 다이어그램 블록** 내부 `<svg>`·액션 바 등 UI 크롬은 검색·강조 대상에서 제외합니다.
- **검색 뷰 본문 일치 클릭 시 모드 유지 위치 이동**:
  - **검색 뷰**에서 파일의 본문 일치 줄을 클릭하면 활성 **편집기 영역**에 해당 파일을 열거나 기존 탭을 활성화한 뒤 `DocumentSearchJumpRequest`를 전달합니다. 이때 현재 **에디터 모드**는 변경하지 않고 **문서 내 찾기 바**도 자동으로 열지 않습니다.
  - `Raw` / `Split`: 요청된 `(lineNumber, columnStart, columnEnd)`로 커서·선택 위치를 정확히 이동하고 일치 구간을 임시 강조(다음 사용자 편집·모드 전환·새 점프 시 해제)하며 뷰포트로 스크롤합니다(`Split` 우측 `Preview`도 동기화 스크롤).
  - `위지윅` / `Preview`: `data-source-line` 블록 범위 및 문맥 텍스트 위치 매칭으로 해당 일치 구간을 찾아 스크롤·임시 강조합니다. 마크다운 기호(`**`, `##`)나 링크 URL처럼 렌더링 결과에 직접 보이지 않는 원문만 일치한 경우, 해당 원문 줄에 대응하는 가장 가까운 블록으로 안전하게 폴백 스크롤합니다.
  - 비동기 파일 열기 도중 다른 검색 결과를 클릭하거나 워크스페이스가 전환되면 요청 시퀀스 검증으로 이전 점프 요청을 폐기합니다.
- **도메인 용어집 동기화 (`CONTEXT.md`)**:
  - **검색 뷰 (Search View)**, **검색 패널 (Search Panel)**, **문서 내 찾기 바 (Find Bar)**를 공식 용어로 등록하고, **액티비티 바**, **왼쪽 사이드바**, **에디터 헤더**, **문서 편집기**, **보조 창** 설명에 검색 기능 연동 내용을 반영합니다.

## Further Notes (기타 참고사항)

- **보안 및 격리**: 워크스페이스 검색은 기존 경로 보안 불변식(워크스페이스 루트 내부 제한, 탈출 심볼릭 링크 및 시스템 폴더 차단)과 다중 **메인 창** 세션 격리를 반드시 유지합니다. 정규식 검색 시 과도한 결과나 빈 매치 패턴으로 UI/메인 프로세스가 멈추지 않도록 결과 상한과 안전 전진 규칙을 적용합니다.
- **성능 및 반응성**: 워크스페이스 파일 읽기는 동시성 제한(예: 제한된 워커 풀)과 `AbortSignal` 취소로 메인 프로세스 이벤트 루프 블로킹을 방지하고, 대용량 파일(`2MB` 초과)과 바이너리 파일은 선두 검사 단계에서 조기 스킵합니다.
- **개발 원칙**: `GEMINI.md`의 Red-Green-Refactor TDD 규칙과 테스트 격리 원칙을 준수하며, 티켓 완료 시 `npm run typecheck`, `npm test`, `npm run build`를 모두 검증합니다.
