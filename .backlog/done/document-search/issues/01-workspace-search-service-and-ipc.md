# 01 — 공용 텍스트 검색 엔진 및 메인 프로세스 워크스페이스 검색 서비스·IPC

**Spec:** [spec.md](../spec.md)

**What to build:** 메인 프로세스와 렌더러가 공유하는 텍스트 검색 매칭 엔진(`Aa` 대소문자 구분 · `ab` 단어 단위 · `.*` 정규식, 잘못된 정규식 오류 반환 및 빈 매치 무한 루프 방어)과 메인 프로세스 세션 단위 워크스페이스 전체 검색 서비스·IPC·프리로드 브리지를 구축합니다. 워크스페이스 내 모든 텍스트 파일의 파일명·경로와 본문을 안전하게 검색하고 현재 **메인 창** 세션의 미저장 열린 **문서 버퍼**를 디스크보다 우선 반영하며, 결과 상한·스니펫 오프셋 계산·후속 요청 시 이전 스캔 취소까지 엔드투엔드로 동작하게 만듭니다.

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 공용 텍스트 매칭 엔진이 기본 대소문자 무시 부분 일치와 `Aa`(대소문자 구분) · `ab`(영문·숫자·한글 유니코드 단어 경계) · `.*`(정규식) 옵션을 지원하며, 1글자 이상 검색어에서 정확한 UTF-16 `TextMatchSpan` 목록을 반환합니다.
- [x] 잘못된 정규식 입력 시 예외를 던지지 않고 구조화된 `error` 메시지를 반환하며, 빈 문자열에 일치하는 정규식(`.*`, `^`, `a*` 등)에서도 무한 루프 없이 안전하게 종료합니다.
- [x] 워크스페이스 검색 서비스가 `.git`, `node_modules`, `.hg`, `.svn`, `.DS_Store`, `Thumbs.db` 및 워크스페이스 밖 탈출·순환 심볼릭 링크를 제외하고 모든 텍스트 파일의 파일명·경로(`nameMatches`)와 본문(`lineMatches`)을 재귀 검색합니다.
- [x] 지원 이미지 확장자, 알려진 바이너리 확장자, 선두 8KB 내 널 바이트(`\0`) 포함 바이너리 파일, 크기 `2MB` 초과 파일은 본문 검색에서 안전하게 제외합니다.
- [x] 현재 **메인 창** 세션의 공유 **문서 버퍼** 허브에 열려 있는 워크스페이스 텍스트 문서(소속 **보조 창** 미저장 편집분 포함)는 디스크 내용 대신 메모리 최신 본문으로 검색하며, 전역 `config.json` 버퍼는 워크스페이스 검색 대상에서 제외합니다.
- [x] 파일명·경로가 일치한 파일이 결과 상단에 우선 정렬되고(동일 우선순위 내 `relativePath` 오름차순), 긴 줄은 첫 일치 지점 주변 스니펫(`lineText`)과 정확한 `lineOffset`(원본 컬럼 = `lineOffset + span.start`)으로 반환합니다.
- [x] 파일당 본문 일치 상한(기본 `100`건)과 전체 본문 일치 상한(기본 `1,000`건) 초과 시 결과를 안전하게 절단하고 `truncatedInFile` / `truncated` 플래그를 설정하며, 동일 세션에 후속 검색 요청이 들어오면 이전 미완료 스캔을 취소합니다.
- [x] 다중 **메인 창** 환경에서 워크스페이스 검색 IPC 호출이 호출자 세션의 워크스페이스 및 **문서 버퍼** 허브로 격리 라우팅되고 프리로드 브리지를 통해 노출됩니다.
- [x] 메인 프로세스 워크스페이스 검색 서비스 · 세션 IPC 통합 테스트 심이 위 동작들을 검증하며, `npm run typecheck`, `npm test`, `npm run build`가 통과합니다.
