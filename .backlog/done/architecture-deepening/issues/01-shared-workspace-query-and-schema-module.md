# 01 — 검색 패널·프론트매터 스키마 통합 @shared 모듈 및 스토리지 어댑터 전환

**Spec:** [spec.md](../spec.md)

**What to build:** **검색 패널** 쿼리(텍스트/정규식·프론트매터 조건·정렬)·`allowCustom` `multi-select` 필드값 수집·**프론트매터 스키마** 상태 머신을 좁은 스토리지 **심(seam)** 위의 단일 `@shared` 깊은 **모듈**로 통합하고, 메인 프로세스(디스크 **어댑터**)와 인메모리 테스트 하네스(인메모리 **어댑터**)가 동일한 구현을 공유하도록 전환하여 하네스 중복 330줄과 `@shared`에 유출된 루프 헬퍼를 제거합니다.

**Blocked by:** None — can start immediately

**Status:** resolved

- [ ] `@shared` 통합 **모듈**이 **프론트매터 스키마** 수명주기(읽기·엄격 검증·기본 템플릿 생성·저장·직렬화 비동기 큐·`missing`/`valid`/`error` 핑거프린트·변경 브로드캐스트), 워크스페이스 문서 스캔, 텍스트/프론트매터 조건 검색 및 정렬, `allowCustom` 필드값 수집을 좁은 스토리지 **심(seam)**(워크스페이스 루트/변경 구독·대상 파일 열거·문서 텍스트 읽기·선택적 realpath 해석·스키마 raw 읽기/쓰기/감시) 뒤의 단일 구현으로 제공합니다.
- [ ] 새 `@shared` **모듈**이 공유 **문서 버퍼** 허브와 직접 연동하여 스캔 시 미저장 **문서 버퍼**(바이너리·`2MB` 초과·`config.json` 제외)를 디스크보다 우선 오버레이하고, 스키마 저장 또는 외부 변경 감지 시 열려 있는 깨끗한(clean) `.wiki-editor/frontmatter.json` **문서 버퍼**를 자동 갱신합니다.
- [ ] 검색(`search`)과 필드값 수집(`collectFieldValues`)이 서로를 취소하지 않는 독립 single-flight `AbortSignal` 레인을 유지하되, 워크스페이스 전환이나 `dispose` 시에는 두 레인이 모두 일괄 취소됩니다.
- [ ] 메인 디스크 **어댑터**가 기존 심볼릭 링크/경로 탈출 차단 보안, 임시 파일 기반 원자적 쓰기, `fsWatch` 디바운스 감시, 제한된 동시성을 100% 보존하며 다중 **메인 창** 세션 격리 IPC 라우팅이 동일하게 동작합니다.
- [ ] 인메모리 테스트 하네스가 자체 검색·필드값 수집·스키마 상태 머신 중복 구현(약 330줄)을 삭제하고 인메모리 스토리지 **어댑터**를 통해 실제 `@shared` **모듈**을 실행하므로, 메인과 하네스 간 스키마 오류 처리·정렬·스캔 동작 불일치가 사라집니다.
- [ ] 기존에 하네스 공유 목적으로 `@shared`에 노출되었던 루프 내부 헬퍼(`WorkspaceSearchAccumulator`, `commitSearchCandidateSlot`, `createFrontmatterFieldValuesCollector`)를 새 깊은 **모듈** 내부로 비공개화하고 얕은 헬퍼 단위 테스트는 삭제하며, 새 `@shared` **모듈** **인터페이스** 테스트·메인 디스크 **어댑터**/IPC 통합 테스트·`<App />` 검색/프론트매터 통합 테스트 및 `npm run typecheck`, `npm test`, `npm run build`가 모두 통과합니다.
