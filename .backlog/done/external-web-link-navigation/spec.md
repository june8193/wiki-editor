# Spec: 마크다운 외부 웹 링크 기본 브라우저 이동 및 입력·자동링크 지원

## Problem Statement (문제 정의)

마크다운 문서에는 공식 문서·저장소·레퍼런스 등을 가리키는 `http://` · `https://` 일반 웹 링크가 자주 포함되지만, 현재 Wiki Editor에서는 다음과 같은 불편이 있습니다.

- **전 에디터 모드 외부 웹 링크 무동작**: **위지윅**·**Preview**·**Split**·**Raw** 모든 **에디터 모드**에서 `http://` · `https://` 웹 링크를 클릭(또는 **Raw** `Ctrl+클릭`)해도 Electron 창 내비게이션 가드와 링크 네비게이션 훅의 외부 링크 조기 반환으로 인해 OS 기본 브라우저가 열리지 않습니다.
- **메인 창·보조 창 공통 외부 URL 실행 경로 부재**: 기존 `shell.openExternal` IPC가 **터미널 패널** 전용(**메인 창** 한정)으로만 연결되어 있어 **보조 창**에 분리된 문서 탭을 포함한 마크다운 **문서 편집기** 전반에서 사용할 수 없습니다.
- **위지윅 모드 직접 타이핑 미변환**: **위지윅** 모드에서 `[텍스트](https://...)`를 직접 타이핑하거나 `Ctrl+K` 후 외부 URL을 입력해 닫는 `)`를 쳐도 클릭 가능한 링크 마크로 변환되지 않고 일반 텍스트로 이스케이프되어 저장됩니다.
- **Raw 모드 자동링크 및 맨 URL `Ctrl+클릭` 미지원**: **Raw** 모드에서는 `[텍스트](URL)` 형태만 링크로 인식하므로, GFM에서 유효한 `<https://...>` 자동링크나 본문에 그대로 적은 `https://...` 맨 URL을 `Ctrl+클릭`해도 반응하지 않습니다.

## Solution (해결 방안)

공유 외부 HTTP(S) URL 검증과 **메인 창**·**보조 창** 공통 `shell` 외부 URL 열기 IPC를 도입하여, 기존 **문서 목차**·`#섹션` 앵커·상대 경로 마크다운 파일 이동 및 **링크 자동완성 메뉴**와 충돌 없이 모든 마크다운 **에디터 모드**에서 일반 웹 링크를 자연스럽게 작성하고 OS 기본 브라우저로 열 수 있게 합니다.

1. **전 에디터 모드·전 창 외부 웹 링크 브라우저 열기**:
   - **위지윅**·**Preview**·**Split** 모드에서는 일반 클릭(및 `Ctrl/Cmd+클릭`)으로, **Raw** 모드에서는 `Ctrl+클릭`(`Cmd+클릭`)으로 유효한 `http://` · `https://` 웹 링크를 별도 확인 다이얼로그 없이 OS 기본 브라우저(`shell.openExternal`)로 즉시 엽니다.
   - **메인 창**과 **보조 창** 모두 동일하게 동작하며, **터미널 패널**의 외부 URL 검증 로직도 동일한 공유 검증 유틸로 통합합니다.
2. **엄격한 스킴 분리 및 오류 안내**:
   - `http://` · `https://`만 OS 기본 브라우저로 실행하며, 잘못된 형식의 `http(s)` URL(예: `https://`)이나 브라우저 실행 실패 시 상단 **오류 배너**로 안내합니다.
   - `mailto:` 링크는 오류 배너 없이 무동작(no-op)으로 유지하고, `javascript:` · `file:` · `ftp:` 등 비허용 스킴은 기존처럼 차단합니다.
3. **위지윅 `[텍스트](URL)` 즉시 변환 및 Raw 자동링크·맨 URL `Ctrl+클릭`**:
   - **위지윅** 모드에서 `[텍스트](URL)` 입력 후 닫는 `)`를 타이핑하는 즉시 안전한 링크 마크로 변환합니다(코드 블록·인라인 코드·이미지 `![alt](...)`·빈 라벨 `[]()` 제외).
   - **Raw** 모드에서 기존 `[텍스트](URL)` 외에 `<https://...>`와 맨 URL(`http://...`, `https://...`) 위에서의 `Ctrl+클릭`도 지원합니다(코드 펜스·인라인 코드·이미지 `![alt](src)` 내부 제외).
4. **사용자 매뉴얼 동기화**:
   - 사용자 매뉴얼(`docs/manual.md`)의 단축키 표와 마크다운 링크 안내에 일반 웹 링크(`http`/`https`) 기본 브라우저 이동 동작을 반영합니다.

## User Stories (사용자 스토리)

1. As a 위키 독자 및 작성자, I want **위지윅**·**Preview**·**Split** 모드에서 일반 웹 링크(`http://`, `https://`)를 클릭했을 때 확인 창 없이 OS 기본 브라우저로 즉시 열리기를 원하며, so that 참고 문서나 외부 레퍼런스를 끊김 없이 확인할 수 있습니다.
2. As a **Raw** 모드 사용자, I want `[텍스트](https://...)`뿐만 아니라 `<https://...>`나 맨 주소 `https://...` 위에서도 `Ctrl+클릭`으로 기본 브라우저를 열 수 있기를 원하며(코드 펜스·인라인 코드·이미지 문법 내부 제외), so that 원문 편집 중에도 마크다운 문법 형태에 관계없이 웹 링크를 바로 열어볼 수 있습니다.
3. As a **보조 창** 사용자, I want **보조 창**으로 분리한 문서 탭에서도 **메인 창**과 동일하게 외부 웹 링크를 기본 브라우저로 열 수 있기를 원하며, so that 보조 모니터나 분리 창 작업 중에도 웹 링크가 막히지 않습니다.
4. As a **위지윅** 모드 작성자, I want 본문에서 `[텍스트](https://...)`를 직접 타이핑하거나 `Ctrl+K` 후 외부 URL을 입력해 닫는 `)`를 쳤을 때 즉시 클릭 가능한 링크로 변환되기를 원하며, so that **Raw** 모드로 전환하지 않고도 웹 링크를 작성할 수 있습니다.
5. As a 위키 사용자, I want 잘못된 `http(s)` URL이나 브라우저 실행 실패 시 상단 **오류 배너**로 원인을 안내받고, `mailto:` 링크는 오류 없이 조용히 무시되며, 기존 **문서 목차**·`#섹션` 스크롤·상대 경로 `.md` 파일 열기 및 **링크 자동완성 메뉴**가 그대로 동작하기를 원하며, so that 안전성과 기존 내비게이션 일관성을 모두 유지할 수 있습니다.
6. As a 위키 사용자, I want 사용자 매뉴얼에서 웹 링크 클릭 이동 방식을 확인할 수 있기를 원하며, so that **에디터 모드**별 링크 동작을 쉽게 파악할 수 있습니다.

## Implementation Decisions (구현 결정사항)

### 1. 공유 외부 HTTP(S) URL 검증 계약
- `http` 및 `https` 스킴만 허용하는 외부 URL 검증·정규화 유틸을 공유 보안 계층에 배치합니다.
  - 공백 트림, 제어 문자 거부, 스킴 추출(`http`/`https` 한정), `new URL()` 파싱을 통해 유효한 호스트를 가진 URL만 통과시킵니다.
  - 새 `shell` 외부 URL IPC, 기존 **터미널 패널** 외부 URL IPC, 렌더러 마크다운 링크 해석기가 동일한 검증 로직을 단일 진실 공급원(single source of truth)으로 공유합니다.

### 2. 창 역할 비제한 `shell` 외부 URL 열기 IPC 계약
- 기존 **터미널 패널** 외부 URL 채널은 **메인 창** 세션 전용으로 제한되어 있으므로, 클립보드 IPC와 동일하게 창 역할 제한 없이 호출 가능한 `shell` 외부 URL 열기 IPC(`wikiApi.shell.openExternalUrl`)를 추가합니다.
- 메인 프로세스 핸들러는 전달받은 URL을 공유 HTTP(S) 검증 유틸로 재검증한 뒤 통과한 URL에 대해서만 `shell.openExternal()`을 호출하며, 비허용 스킴이나 잘못된 URL은 실행하지 않고 실패(`false`)를 반환합니다.

### 3. 마크다운 링크 대상 해석 및 네비게이션 계약
- 마크다운 링크 대상 해석 결과(`ResolvedMarkdownLinkTarget` 계약 형태)는 다음과 같이 세분화합니다:

```ts
// 링크 네비게이션 해석 계약 형태
export type ResolvedMarkdownLinkTarget =
  | { kind: 'external'; url: string }
  | { kind: 'noop' }
  | { kind: 'same-doc-section'; slug: string }
  | { kind: 'workspace-file'; targetPath: string; slug: string | null }
  | { kind: 'error'; message: string }
```

- **분류 규칙**:
  - `http:` · `https:`(해시 프래그먼트 `#anchor`가 포함된 웹 URL 포함): 공유 HTTP(S) 검증을 통과하면 `{ kind: 'external', url }`, 형식이 잘못된 경우(예: `https://`) `{ kind: 'error', message }`를 반환합니다.
  - `mailto:`: `{ kind: 'noop' }`을 반환하여 오류 배너 없이 무동작으로 유지합니다.
  - `#슬러그` 및 상대 경로 `.md`/`.markdown`: 기존과 동일하게 처리하며 **문서 목차** 및 사용자 매뉴얼 모달과 충돌하지 않습니다.
- **네비게이션 훅 동작**:
  - `external` 결과를 받으면 기존 오류 배너를 비운 뒤 `wikiApi.shell.openExternalUrl(url)`을 호출합니다.
  - `openExternalUrl`이 `false`를 반환하거나 예외로 거부(reject)되거나 브리지 API를 사용할 수 없는 경우, 상단 **오류 배너**로 외부 링크 열기 실패 안내를 표시합니다.
  - **위지윅**·**Preview**·**Split**·**Raw** 모든 **에디터 모드**와 **메인 창**·**보조 창**이 동일한 네비게이션 훅을 통해 동작합니다.

### 4. 위지윅 `[텍스트](URL)` 타이핑 변환 규칙
- **위지윅** 링크 확장에서 `markdownLinks: true` 옵션을 활성화하고, 기존 `isSafeMarkdownUrl` URI 허용 검사(`http`, `https`, `mailto`, 상대 경로)와 `inclusive: false` 마크 이탈 동작을 유지합니다.
- `[라벨](대상)`에서 마지막 닫는 `)`를 직접 타이핑하는 순간에만 링크 마크로 변환되며, 코드 블록·인라인 코드·이미지 `![alt](...)`·빈 라벨 `[]()`·비허용 스킴(`javascript:` 등)은 변환하지 않습니다.
- 기존 **링크 자동완성 메뉴**(`[`/`]`/`(` 타이핑 및 선택 시 `)` 입력 전 치환) 및 `Ctrl+K` 흐름(선택 감싸기·기존 링크 풀기)과 충돌하지 않도록 유지합니다.

### 5. Raw 모드 `<https://...>` 및 맨 URL `Ctrl+클릭` 추출 규칙
- **Raw** 링크 구문 스캐너는 기존 `[라벨](href)` 추출을 그대로 유지하면서, 코드 펜스·인라인 코드·이미지 `![alt](src)` 바깥에서 다음 두 형태를 추가로 추출합니다:
  - `<http://...>` · `<https://...>` 꺾쇠 자동링크
  - 본문에 직접 표기된 맨 URL(`http://...`, `https://...`), 단 문장 끝 구두점(`.`, `,`, `;`, `:`, `!`, `?`, `'`, `"` 등)은 제외하고 URL 내부의 균형 잡힌 괄호(`(...)`)는 보존합니다.
- 이스케이프(`\\`), 코드 펜스, 인라인 코드 내부의 URL이나 `![alt](https://...)` 이미지 대상 URL은 추출하지 않습니다.

### 6. 사용자 매뉴얼 갱신
- `docs/manual.md`의 단축키 표와 `마크다운 링크와 자동완성` 섹션에 일반 웹 링크(`http://`, `https://`) 클릭 시 기본 브라우저로 이동하는 동작을 명시합니다.

## Testing Decisions (테스트 결정사항)

- **검증 기준**: 구현 세부사항이 아닌 사용자가 관찰하는 외부 동작(클릭·`Ctrl+클릭` 시 기본 브라우저 열기 호출, 타이핑 시 링크 마크 생성 및 저장, 잘못된 URL/실패 시 `role="alert"` **오류 배너** 표시, **보조 창** 동작, `mailto:`·코드 블록·이미지 비간섭, 기존 `#섹션`·상대 경로 이동 비회귀)을 기준으로 **TDD(Red → Green → Refactor)** 절차에 따라 격리된 환경에서 검증합니다.
- **핵심 모듈 및 테스트 심(Test Seam)**:
  - `<App />` 통합 테스트 심 (인메모리 `WikiApi` 하네스 + React Testing Library, **메인 창** 및 **보조 창**): Catches **위지윅**·**Preview**·**Split**·**Raw** 모드 전반의 웹 링크 클릭/`Ctrl+클릭`, **위지윅** `[텍스트](https://...)` 직접 타이핑 후 클릭, **보조 창** 외부 링크 열기, 잘못된 URL/실패 시 **오류 배너**, `mailto:`·기존 `#섹션`·상대 경로 링크 비회귀 / Misses 실제 Electron `shell.openExternal` OS 프로세스 호출 및 실제 IPC 직렬화.
  - 메인 IPC & Preload 브리지 경계 심 (`registerShellIpc` · `registerTerminalIpc` · `createWikiApi` 단위 테스트): Catches **메인 창**·**보조 창** 호출 허용, `http`/`https` 외 스킴(`javascript:`, `file:`, `mailto:`) 및 잘못된 URL 차단, 메인 프로세스 예외 전파 및 Preload 채널 바인딩 불일치 / Misses 렌더러 DOM 이벤트 및 에디터 상태 동기화.
  - 공유 URL 보안·링크 해석·구문 스캐너·위지윅 링크 확장 순수 도메인 심 (Vitest 단위 테스트): Catches 제어 문자·빈 호스트 URL 오탐, `ResolvedMarkdownLinkTarget` 분기 오류, **Raw** 맨 URL 경계(후행 구두점·균형 괄호·코드 펜스·인라인 코드·이미지) 파싱 오류, **위지윅** `markdownLinks` 입력 규칙과 자동완성·`Ctrl+K` 충돌 / Misses React 컴포넌트 렌더링 및 IPC 호출 흐름.
- *(위 심 목록은 `/ticket-runner`의 사전 합의된 심(Pre-agreed Seams)으로 사용됩니다.)*
- **참고할 기존 테스트 패턴 (Prior Art)**:
  - `<App />` 통합 테스트의 인메모리 `WikiApi` 하네스 기반 마크다운 링크 네비게이션 및 **보조 창** 테스트 패턴
  - **터미널 패널** IPC 단위 테스트의 `openExternal` 스파이 및 URL 스킴 차단 검증 패턴
  - 마크다운 링크 해석·구문 스캐너·위지윅 링크 확장 단위 테스트 패턴

## Out of Scope (범위 제외 사항)

- `mailto:` 링크 클릭 시 OS 기본 메일 클라이언트 실행
- 외부 웹 링크 클릭 전 확인 다이얼로그 표시
- `file://`, `ftp://`, `javascript:` 등 `http`/`https` 외 프로토콜의 외부 앱 실행
- **문서 편집기** 내부에 내장 웹뷰나 브라우저 탭을 열어 웹 페이지를 표시하는 기능
- **위지윅** 모드에서 스킴 없는 도메인(예: `example.com`)이나 닫는 공백 없이 입력 중인 맨 URL의 실시간 자동링크 규칙 변경

## Further Notes (기타 참고사항)

- **Electron 창 보안 유지**: Electron `BrowserWindow` 계층의 `registerWindowNavigationGuard`(`will-navigate` 및 `setWindowOpenHandler` 차단)는 그대로 유지하여 앱 창 내부가 외부 페이지로 이탈하지 않도록 보장하며, 오직 검증된 `http`/`https` URL만 메인 프로세스 IPC를 거쳐 `shell.openExternal`로 전달합니다.
