# 03 — 워크스페이스 뷰 분리

**Spec:** [spec.md](../spec.md)

**What to build:** 액티비티 바에 `워크스페이스` 아이콘을 추가하고, 현재 워크스페이스 카드(이름·경로·즐겨찾기 토글·`폴더 열기...`), 즐겨찾기 목록, 최근 워크스페이스 목록을 담은 워크스페이스 뷰를 제공합니다. 탐색기 헤더의 워크스페이스 전환기 팝오버와 즐겨찾기 토글은 제거하고 워크스페이스 이름 텍스트만 남깁니다. 워크스페이스를 전환하면 탐색기 뷰로 자동 이동하고, 앱을 시작할 때 워크스페이스가 없으면 워크스페이스 뷰로 시작합니다.

**Blocked by:** 02-activity-bar-and-view-switching

**Status:** ready-for-agent

- [ ] 액티비티 바에 `워크스페이스` 아이콘 버튼이 추가되고, 02번의 전환·접기 규칙을 동일하게 따릅니다.
- [ ] 워크스페이스가 열려 있을 때 워크스페이스 뷰에는 현재 워크스페이스 이름·경로, 즐겨찾기 추가/해제 토글(`즐겨찾기 추가`/`즐겨찾기 해제`, `aria-pressed`), `폴더 열기...` 버튼이 표시됩니다.
- [ ] 워크스페이스가 없을 때는 현재 워크스페이스 카드 대신 안내 문구와 `폴더 열기...` 버튼이 표시됩니다.
- [ ] `폴더 열기...` 버튼은 메뉴의 `open-folder` 명령과 동일한 동작을 합니다.
- [ ] 즐겨찾기 목록과 최근 워크스페이스 목록이 상시 표시되고, 항목을 클릭하면 전환되며, 즐겨찾기 항목은 개별 해제(`×`, `{이름} 즐겨찾기 해제`)를 할 수 있고, 현재 워크스페이스는 강조 표시되며, 목록이 비어 있으면 빈 상태 문구가 표시됩니다.
- [ ] 워크스페이스 뷰에서 전환에 성공하면 활성 뷰가 탐색기로 바뀝니다. 미저장 변경 확인 다이얼로그에서 취소하거나 전환에 실패하면 워크스페이스 뷰를 유지합니다.
- [ ] 앱 시작 시 초기 워크스페이스 복원 결과 워크스페이스가 없으면 워크스페이스 뷰, 있으면 탐색기 뷰가 활성화되며, 이후 사용자 선택을 덮어쓰지 않습니다.
- [ ] 탐색기 헤더에서 워크스페이스 전환기 팝오버(`워크스페이스 전환` 버튼)와 즐겨찾기 토글이 제거되고, 워크스페이스 이름 텍스트(경로는 툴팁)와 파일·폴더 생성/새로고침 액션만 남습니다.
- [ ] 기존 사이드바 워크스페이스 전환기 관련 `<App />` 통합 테스트를 워크스페이스 뷰 기준으로 이관·갱신하여 모두 통과합니다.
- [ ] `CONTEXT.md`에서 **워크스페이스 전환기**를 **워크스페이스 뷰**로 대체(또는 Avoid 목록에 반영)하고 정의를 갱신합니다.
- [ ] `npm run typecheck`, `npm test`, `npm run build`가 통과합니다.
