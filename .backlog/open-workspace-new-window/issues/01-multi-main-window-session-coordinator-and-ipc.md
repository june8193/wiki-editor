# 01 — 다중 메인 창 워크스페이스 세션 코디네이터 및 IPC·프로토콜 격리

**Spec:** [spec.md](../spec.md)

**What to build:** 메인 프로세스의 창 매니저와 워크스페이스·문서 버퍼·Git·로컬 에셋(`wiki-asset:`)·애플리케이션 메뉴 라우팅을 **다중 메인 창(워크스페이스 세션)** 구조로 확장합니다. 각 **메인 창**이 독립된 워크스페이스 파일시스템·파일 감시(`watch`)·공유 **문서 버퍼** 허브·소속 **보조 창** 그룹을 소유하고, 새 창에서 워크스페이스 열기(사전 경로 검증·오프셋 배치·중복 워크스페이스 기존 창 포커스·`initialWorkspacePath` 초기화 컨텍스트 전달) 및 독립적인 창 닫기 생명주기가 동작하도록 구축합니다.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 여러 **메인 창** 세션을 동시에 생성·관리할 수 있으며, 각 **메인 창** 세션은 독립된 워크스페이스 루트·파일 감시(`watch`/`unwatch`)·공유 **문서 버퍼** 허브·소속 **보조 창** 집합을 소유합니다.
- [ ] 새 창에서 워크스페이스 열기 요청 시 창 생성 전에 대상 경로의 실재(`realpath`) 및 디렉터리 여부를 검증하여, 존재하지 않거나 폴더가 아니면 새 창을 생성하지 않고 오류를 반환합니다.
- [ ] 검증된 경로가 아직 어떤 **메인 창**에도 열려 있지 않으면 원본 창 `bounds`에서 `(+40, +40)` 오프셋(`workArea` 내부 클램핑)된 새 **메인 창**(`1280×820`, 최소 `900×600`, 보안 `webPreferences` 및 네비게이션 가드 적용)을 생성하고, 해당 창의 초기화 컨텍스트(`WindowInitContext.initialWorkspacePath`)에 대상 경로를 전달합니다.
- [ ] 대상 워크스페이스 경로(`isSameWorkspacePath`, 심볼릭 링크·대소문자 정규화 포함)가 이미 열려 있는 다른 **메인 창**과 일치하면, 새 창에서 열기 또는 현재 창 워크스페이스 열기 시 새 창을 만들거나 중복 오픈하지 않고 기존 **메인 창**을 복원(최소화 시 `restore`)·포커스(`focus`)합니다.
- [ ] 워크스페이스·**문서 버퍼**·Git·워크스페이스 상태(`workspace-state`) IPC 호출은 요청을 보낸 `webContents`가 속한 **메인 창** 세션을 기준으로 라우팅되며, 파일 변경(`workspace:changed`)·버퍼 이벤트(`buffer:event`)·탭 드래그 상태(`window:drag-state-changed`)는 해당 세션의 창들(**메인 창** + 소속 **보조 창**)에게만 전달됩니다.
- [ ] 창 간 탭 드래그 드롭(`acceptTabDragDrop`)은 같은 **메인 창** 세션에 속한 창들 사이에서만 수락되고, 다른 워크스페이스 세션의 창으로 드롭할 때는 거부됩니다.
- [ ] 특정 **메인 창**을 닫을 때는 해당 **메인 창**과 그 소속 **보조 창**들의 미저장 **문서 버퍼** 및 상태 플러시만 확인·종료하고, 다른 **메인 창**(및 그 소속 **보조 창**)은 닫히지 않고 유지됩니다.
- [ ] `wiki-asset:` 로컬 이미지 프로토콜은 현재 열려 있는 모든 **메인 창** 세션의 워크스페이스 중 요청 경로를 포함하는 워크스페이스에서 에셋을 안전하게 해석하며, **애플리케이션 메뉴 바** 명령은 대상 창(보조 창인 경우 부모 **메인 창**)으로 라우팅됩니다.
- [ ] 메인 프로세스 다중 창·워크스페이스 세션 매니저 및 IPC 통합 테스트 심이 위 동작들을 검증하며, `npm run typecheck`, `npm test`, `npm run build`가 통과합니다.
