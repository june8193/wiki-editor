# Spec: 워크스페이스 뷰에서 새 창으로 워크스페이스 열기 및 다중 메인 창 세션 지원

## Problem Statement (문제 정의)

현재 앱은 프로세스 전체에서 단 하나의 **메인 창**만 허용하고, **워크스페이스 뷰**의 즐겨찾기·최근 워크스페이스 항목을 클릭하면 현재 창의 워크스페이스를 전환(교체)하는 방식만 지원합니다.

- 서로 다른 두 위키 프로젝트(워크스페이스)를 동시에 열어 두고 문서를 비교·참조하거나 양쪽 워크스페이스의 **폴더 트리**·**Git 패널**·**문서 편집기**를 나란히 작업할 수 없습니다.
- 단일 **메인 창**에 워크스페이스 파일시스템·파일 감시(`watch`)·공유 **문서 버퍼** 허브·Git 상태가 1:1로 묶여 있어, 여러 워크스페이스를 각각 독립된 **메인 창**으로 동시에 띄울 수 있는 세션 격리 구조가 없습니다.

## Solution (해결 방안)

**워크스페이스 뷰**의 즐겨찾기·최근 워크스페이스 목록 각 항목에 `'새 창에서 열기'` 액션 버튼을 추가하고, 각 **메인 창**이 독립된 워크스페이스 세션을 소유하는 다중 **메인 창** 아키텍처를 구축합니다.

1. **워크스페이스 뷰 항목별 `'새 창에서 열기'` 버튼 제공**: 상단 현재 워크스페이스 카드는 기존의 간결한 `'폴더 열기...'` 단일 구성을 유지하고, **즐겨찾기 워크스페이스** 및 **최근 워크스페이스** 목록의 각 항목 행 우측에만 `'새 창에서 열기'` 아이콘 버튼(`↗`)을 상시 배치합니다(현재 창에 이미 열려 있는 활성 워크스페이스 행은 아이콘 열 정렬 유지를 위해 `disabled` 처리).
2. **메인 창(워크스페이스 세션) 단위 격리 및 독립 생명주기**: 각 **메인 창**이 자신만의 워크스페이스 파일시스템·파일 감시(`watch`)·공유 **문서 버퍼** 허브·소속 **보조 창** 그룹을 독립적으로 소유합니다. 특정 **메인 창**을 닫으면 그 **메인 창**과 소속 **보조 창**들만 미저장 확인 후 닫히고 다른 **메인 창**은 유지되며, 모든 **메인 창**이 닫힐 때 앱이 종료됩니다.
3. **새 메인 창 초기 워크스페이스 지정 및 상태 복원**: `'새 창에서 열기'` 실행 시 창 생성 전에 대상 경로의 유효성을 먼저 검증(유효하지 않으면 현재 창에 **오류 배너** 표시)한 뒤, 원본 창에서 `(+40, +40)` 오프셋된 위치에 새 **메인 창**을 열어 대상 워크스페이스의 저장된 **폴더 트리** 펼침 상태와 **편집 공간** 탭·분할 레이아웃(`workspace-state.json`)을 복원하고 **탐색기 뷰**로 진입합니다.
4. **동일 워크스페이스 중복 메인 창 오픈 방지 (기존 창 포커스)**: 이미 다른 **메인 창**에 열려 있는 워크스페이스를 `'새 창에서 열기'`, 목록 항목 클릭(현재 창 전환), 또는 `'폴더 열기...'`로 선택하면 중복 **메인 창**을 띄우거나 현재 창을 전환하지 않고, 이미 해당 워크스페이스를 열고 있는 기존 **메인 창**을 복원(`restore`)·포커스(`focus`)합니다(동일 워크스페이스 내 다중 창 문서 편집은 기존 **보조 창** 기능 사용).

## User Stories (사용자 스토리)

1. As a 위키 작성자, I want **워크스페이스 뷰**의 **즐겨찾기 워크스페이스** 및 **최근 워크스페이스** 목록 각 항목 우측에 `'새 창에서 열기'` 아이콘 버튼이 표시되기를 원하며, so that 현재 창의 작업을 중단하지 않고도 다른 위키 워크스페이스를 별도 창으로 즉시 열 수 있습니다.
2. As a 위키 작성자, I want 현재 창에 이미 열려 있는 활성 워크스페이스 행에서는 `'새 창에서 열기'` 버튼이 비활성화(`disabled`) 상태로 표시되어 다른 행들과 아이콘 열(`↗`, `×`) 수직 정렬이 일정하게 유지되기를 원하며, so that 현재 열려 있는 워크스페이스임을 명확히 인지하면서도 정돈된 목록 UI를 볼 수 있습니다.
3. As a 위키 작성자, I want 다른 워크스페이스 항목의 `'새 창에서 열기'` 버튼을 눌렀을 때 원본 창의 열린 워크스페이스·미저장 **문서 버퍼**·현재 **왼쪽 사이드바** 뷰는 그대로 유지되고, 원본 창에서 `(+40, +40)` 오프셋된 새 **메인 창**이 열려 해당 워크스페이스의 이전 탭·분할 레이아웃 및 **폴더 트리** 펼침 상태를 복원한 채 **탐색기 뷰**로 시작하기를 원하며, so that 두 워크스페이스를 나란히 두고 곧바로 작업을 이어갈 수 있습니다.
4. As a 위키 작성자, I want 디스크에서 삭제되었거나 유효하지 않은 폴더 경로에 대해 `'새 창에서 열기'`를 눌렀을 때 빈 새 창이 뜨지 않고 현재 창의 **오류 배너**에 즉시 오류 메시지가 표시되기를 원하며, so that 잘못된 경로로 인해 불필요한 빈 창이 생성되지 않습니다.
5. As a 위키 작성자, I want 이미 다른 **메인 창**에 열려 있는 워크스페이스에 대해 `'새 창에서 열기'` 버튼을 누르거나 목록 항목 일반 클릭(현재 창 전환) 또는 `'폴더 열기...'`로 선택했을 때, 새 창 생성이나 현재 창 전환 없이 이미 해당 워크스페이스가 열려 있는 기존 **메인 창**이 앞으로 활성화(최소화 시 복원 후 포커스)되기를 원하며, so that 동일한 워크스페이스가 여러 **메인 창**에 중복으로 열려 상태 파일(`workspace-state.json`)이나 파일 감시가 충돌하는 일을 방지할 수 있습니다.
6. As a 위키 작성자, I want 각 **메인 창**에서 문서 탭을 `'새 창으로 이동'`하거나 창 밖으로 드래그해 분리한 **보조 창**이 해당 **메인 창**(워크스페이스 세션)에 귀속되어 같은 세션의 창들끼리만 실시간 **문서 버퍼**를 공유하고 탭 드래그 재결합이 허용되기를 원하며, so that 서로 다른 워크스페이스의 문서 탭이 섞이지 않고 안전하게 다중 창 편집을 할 수 있습니다.
7. As a 위키 작성자, I want 여러 **메인 창**이 열려 있을 때 특정 **메인 창**의 닫기(`X`) 버튼을 누르면 그 **메인 창**과 소속 **보조 창**들의 미저장 **문서 버퍼**만 확인한 뒤 해당 **메인 창**과 소속 **보조 창**들만 닫히고, 다른 워크스페이스의 **메인 창**(및 그 소속 **보조 창**)은 닫히지 않고 유지되기를 원하며, so that 한 프로젝트 작업을 마치고 창을 닫아도 다른 프로젝트 작업을 계속할 수 있습니다.
8. As a 위키 작성자, I want 어느 **메인 창**에서든 전역 설정(테마, 자동 저장, 즐겨찾기 추가·해제, 최근 워크스페이스 목록)을 변경하면 열려 있는 모든 **메인 창**과 **보조 창**에 즉시 동기화되고, 로컬 마크다운 이미지(`wiki-asset:`) 렌더링과 **Git 패널** 작업도 각 **메인 창**의 워크스페이스에 맞게 독립적으로 동작하기를 원하며, so that 어느 창에서나 일관된 앱 설정과 완전한 위키 편집·Git 기능을 사용할 수 있습니다.

## Implementation Decisions (구현 결정사항)

### 확정된 핵심 상태 및 계약 형태 (설계 검토 확정안)

```ts
interface WindowInitContext {
  role: WindowRole
  initialTabs: TabTransferPayload[]
  initialWorkspacePath?: string | null
}

type OpenWorkspaceInNewWindowResult =
  | { status: 'opened'; windowId: number; rootPath: string }
  | { status: 'focused-existing'; windowId: number; rootPath: string }

type ActivateOrOpenWorkspaceResult =
  | { status: 'opened'; info: WorkspaceInfo }
  | { status: 'focused-existing'; windowId: number; rootPath: string }
```

### 아키텍처 및 전이 규칙

- **워크스페이스 뷰 UI 구성 (프로토타입 안 B 확정)**:
  - 상단 현재 워크스페이스 카드 영역은 기존 `'폴더 열기...'` 단일 버튼을 유지합니다.
  - **즐겨찾기 워크스페이스** 및 **최근 워크스페이스** 섹션의 각 항목 행 우측에 `'새 창에서 열기'` 아이콘 버튼(`ExternalLink`, `aria-label="{워크스페이스 표시 이름} 새 창에서 열기"`)을 배치합니다. 즐겨찾기 항목 행에서는 `'새 창에서 열기'` 버튼 다음에 기존 `'즐겨찾기 해제'`(`×`) 버튼을 배치합니다.
  - 현재 창의 활성 워크스페이스와 경로가 일치하는 행(`isSameWorkspacePath`)에서는 `'새 창에서 열기'` 버튼을 `disabled` 상태로 렌더링하여 열 정렬을 유지합니다.
- **다중 메인 창(워크스페이스 세션) 아키텍처**:
  - 단일 프로세스 내에서 여러 개의 **메인 창** 세션을 동시에 관리합니다.
  - 각 **메인 창** 세션은 고유한 **메인 창** `webContentsId`, 0개 이상의 소속 **보조 창** 집합, 세션 전용 워크스페이스 파일시스템 및 파일 감시자(`watch`), 세션 전용 공유 **문서 버퍼** 허브를 가집니다.
  - 전역 설정(`config.json`)과 워크스페이스 상태 저장소(`workspace-state.json`), 로그 서비스는 프로세스 전역 단일 인스턴스를 공유하여 비동기 직렬 큐 기반의 원자적 파일 쓰기와 전체 창 설정 브로드캐스트를 보장합니다.
- **새 메인 창 생성 및 사전 경로 검증**:
  - 렌더러가 특정 경로에 대해 `'새 창에서 열기'`를 요청하면, 메인 프로세스는 창을 생성하기 전에 대상 경로의 실재 여부(`realpath`)와 디렉터리 여부를 먼저 검증합니다.
  - 경로가 존재하지 않거나 디렉터리가 아니면 새 창을 생성하지 않고 즉시 오류를 반환하여 요청한 창의 **오류 배너**에 표시합니다.
  - 검증된 정규화 경로(`realRoot`)가 이미 열려 있는 다른 **메인 창** 세션의 워크스페이스 루트와 일치(`isSameWorkspacePath`)하면, 새 창을 생성하지 않고 해당 기존 **메인 창**이 최소화되어 있을 경우 복원(`restore`)한 뒤 포커스(`focus`)하고 `{ status: 'focused-existing' }`를 반환합니다.
  - 어떤 창에서도 열려 있지 않은 유효한 경로라면 원본 창 `bounds`에서 `(+40, +40)` 오프셋(가장 가까운 디스플레이 `workArea` 내부로 클램핑)된 기본 크기(`1280×820`, 최소 `900×600`)의 새 **메인 창**을 생성하고, 해당 창의 초기화 컨텍스트(`WindowInitContext.initialWorkspacePath`)에 대상 경로를 주입합니다.
  - 새 **메인 창**은 마운트 시 `initialWorkspacePath`가 존재하면 `recentWorkspaces[0]` 대신 `initialWorkspacePath`를 열어 `workspace-state.json`의 이전 상태(**폴더 트리** 펼침 및 탭/분할 레이아웃)를 복원하고, `recentWorkspaces`를 갱신하며, **왼쪽 사이드바**를 **탐색기 뷰**로 전환합니다.
- **현재 창 워크스페이스 전환 시 중복 오픈 방지**:
  - **메인 창**에서 목록 항목 본문을 클릭해 현재 창 전환을 시도하거나 `'폴더 열기...'`로 폴더를 선택했을 때, 대상 경로가 이미 **다른 메인 창**에 열려 있다면 미저장 **확인 다이얼로그**나 현재 창 워크스페이스 교체를 수행하지 않고 해당 기존 **메인 창**을 복원·포커스합니다(단일 워크스페이스-단일 **메인 창** 불변식 유지).
- **세션별 IPC 라우팅·이벤트 브로드캐스트·에셋 프로토콜**:
  - 워크스페이스 파일 읽기/쓰기/감시, **문서 버퍼** 조회/편집/저장/탭 동기화, Git 상태/커밋/브랜치/Diff IPC 요청은 호출자 `event.sender`(`webContents`)가 속한 **메인 창** 세션을 찾아 해당 세션의 서비스 및 버퍼 허브로 라우팅합니다.
  - 파일시스템 감시(`workspace:changed`) 및 공유 버퍼 이벤트(`buffer:event`), 탭 드래그 상태(`window:drag-state-changed`)는 해당 세션에 속한 창들(**메인 창** + 그 소속 **보조 창**들)에게만 브로드캐스트합니다.
  - 전역 `config.json` **문서 버퍼**가 여러 세션에서 열리거나 편집되어 저장될 때 `configService` 변경 이벤트를 통해 다른 세션의 깨끗한(clean) `config.json` 버퍼와 설정 상태도 동기화됩니다.
  - `wiki-asset:` 로컬 이미지 프로토콜 요청은 현재 열려 있는 **메인 창** 세션들의 워크스페이스 서비스들 중 요청 경로를 포함하는 유효한 워크스페이스에서 해석합니다.
  - **애플리케이션 메뉴 바** 명령(`폴더 열기...`, `설정 패널`, `테마 전환`)은 명령이 실행된 창(또는 포커스된 **보조 창**의 부모 **메인 창**)의 `webContents`로 라우팅합니다.
- **보조 창 귀속·탭 드래그 경계·독립 닫기 생명주기**:
  - 탭 컨텍스트 메뉴 `'새 창으로 이동'` 또는 창 밖 드래그 아웃으로 생성된 **보조 창**은 원본 창이 속한 **메인 창** 세션에 귀속됩니다.
  - 창 간 탭 드래그 드롭(`acceptTabDragDrop`)은 원본 창과 대상 창이 **동일한 메인 창 세션**에 속할 때만 수락하며, 다른 워크스페이스 세션의 창으로 드롭하면 거부합니다.
  - 특정 **메인 창**을 닫을 때는 해당 **메인 창** 세션(그 **메인 창**과 소속 **보조 창**들)의 미저장 **문서 버퍼** 및 상태 플러시(`workspace-state.json`)만 확인·처리한 뒤 그 세션의 소속 **보조 창**들만 함께 닫으며, 다른 **메인 창** 세션은 영향을 받지 않습니다.
- **도메인 용어 갱신 (`CONTEXT.md`)**:
  - **메인 창 (Main Window)**, **보조 창 (Auxiliary Window)**, **워크스페이스 뷰 (Workspace View)**, **문서 버퍼 (Document Buffer)**, **확인 다이얼로그 (Confirm Dialog)**의 정의를 다중 **메인 창** 워크스페이스 세션 모델에 맞게 갱신합니다.

## Out of Scope (범위 제외 사항)

- 상단 현재 워크스페이스 카드에 `'새 창에서 폴더 열기...'` 버튼을 추가하거나 목록 항목에 우클릭 컨텍스트 메뉴를 추가하는 기능 (프로토타입 검토에서 안 B로 확정)
- 동일한 워크스페이스 폴더를 두 개 이상의 **메인 창**에서 중복으로 동시에 여는 기능 (동일 워크스페이스 내 다중 창 편집은 기존 **보조 창** 분리 기능으로 수행)
- 서로 다른 워크스페이스의 **메인 창** 또는 **보조 창** 사이에서 문서 탭을 드래그 앤 드롭으로 직접 이동·병합하는 기능
- 앱 종료 후 재시작 시 이전에 열려 있던 여러 **메인 창**의 개수와 위치·크기를 한꺼번에 자동 복원하는 기능 (앱 최초 실행 시에는 기존과 동일하게 단일 **메인 창**에서 최근 워크스페이스 1개를 복원)

## Further Notes (기타 참고사항)
