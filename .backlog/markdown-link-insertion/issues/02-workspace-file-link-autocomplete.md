# 02 — 워크스페이스 마크다운 파일 상대 경로 링크 자동완성 연동

**Spec:** [spec.md](../spec.md)

**What to build:** 열린 워크스페이스 전체(접혀 있는 하위 폴더 포함)의 마크다운 파일(`.md`, `.markdown`) 목록을 조회·동기화하여 **링크 자동완성 메뉴**에 다른 마크다운 파일 후보를 통합하고, 선택 시 현재 문서 위치 기준 안전한 상대 경로 링크(`[표시텍스트](./경로.md)` / `../경로.md`)로 **Raw**·**위지윅** 양쪽에 완성합니다.

**Blocked by:** 01-section-link-autocomplete-and-ctrl-k

**Status:** ready-for-agent

- [ ] 워크스페이스 파일시스템 서비스와 Preload 브리지(`window.wikiApi.workspace`)에 열린 워크스페이스의 모든 하위 폴더를 재귀 순회하여 마크다운 파일(`.md`, `.markdown`, 대소문자 무관) 엔트리 목록을 반환하는 인터페이스가 추가되며, `.git`·`node_modules` 등 시스템 예약 폴더와 워크스페이스 루트 밖을 가리키거나 유효하지 않은 심볼릭 링크는 제외됩니다.
- [ ] 렌더러는 워크스페이스 열기, 파일 생성·이름 변경·삭제, 외부 파일 변경 감시(`workspace:changed`) 이벤트 시 마크다운 파일 후보 목록을 최신 상태로 유지하므로, 왼쪽 사이드바 **폴더 트리**에서 하위 폴더를 펼치지 않아도 중첩 폴더의 마크다운 파일이 후보에 표시됩니다.
- [ ] **링크 자동완성 메뉴**의 파일 후보에서 현재 편집 중인 활성 문서 자신은 제외되며, 각 파일 항목에는 파일 이름과 워크스페이스 내 상대 경로가 구분 가능하게 표시됩니다.
- [ ] 정렬 및 접두사 필터링: 검색어가 없을 때 `[텍스트](`의 `텍스트`와 일치하는 섹션·파일을 최상단에 우선 추천한 뒤 현재 문서 섹션 → 다른 마크다운 파일 순으로 표시하고, `#`으로 시작하면 현재 문서 섹션만, `./` 또는 `../`로 시작하면 파일 후보만, 그 외 검색어는 섹션과 파일을 통합 필터링합니다.
- [ ] 파일 후보 선택 시 현재 활성 문서의 상위 폴더 기준 POSIX 상대 경로(같은 폴더 `./파일.md`, 상위·타 폴더 `../폴더/파일.md`, 공백·괄호 등 특수문자 세그먼트 퍼센트 인코딩)로 링크가 완성되며, 빈 `[](` 상태에서는 마크다운 확장자를 제외한 파일 이름이 표시 텍스트로 자동 채워집니다.
- [ ] 임시 디렉토리 기반 `WorkspaceFsService` 테스트, Preload 브리지 단위 테스트, 순수 상대 경로·필터링 단위 테스트, 그리고 `<App />` 통합 테스트(**Raw**·**위지윅**에서 중첩 폴더 파일 링크 완성 및 파일 추가/이름 변경 반영)가 모두 통과합니다.
- [ ] `npm run typecheck`, `npm test`, `npm run build`가 모두 통과합니다.
