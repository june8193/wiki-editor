# 02 — 4개 에디터 모드 · 문서 목차 · 문서 내 찾기 · 검색 점프의 프론트매터 정합성 통합

**Spec:** [spec.md](../spec.md)

**What to build:** YAML 프론트매터가 포함된 마크다운 문서를 `Raw` · `위지윅` · `Preview` · `Split` 4개 **에디터 모드**와 **문서 목차** · **문서 내 찾기 바** · **검색 뷰** 위치 이동에서 원문 손실이나 렌더링 깨짐·줄 번호 어긋남 없이 일관되게 다루도록 마크다운 파이프라인 전반을 통합합니다.

**Blocked by:** `01-frontmatter-engine-and-schema-ipc`

**Status:** ready-for-agent

- [ ] `위지윅` **에디터 모드**에서 프론트매터가 본문 리치 텍스트에 노출되지 않고, 본문 편집 시 원본 YAML 프론트매터(미정의 키·주석·복잡 YAML·줄바꿈 포함)가 손실·변형 없이 재결합되며, 외부에서 프론트매터 영역만 변경될 때 본문 편집 커서/선택이 불필요하게 초기화되지 않습니다.
- [ ] `Preview` 및 `Split` 우측 미리보기에서 원문 YAML 프론트매터 블록이 `<hr>`나 일반 텍스트로 렌더링되지 않고 깔끔하게 숨겨지며, 모든 최상위 블록의 `data-source-line` / `data-source-end-line`이 `bodyStartLine - 1`만큼 정확히 오프셋되어 `Split` 줄 동기화 스크롤과 일치합니다.
- [ ] **문서 목차**가 YAML 프론트매터 블록 내부의 `#` 주석 줄을 헤딩으로 추출하지 않고, 본문 헤딩의 1-기반 줄 번호를 `Raw` 원문 기준으로 정확히 산출하여 클릭 스크롤과 활성 헤딩 추적이 4개 **에디터 모드** 모두에서 일치합니다.
- [ ] **문서 내 찾기 바**가 `Raw`·`Split`에서는 프론트매터 포함 원문을, `Preview`·`위지윅`에서는 프론트매터가 제외된 본문을 정확히 매칭·강조·카운트(`n / m`)합니다.
- [ ] **검색 뷰** 본문 일치 줄 클릭 점프가 프론트매터가 있는 문서의 본문 줄을 4개 **에디터 모드** 모두에서 정확한 위치로 이동·강조하고, 프론트매터 영역 줄(`lineNumber < bodyStartLine`) 클릭 시 `Raw`·`Split`은 해당 YAML 줄로 이동하며 `Preview`·`위지윅`은 예외 없이 문서 최상단으로 안전 폴백합니다.
- [ ] 프론트매터가 없거나 YAML 구문 오류가 있는 마크다운 문서에서도 기존 편집·미리보기·목차·찾기·점프 동작이 회귀 없이 정상 유지됩니다.
- [ ] `<App />` 통합 · 멀티윈도우 및 `<DocumentEditor />` 공개 UI 테스트 심이 위 동작들을 검증하며, `npm run typecheck`, `npm test`, `npm run build`가 통과합니다.
