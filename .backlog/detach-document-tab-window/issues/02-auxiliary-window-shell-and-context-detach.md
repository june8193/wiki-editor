# 02 — 보조 창 편집 셸 및 탭 컨텍스트 메뉴 '새 창으로 이동'

**Spec:** [spec.md](../spec.md)

**What to build:** 공통 편집 셸을 구성해 **보조 창**(`960×760`, 네이티브 **애플리케이션 메뉴 바** 숨김, **액티비티 바**·**왼쪽 사이드바**·**전역 설정 패널** 생략, 기본 접힘 상태의 **우측 사이드바**)을 렌더링하고, **탭 바** 컨텍스트 메뉴에 `'새 창으로 이동'` 항목을 추가해 탭 분리(단일 탭 규칙·오프셋 배치·빈 **보조 창** 자동 닫힘 포함) 및 `CONTEXT.md` 용어 갱신을 완성합니다.

**Blocked by:** 01-shared-document-buffer-hub

**Status:** ready-for-agent

- [ ] 창 역할(`main` / `auxiliary`)에 따라 **보조 창**은 **애플리케이션 메뉴 바**(`removeMenu`)·**액티비티 바**·**왼쪽 사이드바**·**전역 설정 패널**을 생략하고, **오류 배너**·**편집 공간**·**우측 사이드바**(초기 접힘 상태, 펼치기/접기 및 `180~500px` 리사이즈 동작 동일)·**확인 다이얼로그**만 렌더링합니다.
- [ ] **보조 창** 생성 옵션은 기본 `960×760`, 최소 `520×420`, 보안 `webPreferences`(`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`)를 강제하며, 창 제목은 활성 문서 유무에 따라 `<문서 이름> - Wiki Editor` 또는 `Wiki Editor`로 갱신됩니다.
- [ ] **보조 창** 마운트·언마운트 시 **메인 창**의 워크스페이스 파일 감시(`watch`)가 해제되지 않으며, **보조 창**에서도 3가지 **에디터 모드** 전환, `Ctrl/Cmd+S` 저장, **슬래시 명령어 메뉴**, **문서 목차** 스크롤·TOC 삽입·헤딩 넘버링이 동일하게 동작합니다.
- [ ] **탭 바** 우클릭 컨텍스트 메뉴에 `'새 창으로 이동'` 항목 1개가 추가되어, 실행 시 원본 창 좌표에서 오프셋(`workArea` 내 클램핑)된 새 **보조 창**이 생성되고 원본 탭의 **에디터 모드**·커서·스크롤 위치와 미저장 공유 **문서 버퍼**를 유지한 채 이동합니다.
- [ ] **메인 창**은 열린 탭이 1개뿐이어도 `'새 창으로 이동'`이 활성화되어 분리 후 빈 **편집 공간**을 유지하고, **보조 창**은 창 내 전체 탭이 1개뿐일 때 `'새 창으로 이동'`이 비활성화(`disabled`)됩니다.
- [ ] **보조 창**의 마지막 남은 탭을 닫아 열린 탭 수가 0개가 되면 해당 **보조 창**이 자동으로 닫힙니다.
- [ ] `CONTEXT.md`에 **메인 창**, **보조 창** 용어를 추가하고 **문서 버퍼**, **탭 바** 정의를 갱신합니다.
- [ ] 멀티윈도우 `<App />` 통합 테스트 심과 메인 프로세스 다중 창 IPC 테스트 심이 위 동작을 검증하며, `npm run typecheck`, `npm test`, `npm run build`가 통과합니다.
