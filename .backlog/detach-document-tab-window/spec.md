# Spec: 문서 탭 별도 창(보조 창) 분리 및 창 간 재결합

## Problem Statement (문제 정의)

현재 앱은 단일 창 내부에서만 탭 순서 이동과 **주 편집기 영역**·**보조 편집기 영역** 분할을 지원하여, 멀티 모니터 환경이나 넓은 화면에서 여러 문서를 독립된 창으로 띄워 나란히 비교·편집할 수 없습니다.

- **문서 버퍼**와 자동 저장 타이머가 단일 렌더러 인스턴스 메모리에 종속되어 있어, 다중 창에서 동일 문서를 열거나 미저장 탭을 다른 창으로 옮길 때 실시간 동기화와 참조 카운트 판별을 할 수 없습니다.
- 창의 닫기(`X`) 동작 시 마지막 남은 미저장 문서를 보호하는 확인 절차가 없습니다.

## Solution (해결 방안)

문서 탭을 **메인 창** 밖으로 분리해 독립된 **보조 창**에서 편집하고, 다시 기존 창으로 합칠 수 있는 다중 창 문서 편집 체계를 구축합니다.

1. **보조 창 (Auxiliary Window) 분리**: **탭 바**의 문서 탭을 창 밖 빈 화면으로 드래그하거나 탭 컨텍스트 메뉴의 `'새 창으로 이동'`을 실행하면, **액티비티 바**·**왼쪽 사이드바**·**애플리케이션 메뉴 바**·**전역 설정 패널**을 생략하고 **오류 배너**·**편집 공간**·**우측 사이드바**(기본 접힘)·**확인 다이얼로그**만 갖춘 문서 편집 전용 **보조 창**으로 탭을 이동합니다.
2. **양방향 창 간 이동 및 재결합**: 이미 열려 있는 **메인 창**이나 다른 **보조 창**의 **탭 바** 또는 분할 드롭 영역으로 탭을 드래그 앤 드롭하여 창 간 병합·화면 분할을 수행하며, 탭이 모두 빠져나간 **보조 창**은 자동으로 닫힙니다.
3. **실시간 공유 문서 버퍼**: 모든 열린 창이 단일 **문서 버퍼** 상태를 실시간 공유하여 타이핑 내용·미저장 배지(`●`)·저장 중 상태·파일 이름 변경/삭제가 모든 창에 즉시 반영되고, 전체 창을 통틀어 마지막 탭 참조가 닫힐 때만 미저장 **확인 다이얼로그**를 표시합니다.
4. **종속 생명주기 및 닫기 보호**: **메인 창**을 닫으면 모든 **보조 창**도 함께 닫히며 앱이 종료되고, 창 닫기(`X`) 및 워크스페이스 전환 시 유실될 수 있는 미저장 문서를 확인·저장합니다.

## User Stories (사용자 스토리)

1. As a 위키 작성자, I want **탭 바**의 문서 탭을 앱 창 밖 빈 화면에 드래그 앤 드롭해 드롭한 커서 위치에 새 **보조 창**으로 이동하고, so that 여러 문서를 모니터나 화면 공간에 나란히 배치해 편집할 수 있습니다.
2. As a 위키 작성자, I want 탭 우클릭 컨텍스트 메뉴에서 `'새 창으로 이동'`을 실행해 오프셋된 위치의 새 **보조 창**으로 탭을 이동하고, so that 드래그가 불편한 환경에서도 간편하게 문서를 분리할 수 있습니다.
3. As a 위키 작성자, I want **보조 창**이 **액티비티 바**·**왼쪽 사이드바**·**애플리케이션 메뉴 바** 없이 **편집 공간**과 기본 접힘 상태의 **우측 사이드바**(**문서 목차**)만 표시(`960×760`, 최소 `520×420`)하길 원하며, so that 보조 창에서는 탐색 UI 없이 문서 편집에만 집중할 수 있습니다.
4. As a 위키 작성자, I want **보조 창**에서도 3가지 **에디터 모드** 전환, `Ctrl/Cmd+S` 저장, **슬래시 명령어 메뉴**, 표/Mermaid 편집, 창 내부 **화면 분할 모드** 전환, **우측 사이드바** 펼치기·접기·너비 조절·목차 스크롤·TOC 삽입·헤딩 넘버링이 동일하게 동작하길 원하며, so that 어느 창에서나 동일한 편집 경험을 누릴 수 있습니다.
5. As a 위키 작성자, I want 탭을 다른 창으로 이동할 때 기존 **에디터 모드**, 커서 선택 범위, 스크롤 위치 및 미저장 편집 내용이 손실 없이 그대로 유지되기를 원하며, so that 문맥이 끊기지 않고 계속 작업할 수 있습니다.
6. As a 위키 작성자, I want **메인 창**에 탭이 1개만 열려 있어도 새 **보조 창**으로 분리할 수 있기를 원하며(**메인 창**은 빈 **편집 공간** 유지), so that 메인 창을 탐색기 전용처럼 두고 문서만 별도 창으로 띄울 수 있습니다.
7. As a 위키 작성자, I want **보조 창**에 열린 탭이 전체 1개뿐일 때는 `'새 창으로 이동'`이 비활성화되고 창 밖 빈 화면 드롭 시에도 불필요한 창 재생성이 일어나지 않기를 원하며, so that 실수로 같은 창이 다시 열렸다 닫히는 깜빡임을 방지할 수 있습니다.
8. As a 위키 작성자, I want 드래그 도중 `Esc` 키로 취소하거나 앱 창 내부의 비드롭 영역(본문·사이드바 등)에 놓으면 새 창이 열리지 않고 기존 탭이 유지되기를 원하며, so that 의도하지 않은 창 분리를 피할 수 있습니다.
9. As a 위키 작성자, I want **보조 창**의 탭을 **메인 창**(또는 다른 **보조 창**)의 **탭 바**나 좌우·상하 분할 드롭 영역으로 드래그해 재결합·병합하고 반대로 **메인 창**의 탭도 기존 **보조 창**에 드래그해 합칠 수 있기를 원하며, so that 작업 흐름에 따라 창 구성을 자유롭게 재편성할 수 있습니다.
10. As a 위키 작성자, I want 탭 닫기나 다른 창으로의 이동 등으로 **보조 창**에 열린 탭이 0개가 되면 **보조 창**이 자동으로 닫히기를 원하며, so that 빈 **보조 창**을 일일이 수동으로 닫을 필요가 없습니다.
11. As a 위키 작성자, I want 같은 문서를 **메인 창**(**폴더 트리** 클릭 등)과 **보조 창**에 동시에 열었을 때 편집 내용·미저장 배지(`●`)·저장 상태·이름 변경·삭제가 실시간으로 동기화되기를 원하며, so that 한 문서를 여러 창에서 참조·편집해도 내용이 어긋나지 않습니다.
12. As a 위키 작성자, I want 여러 창에 동시에 열린 미저장 문서의 탭 하나를 닫을 때는 확인 없이 즉시 닫히고 모든 창을 통틀어 마지막 남은 탭을 닫을 때만 **확인 다이얼로그**가 표시되기를 원하며, so that 다른 창에 아직 열려 있는 문서를 불필요하게 저장 확인하지 않습니다.
13. As a 위키 작성자, I want **보조 창**의 닫기(`X`) 버튼을 누를 때 그 창에만 열려 있는 미저장 문서가 있으면 **확인 다이얼로그**(`저장 후 닫기` / `버리고 닫기` / `취소`)가 표시되고 다른 창에도 열려 있는 문서만 있으면 즉시 닫히기를 원하며, so that 보조 창을 닫다가 유일한 미저장 작업물을 잃지 않습니다.
14. As a 위키 작성자, I want **메인 창**의 닫기(`X`) 버튼을 누르면 **메인 창**과 모든 **보조 창**의 미저장 문서를 확인한 뒤 모든 **보조 창**이 함께 닫히며 앱이 종료되기를 원하며, so that 앱을 종료할 때 모든 창의 미저장 작업을 안전하게 보존할 수 있습니다.
15. As a 위키 작성자, I want **메인 창**에서 워크스페이스를 전환할 때 모든 창에 열린 미저장 워크스페이스 문서를 함께 확인하고 전환 확정 시 **보조 창**의 이전 워크스페이스 탭들이 정리되어 빈 **보조 창**이 자동으로 닫히기를 원하며, so that 이전 프로젝트 문서가 잔존하지 않고 안전하게 전환할 수 있습니다.

## Implementation Decisions (구현 결정사항)

### 확정된 핵심 상태 및 계약 형태 (설계 검토 확정안)

```ts
type WindowRole = 'main' | 'auxiliary'

interface TabTransferPayload {
  bufferKey: string
  mode: EditorMode
  cursor: CursorPosition
  scrollTop: number
}

type TabDragOutcome = 'pending' | 'dropped-in-window' | 'cancelled'
```

### 아키텍처 및 전이 규칙

- **창 역할 및 보조 창 옵션**: 각 창은 고유 `windowId`와 `WindowRole`(`'main' | 'auxiliary'`)을 가집니다. **보조 창**은 기본 `960×760`, 최소 `520×420`, 보안 설정(`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`), 네이티브 **애플리케이션 메뉴 바** 제거(`removeMenu`), 창 제목 `<활성 문서 이름> - Wiki Editor`(활성 문서가 없으면 `Wiki Editor`)를 적용합니다. **보조 창**은 **액티비티 바**·**왼쪽 사이드바**·**전역 설정 패널**을 렌더링하지 않으며, **우측 사이드바**는 초기 `isCollapsed: true`(기본 너비 `240px`, `180~500px` 클램핑)로 시작합니다.
- **워크스페이스 파일 감시 소유권**: **메인 창**만 워크스페이스 열기 및 파일 감시(`watch`/`unwatch`) 생명주기를 소유합니다. **보조 창**이 마운트·언마운트되어도 **메인 창**의 파일 감시가 해제되지 않으며, 설정 변경 및 파일시스템 변경 이벤트 브로드캐스트는 열린 모든 창에 전달됩니다.
- **창 배치 및 모니터 작업 영역 클램핑**: 드래그 분리 시 드롭 커서 화면 좌표 `(screenX, screenY)` 기준, 컨텍스트 메뉴(`'새 창으로 이동'`) 분리 시 원본 창 좌표에서 `(+40, +40)` 오프셋한 좌표를 기준으로 가장 가까운 디스플레이(`workArea`) 내부에 창 전체가 들어오도록 좌표를 클램핑합니다.
- **중앙 공유 문서 버퍼 및 탭 참조 카운트**: 열린 모든 **문서 버퍼**(`workspace` 및 `config`)의 상태(`content`, `savedContent`, `isDirty`, `isSaving`, `version`)와 창별 열린 탭 참조 목록을 중앙 코디네이터가 단일 진실 공급원으로 관리하고 변경을 모든 창에 실시간 브로드캐스트합니다(창 파괴 시 해당 창의 탭 참조 자동 정리 포함). 전체 창 기준 탭 참조 합계(`totalTabCount`)가 `0`이 될 때만 미저장 확인 대상이 되며 닫힘 확정 시 버퍼를 제거합니다.
- **자동 저장 단일화**: `autoSave` 활성화 시 동일 **문서 버퍼**가 여러 창에 열려 있어도 디바운스 타이머와 디스크 쓰기가 중복 실행되지 않도록 조율하고, 저장 완료 시 모든 창의 저장 상태 갱신과 Git 상태 새로고침이 일관되게 반영되도록 합니다.
- **단일 탭 분리 및 빈 보조 창 자동 닫힘**: 탭 컨텍스트 메뉴에는 `'새 창으로 이동'` 항목 1개만 추가합니다(`분할 영역으로 이동`, `분할 영역에 복제 열기` 다음, `닫기` 위). **메인 창**은 탭 수와 무관하게 활성(`1`개 탭 분리 시 빈 **편집 공간** 유지), **보조 창**은 창 내 전체 탭 수(`primary.tabs.length + secondary.tabs.length`)가 `2`개 이상일 때만 활성화합니다(`1`개일 때는 메뉴 비활성화 및 창 밖 드롭 분리 무시). **보조 창**의 전체 탭 수가 `0`이 되면 즉시 자동 닫힘 처리합니다.
- **창 밖 드래그 분리 및 창 간 재결합 전이 규칙**:
  - 드래그 시작 시 메인 프로세스에 활성 드래그 세션(`dragSessionId`, `sourceWindowId`, `paneId`, `tabId`, `TabTransferPayload`, 초기 상태 `'pending'`)을 등록하고 다른 창들에 외부 탭 드래그 진행 상태를 알립니다.
  - Chromium HTML5 DnD에서는 `drop` 이전(`dragenter`/`dragover`)에 `dataTransfer.getData`를 읽을 수 없으므로, 대상 창은 `dataTransfer.types`의 커스텀 탭 MIME 포함 여부 또는 활성 드래그 세션 상태를 통해 외부 탭 드래그 진입을 감지하여 **탭 바** 드롭 및 분할 드롭 영역을 활성화합니다. 이때 **단일(single)** 모드의 대상 창에 탭이 1개만 열려 있어도 외부 창에서 탭이 드래그되어 들어오는 경우에는 분할 후 양쪽 **편집기 영역**이 모두 채워지므로 좌우·상하 분할 드롭 영역을 모두 표시합니다.
  - 대상 창에서 드롭이 수락되면 드래그 세션을 `'dropped-in-window'`로 전환하고 대상 창 탭 추가(동일 **편집기 영역**에 같은 `bufferKey` 탭이 이미 있으면 중복 생성 대신 해당 탭 활성화)와 원본 창 탭 제거를 원자적으로 수행합니다.
  - 드래그 도중 `Esc` 키 입력(`before-input-event` 등)이 감지되면 세션을 `'cancelled'`로 전환합니다.
  - 원본 창에서 `dragend` 발생 시 세션이 `'pending'`이고, 원본 창이 탭 1개짜리 **보조 창**이 아니며, 드롭 시점 화면 커서 좌표가 열려 있는 모든 앱 창(**메인 창** 및 모든 **보조 창**)의 외곽 `bounds` 바깥일 때만 새 **보조 창**을 생성하고 탭을 이동시킵니다.
- **창 닫기 인터셉트 및 종속 생명주기**:
  - 프로그램에 의한 빈 **보조 창** 자동 닫힘이나 이미 확인이 끝난 강제 닫힘이 아닌 사용자 창 닫기(`close`) 이벤트를 인터셉트합니다.
  - **보조 창** 닫기 시: 해당 **보조 창**이 닫힘으로써 전체 창 기준 탭 참조가 `0`이 되는 미저장 **문서 버퍼**(`workspace` 및 `config`)만 추려, 1개 이상 존재할 때만 해당 **보조 창**에 **확인 다이얼로그**(`저장 후 닫기` / `버리고 닫기` / `취소`)를 띄웁니다.
  - **메인 창** 닫기 시: 모든 **보조 창**이 함께 종료되므로 앱 전체의 모든 미저장 **문서 버퍼**(`workspace` 및 `config`)가 1개 이상 존재하면 **메인 창**에 **확인 다이얼로그**(`저장 후 닫기` / `버리고 닫기` / `취소`)를 띄우고, 저장 성공 또는 버리기 확정 시 모든 **보조 창**을 추가 확인 없이 닫은 뒤 **메인 창**을 닫아 종료합니다.
  - **워크스페이스 전환**: **메인 창**에서 다른 워크스페이스로 전환할 때 전체 창에 열린 미저장 `workspace` 버퍼를 함께 확인·저장하고, 전환 시 모든 창의 이전 워크스페이스 버퍼·탭을 닫아 탭이 0개가 된 **보조 창**은 자동 닫히게 합니다(`config.json` 탭만 남은 **보조 창**은 유지).
- **도메인 용어 갱신 (`CONTEXT.md`)**: 신규 용어로 **메인 창 (Main Window)**, **보조 창 (Auxiliary Window)**을 추가하고, 기존 용어 중 **문서 버퍼**, **탭 바**, **확인 다이얼로그**의 정의를 다중 창 동작에 맞게 갱신합니다.

- 핵심 모듈 및 테스트 심(Test Seam):

## Out of Scope (범위 제외 사항)

- 앱 재시작 시 열려 있던 탭이나 **보조 창** 목록·크기·위치를 `config.json` 등에 저장·복원하는 기능
- **보조 창**에서 독립적으로 다른 워크스페이스 폴더를 열거나 **탐색기 뷰**·**Git 뷰**·**전역 설정 패널**을 표시하는 기능
- `'새 창에 복제 열기'`·`'메인 창으로 이동'` 등 추가 컨텍스트 메뉴 항목 및 탭 분리 전용 키보드 단축키
- 여러 탭을 다중 선택해 한꺼번에 새 창으로 분리하는 기능

## Further Notes (기타 참고사항)

- Windows/Chromium HTML5 드래그 앤 드롭에서 `Esc` 취소와 창 밖 빈 공간 드롭 모두 `dropEffect === 'none'`으로 `dragend`가 발생하므로, 메인 프로세스 `before-input-event` 감지와 활성 드래그 세션 상태 추적을 결합해 `Esc` 취소를 신뢰성 있게 구분해야 합니다.
- 보안 경계: **보조 창** 역시 **메인 창**과 동일한 프리로드 브리지 및 샌드박스 정책(`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`)을 강제하며, 워크스페이스 루트 밖 경로 접근 차단 정책을 그대로 따릅니다.
